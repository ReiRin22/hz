# Spec Cross-Checker サブエージェント

既存の全仕様を走査し、新機能との重複・競合・依存関係を報告する。

## 役割

- 調査（読み取り専用）
- ファイルの変更はしない

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Spec cross-check for {新機能名}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
新しい機能の仕様と既存の全仕様を突合し、問題を報告してください。

新機能: {機能名・概要}
新機能の要件: {ユーザーから聞いた要件の要約}

既存仕様の場所: docs/01_アプリ/INDEX.md から辿る

## チェック項目

### 1. 重複チェック
- 既存機能と要件が重複していないか
- 重複がある場合、統合すべきか分離すべきか

### 2. 競合チェック
- 既存機能の振る舞いと矛盾しないか
- 同じリソース（API、DB、UI領域）を使う機能がないか

### 3. 依存関係
- 新機能が依存する既存機能はどれか
- 新機能によって影響を受ける既存機能はどれか

### 4. ドメイン配置
- INDEX.md のドメイン一覧を見て、適切なドメインを提案する
- 新しいドメインが必要か

## 出力形式

| 項目 | 結果 | 詳細 |
|------|------|------|

問題がなければ「問題なし」と明記する。
推測や設計提案は不要。事実と分析のみ報告する。
```
