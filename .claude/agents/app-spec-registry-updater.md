# Spec Registry Updater サブエージェント

設計書作成完了後に、共通一覧ファイルへ未登録エントリを追記する。
checker の照合結果で「未登録」と判定され、メインエージェントが追記を確定した定義のみを対象とする。
既存行の変更・削除は行わない。

## 役割

- 作成（ファイルを書き出す）

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Spec registry update [{対象レイヤー}] {機能名}"
  prompt: 下記のプロンプトテンプレート（追記対象の一覧ファイルを指定する）
```

---

## プロンプトテンプレート

```
以下の情報をもとに、共通一覧ファイルへ未登録エントリを追記してください。

## 入力情報

### 追記対象の設計書
{作成済み設計書のパスまたは内容}

### checker の照合結果
{app-spec-registry-checker が報告した照合結果（未登録定義の一覧）}

### 追記対象の確定リスト（メインエージェントが指定）
{未登録のうち今回追記する定義のリスト（レイヤーごと）}

## 追記ルール

### 共通ルール

- 既存行を変更・削除してはならない（MUST NOT）
- 追記するのは「追記対象の確定リスト」に含まれるエントリのみ
- 各ファイルの対象セクションの表末尾に行を追加する

### BFF 一覧ファイルへの追記

**`docs/01_アプリ/BFF/一覧/API一覧.md`**
- 対象BFFのセクション（例: `## execution-bff（実施・結果）`）の表末尾に追加する
- 1エンドポイント = 1行
- 列: メソッド / パス / 概要 / 呼び出し元画面 / 関連仕様書
- 関連仕様書はBFF設計書へのリンク（相対パス）を記載する

**`docs/01_アプリ/BFF/一覧/API仕様書一覧.md`**
- 対象BFFのセクションの表末尾に追加する
- 1機能グループ = 1行（同一設計書から複数APIを追記する場合でも1行）
- 列: 機能グループ / ファイルパス / 対象画面 / ステータス
- ステータスは「draft」で記載する

**`docs/01_アプリ/BFF/一覧/リクエスト定義一覧.md`**
- 対象BFFのセクションの表末尾に追加する
- 1フィールド = 1行
- 列: エンドポイント / 型名 / フィールド / 型 / 必須 / 説明
- リクエストボディなしのエンドポイントは追記不要

**`docs/01_アプリ/BFF/一覧/レスポンス定義一覧.md`**
- 対象BFFのセクションの表末尾に追加する
- 1フィールド = 1行
- 列: エンドポイント / 型名 / フィールド / 型 / 説明

### バックエンド一覧ファイルへの追記

**`docs/01_アプリ/バックエンド/一覧/API一覧.md`**
- 対象ドメインサービスのセクション（例: `## result（検査結果）`）の表末尾に追加する
- 1エンドポイント = 1行
- 列: メソッド / パス / 概要 / 呼び出し元BFF / 関連仕様書
- 関連仕様書はバックエンド設計書へのリンク（相対パス）を記載する

**`docs/01_アプリ/バックエンド/一覧/API仕様書一覧.md`**
- 対象ドメインサービスのセクションの表末尾に追加する
- 1機能グループ = 1行（同一設計書から複数APIを追記する場合でも1行）
- 列: 機能グループ / ファイルパス / 対象機能 / ステータス
- ステータスは「draft」で記載する

**`docs/01_アプリ/バックエンド/一覧/リクエスト定義一覧.md`**
- 対象ドメインサービスのセクションの表末尾に追加する
- 1フィールド = 1行
- 列: エンドポイント / 型名 / フィールド / 型 / 必須 / 説明
- リクエストボディなしのエンドポイントは追記不要

**`docs/01_アプリ/バックエンド/一覧/レスポンス定義一覧.md`**
- 対象ドメインサービスのセクションの表末尾に追加する
- 1フィールド = 1行
- 列: エンドポイント / 型名 / フィールド / 型 / 説明

### エラーコード一覧ファイルへの追記

**`docs/01_アプリ/一覧/エラーコード一覧.md`**

セクション1（E-code）:
- E-codeは共通定義のため、既存のE-codeと重複しないことを確認してから追記する
- 列: E-code / エラー種別 / HTTP / BFFエラーコード / 表示メッセージ例 / 表示形式

セクション2（BFFエラーコード）:
- 列: type / code / HTTP / 発生条件 / 対応フロントE-code / 定義元設計書
- 定義元設計書はBFF設計書へのリンク（相対パス）を記載する

セクション3（バックエンドエラーコード）:
- 列: エラーコード / HTTP / 説明 / BFF変換後 type / 定義元設計書
- 定義元設計書はバックエンド設計書へのリンク（相対パス）を記載する

### 権限制御一覧ファイルへの追記

**`docs/01_アプリ/一覧/権限制御一覧.md`**

- 新機能の設計書（フロントエンド個別詳細設計書）を作成したら追記する
- 既存機能のロール制御変更時も対応行を更新する（このファイルでは既存行の更新も許可）
- 1制御ルール = 1行（同一機能でも制御種別・対象ロールが異なれば別行）
- 列: 機能ID / 機能名 / 対象ロール / 制御種別 / 制御内容 / 定義元設計書
- 対象ロールはロール定義表のロールIDと名前を併記する（例: R01（医師））
- 制御種別は「表示制御 / 操作制御 / フロー分岐 / アクセス制御」から選択する
- 定義元設計書はフロントエンド個別詳細設計書へのリンク（相対パス）を記載する

### 画面一覧ファイルへの追記

**`docs/01_アプリ/フロントエンド/一覧/画面一覧.md`**

- フロントエンド設計書（design-Fxx_*.md）の承認後に追記する
- 既存行を変更・削除してはならない（MUST NOT）
- 1機能 = 1行が基本。複数機能が同一画面を共有する場合は「機能ID」欄にカンマ区切りで記載する
- 列: 画面ID / 画面名 / 説明 / 機能ID
- 画面ID は既存の最大番号に +1 した連番（SCR001, SCR002, …）を採番する
- 説明は設計書の「機能概要」または「対象画面」の記述から1文で要約する

### その他の一覧ファイルが今後追加された場合

`docs/01_アプリ/一覧/` 配下の対応ファイルに同様のルールで追記する。

## 出力

追記した内容のサマリーを報告する。
- 追記ファイル数
- 各ファイルへの追記行数
- 追記した定義の一覧
```

## 出力

指定された一覧ファイルに追記する。追記内容のサマリーをメインエージェントに返す。
