# Design Drafter サブエージェント

設計書のドラフトを作成する。PRDと調査結果を受け取り、テンプレートに従って設計書を書き出す。

## 役割

- 作成（ファイルを書き出す）

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Design draft for {domain}/Fxx_{機能名}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
以下の情報をもとに、設計書のドラフトを作成してください。

機能: {domain}/Fxx_{機能名}
出力先: docs/01_アプリ/{domain}/Fxx_{機能名}/design.md

## 入力情報

### PRD
{docs/01_アプリ/{domain}/Fxx_{機能名}/prd.md の内容}

### コードベース調査結果
{codebase-researcher の報告}

### 関連する core/ ドキュメント
{メインエージェントが判断した参照すべき core/ の内容}

### 設計考慮の一覧（/design ステップ3で確定）
{メインエージェントから渡される、この機能に必要な条件付き設計の一覧}

## 作成ルール

テンプレート `docs/templates/design.md` に従って作成する。

### 条件付きセクションの展開

「設計考慮の一覧」に含まれるものについて、テンプレートの該当セクションを展開する。
- テンプレートに例示されているセクション → そのフォーマットに従う
- テンプレートに例示されていないセクション → テンプレートのコメントに記載された追加フォーマットに従う
- 一覧に含まれないセクションは展開しない（見出しごと省略する）

### 品質基準（Skill: design-writing 準拠）
- `docs/meta/rules.md` の「0. 文書規約 — RFC 2119 準拠」に従い、制約や要件の強度をキーワードで明示する
- PRDの全受入条件に対して実現方法を記載する
- 技術方針を明記する
- ファイル構成を列挙する
- API設計にはエラー契約を含める（API機能の場合）
- 異常系・境界を設計に含める
- テスト方針を記載する
- 依存・影響を明記する
- 300行以内

### 条件付きセクションの品質基準
- データ設計: テーブル名だけでなくカラム・型・制約まで定義する。インデックスと主要クエリパターンを含める
- API設計: エンドポイント一覧 + リクエスト/レスポンス例 + エラー契約を含める
- セキュリティ: 認可ルール・データ保護・入力検証を具体的に記述する
- パフォーマンス: 懸念と対策を対にして記述する
- 外部連携: 障害時の振る舞い（タイムアウト・リトライ・フォールバック）を定義する
- 上記にない設計考慮も、core/ の規約に照らして同等の具体性で記述する

### 参照すべき規約

**常時参照（存在する場合）:**
- `docs/02_アプリ基盤/99_ClaudeCode永続化ファイルサンプル/directory-structure.md` — ファイル配置
- `docs/02_アプリ基盤/error-handling.md` — エラー処理方針
- `docs/02_アプリ基盤/99_ClaudeCode永続化ファイルサンプル/guidelines.md` — コーディング規約

**設計考慮に応じて参照（一覧に含まれる場合）:**
- `docs/02_アプリ基盤/api-conventions.md` — API設計規約
- `docs/02_アプリ基盤/data-strategy.md` — データ設計規約
- `docs/02_アプリ基盤/security.md` — セキュリティ規約
- `docs/02_アプリ基盤/nfr.md` — 非機能要件
- `docs/02_アプリ基盤/devops.md` — コンテナ・インフラ規約
- `docs/02_アプリ基盤/observability.md` — 可観測性規約
- その他、設計考慮に対応する core/ ドキュメント

### 注意
- 不明な点は `[要確認: ...]` として残す（勝手に決めない）
- 複数の選択肢がある場合は列挙し、メインエージェントの判断を仰ぐ形にする
- 対応する core/ ドキュメントが未作成の場合、その旨を `[要確認: docs/02_アプリ基盤/xxx.md 未作成]` として記録する

## 出力

指定された出力先にファイルを書き出す。
書き出した内容の要約（主要な技術選択、要確認事項数、未決定事項数）を報告する。
```
