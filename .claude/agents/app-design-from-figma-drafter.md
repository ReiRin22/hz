# Design from Figma Drafter サブエージェント

機能検討書と画面構造サマリー（screen-summary.md）を基に、`{機能名}機能設計書.md` のドラフトを作成する。

## 役割

- 作成（ファイルを書き出す）
- app-figma-screen-extractor が出力した screen-summary.md を読み、TSX ソースを直接読まずに設計書を作成する

## 起動方法

```
Agent tool:
  subagent_type: "general-purpose"
  description: "Design draft from Figma: {機能ID}"
  prompt: 下記のプロンプトテンプレートに値を埋めて渡す
```

## プロンプトテンプレート

```
以下の情報を基に、`{機能名}機能設計書.md`のドラフトを作成してください。

## 入力

- 機能検討書: {docs/01_アプリ/機能設計/機能検討/ORDxxx_xxx_機能検討.md} の絶対パス
- 画面構造サマリー: {docs/01_アプリ/機能設計/Fxx_機能名/screen-summary.md} の絶対パス
- 出力先: {docs/01_アプリ/機能設計/Fxx_機能名/{機能名}機能設計書.md} の絶対パス
- 外来版設計書（任意）: {外来版 design.md のパス。なければ省略}

## 作業手順

### Step1: インプットを読む
- 機能検討書を Read で読み込み、スコープ・権限・要件・決定事項を把握する
- 画面構造サマリーを Read で読み込み、パネル構成・UI要素・ダイアログを把握する
- 外来版設計書が指定されている場合は Read で読み込み、フォーマット見本として参照する

### Step2: 設計書を作成する
- 下記フォーマットに従って `{機能名}機能設計書.md` を作成する
- 機能検討書のスコープ内・スコープ外を設計書に忠実に反映する（スコープ外の機能を設計書に混入しない）
- 画面構造サマリーからパネル・ダイアログ・UI要素を設計に落とし込む
- 不明な点は `[要確認: ...]` として残す（勝手に決めない）
- 粒度の最低基準を守ること（下記「粒度基準」参照）
- 設計書作成後に機能検討書と照合し、スコープ内の全機能が設計書に記載されているか確認する

#### 粒度基準（必ず記載する項目）

**4. 入力・表示項目仕様** の各行について:
- 「初期状態・振る舞い例」: 空欄禁止。初期値・活性切り替え条件・表示切り替え条件を記載。該当なしは `-`
- 「入力検証ルール」: 入力可能フィールドは必ず記載。最大桁数・形式・必須チェックを含む。該当なしは `-`
- 「エラーメッセージID」: 入力検証ルールがある場合は必ず対応するIDを記載。エラーメッセージ一覧にも追加する

**入力チェックの必須確認項目:**
- [ ] 入力必須フィールドに「未入力時の動作（非活性制御またはエラー表示）」が定義されているか
- [ ] 送信・確定ボタンの活性/非活性制御条件（いつ押せるか）が定義されているか
- [ ] フォーマット違反（桁数超過・形式不正等）のエラー表示が定義されているか

#### 機能過不足の確認（Step2 完了後に実施）

機能検討書の「スコープ内」リストと設計書の全項目を突き合わせて確認する:
- [ ] スコープ内の全機能（ボタン・ダイアログ・操作フロー）が設計書に記載されているか
- [ ] スコープ外の機能が設計書に混入していないか

#### ADRの作成（設計判断がある場合）

以下のいずれかに該当する場合、`[要ADR: {判断内容の要約}]` とコメントを残す（ADR自体はメインエージェントが作成）:
- UI構造・データモデルについて複数の選択肢を検討した
- 既存機能との整合性確保のためにトレードオフがある
- 「なぜこの設計にしたか」が設計書本文から読み取れない

### Step3: 出力する
- Write ツールで出力先に保存する
- 保存後、セクション数・要確認事項数・`[要ADR]` 箇所数を報告する

## 注意事項

- TSX ソースファイルは直接読まない（screen-summary.md 経由で把握する）
- 出力ファイル名は `{機能ID}_{機能名}.md` とする（例: `ORD064_入院オーダー.md`）
- フォーマットは `docs/01_アプリ/機能設計/入院オーダー/ORD064_入院オーダー.md` に準拠する
- 300行を超えても別ファイルへの分割はしない。セクションを圧縮して1ファイルに収める
- 外来版設計書がある場合はフォーマット見本として参照するが、内容をそのままコピーしない
- テーブル定義がある場合、No 90〜93（作成日時・作成ユーザ・更新日時・更新ユーザ）は必ず末尾に含める
```
