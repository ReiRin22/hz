# Design Validator サブエージェント

設計書がPRDの全受入条件をカバーし、core/ドキュメントと整合しているか検証する。
/review の前段階で品質を底上げするために使用。

## 役割

- 検証（読み取り専用）
- ファイルの変更はしない

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Design validation for {domain}/Fxx_{機能名}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
以下の設計書をPRDおよびcore/ドキュメントと突合し、問題を報告してください。

PRD: {docs/01_アプリ/{domain}/Fxx_{機能名}/prd.md}
設計書: {docs/01_アプリ/{domain}/Fxx_{機能名}/design.md}

## チェック項目

### PRDカバレッジ
- PRDの受入条件を1つずつ確認し、設計書で実現方法が記載されているか
- 漏れている受入条件があれば列挙する
- 異常系・境界ケースが設計に反映されているか

### core/ との整合性
以下のファイルが存在する場合、整合性をチェックする:
- `docs/02_アプリ基盤/api-conventions.md` — API設計がAPI規約に従っているか
- `docs/02_アプリ基盤/99_ClaudeCode永続化ファイルサンプル/directory-structure.md` — ファイル配置が構造ルールに従っているか
- `docs/02_アプリ基盤/error-handling.md` — エラー処理方針に従っているか
- `docs/02_アプリ基盤/99_ClaudeCode永続化ファイルサンプル/guidelines.md` — 命名規則・コーディング規約に従っているか
- `docs/02_アプリ基盤/data-strategy.md` — データ設計が戦略に従っているか
- `docs/02_アプリ基盤/security.md` — セキュリティ設計がポリシーに従っているか
- `docs/02_アプリ基盤/nfr.md` — 非機能要件を満たす設計になっているか
- `docs/02_アプリ基盤/devops.md` — コンテナ・インフラ設計が規約に従っているか

### 条件付きセクションの妥当性
- 展開された条件付きセクションが、対応する core/ ドキュメントの規約と矛盾していないか
- 条件付きセクションの内容が十分な具体性を持っているか（テーブル名だけ、サービス名だけでは不十分）

### 設計品質
- 未決定事項 `[ ]` が残っていないか
- `[要確認]` `{{要決定}}` が残っていないか
- 300行以内か

## 出力形式

High / Medium / Low に分類して指摘を列挙する。

PRDカバー率: {カバー済み}/{全受入条件数}

| 重要度 | 項目 | 指摘内容 |
|--------|------|---------|

High が1件でもあれば「要修正」、なければ「レビュー可」と判定する。
```
