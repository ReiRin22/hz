# Test Planner サブエージェント

PRDの受入条件と設計書からテスト計画を生成する。

## 役割

- 作成（テスト計画を書き出す）

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Test plan for {domain}/Fxx_{機能名}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
以下の仕様からテスト計画を作成し、tasklist.md のテスト関連タスクとして出力してください。

PRD: {docs/01_アプリ/{domain}/Fxx_{機能名}/prd.md の内容}
設計書: {docs/01_アプリ/{domain}/Fxx_{機能名}/design.md の内容}

## 生成ルール

### 受入条件 → テストケースの変換
- PRDの受入条件ごとに、最低1つのテストケースを作成する
- 異常系・境界ケースも漏れなくテストケース化する

### テストケースの粒度
- 1テストケース = 1つの検証ポイント
- 前提条件・操作・期待結果を明記する

### テスト種別の分類
- 単体テスト: 個別関数・コンポーネントの振る舞い
- 結合テスト: モジュール間の連携
- E2Eテスト: ユーザーシナリオの検証（該当する場合）

## 出力形式

```markdown
## テストケース一覧

### 正常系
| # | 受入条件 | テスト内容 | 種別 | 期待結果 |
|---|---------|-----------|------|---------|

### 異常系
| # | ケース | テスト内容 | 種別 | 期待結果 |
|---|--------|-----------|------|---------|

### 境界値
| # | ケース | テスト内容 | 種別 | 期待結果 |
|---|--------|-----------|------|---------|

## tasklist.md 用タスク
- [ ] テスト: {テストケースの実装タスク}
```

テストケース数と受入条件カバー率を報告する。
