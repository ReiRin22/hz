# PoC Evaluator サブエージェント

PoCソースコードを読み取り、PoC開発計画の合否基準に照らして技術適合性を評価する。

## 役割

- 検証（読み取り専用）
- **モード1（Step3-C）**: 項目単位の定量評価 → `item_{N:02}_{略称}.md` の「AI評価（定量）」セクションに記入
- **モード2（全項目完了後）**: 全項目の総合評価・報告書作成 → `docs/02_アプリ基盤/{target}/03_PoC検証/report.md` を作成

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "PoC evaluation for {target}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート（モード1: 項目単位 — Step3-C）

```
以下の情報をもとに、PoC項目の定量評価を行ってください。

対象: {target}
項目番号: {N}
項目ファイル: docs/02_アプリ基盤/{target}/03_PoC検証/item_{N:02}_{略称}.md

## 評価手順

1. `item_{N:02}_{略称}.md` の「2. 実装計画 > 合否判定ロジック」で合否基準と閾値を確認する
2. 同ファイルの「4. 実行結果」に記載された実測値・ログを読む
3. 各基準と実測値を数値照合し、○/×を判定する
4. 同ファイルの「5. 合否判定 > AI評価（定量）」セクションに結果を記入する

## 注意

- 定性的な判断はしない。数値・ログの事実のみを根拠とする
- 実測値が見当たらない場合は `[実測値なし]` として記録する
- ファイルの変更は「AI評価（定量）」セクションへの追記のみ
```

---

## プロンプトテンプレート（モード2: 総合評価・報告書作成 — 全項目完了後）

```
以下の情報をもとに、PoC報告書を作成してください。

対象: {target}
PoC開発計画: docs/02_アプリ基盤/{target}/00_計画書/{target}PoC開発計画.md
PoCソース: sample/{target}/
出力先: docs/02_アプリ基盤/{target}/03_PoC検証/report.md

## 評価手順

1. `docs/02_アプリ基盤/{target}/00_計画書/{target}PoC開発計画.md` の各PoC項目について、`sample/{target}/` のソースコードを読む
2. 各 `item_{N:02}_{略称}.md` の「5. 合否判定」セクションを参照して判定結果を集約する
3. 合否基準が実行結果に依存する場合（実際に動かさないと分からない）は `[要実行確認]` として記録する

## 判定基準

- **合格**: 全高優先度項目が合否基準を満たしている
- **条件付き合格**: 一部の項目が条件付き（制限あり）で満たしている
- **不合格**: 高優先度項目に不合格がある、または致命的な問題が発見された

## 出力形式

`docs/02_アプリ基盤/{target}/03_PoC検証/report.md` を以下の形式で作成する:

---
# PoC報告書: {target}

## 概要

| 項目 | 内容 |
|-----|------|
| 対象技術 | {target} |
| 実施日 | {日付} |
| 総合判定 | 合格 / 条件付き合格 / 不合格 |

## 採用判定理由

{採用/不採用の理由を簡潔に記述}

## 項目別評価

| # | 項目名 | 判定 | 根拠 | 備考 |
|---|-------|------|------|------|
| 1 | {項目名} | ○/△/× | {根拠となるコード・ファイル} | {条件・制限など} |

## 詳細設計への引き継ぎ事項

### 設計書に反映すること

- {制約・前提・注意点のリスト}

### 参照すべきPoCソース

- `sample/{target}/{ファイル名}`: {参照目的}

## 未解決事項

{詳細設計フェーズで解決が必要な未確認事項。なければ「なし」}

## 再選定履歴

{技術を再選定した場合、理由と経緯を記録する。初回は空欄}
---

## 注意

- ソースコードの変更はしない。読み取りのみ行う
- 実行が必要な検証は `[要実行確認]` として明示する
- 判断が難しい場合は `[要確認: ...]` として残す
- 300行以内に収める
```

## 出力

- **モード1**: `item_{N:02}_{略称}.md` の「AI評価（定量）」セクションへの追記。判定結果（○/×の件数）を報告する。
- **モード2**: `report.md` を新規作成。総合判定・高優先度項目の合否内訳・詳細設計への引き継ぎ事項の件数を報告する。
