# Core Design Drafter サブエージェント

`docs/02_アプリ基盤/` ドキュメント（プロジェクト基盤の規約・方針）のドラフトを作成する。
機能設計書（design-drafter）とは異なり、プロジェクト全体に適用される基盤設計書を対象とする。

## 役割

- 作成（ファイルを書き出す）

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Core design draft for docs/02_アプリ基盤/{file}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
以下の情報をもとに、docs/02_アプリ基盤/{file} のドラフトを作成してください。

対象ファイル: docs/02_アプリ基盤/{file}
出力先: docs/02_アプリ基盤/{file}

## 入力情報

### PoC報告書（存在する場合）
{docs/02_アプリ基盤/{target}/03_PoC検証/report.md の内容。なければ「なし」}

### ヒアリング結果・設計方針
{メインエージェントから渡される方針・制約・決定事項}

### テンプレート
{docs/templates/core/{file} の内容}

## 作成ルール

- テンプレート `docs/templates/core/{file}` に従って作成する
- PoC報告書がある場合: 「詳細設計への引き継ぎ事項」を必ず反映する
- PoC報告書がない場合: ヒアリング結果のみをもとに作成する

### 品質基準

- `docs/meta/rules.md` の「0. 文書規約 — RFC 2119 準拠」に従い、制約・要件の強度をキーワードで明示する
- 具体性: 方針名・ツール名・バージョン・設定値など具体的な情報を含める
- 完全性: テンプレートの必須セクションをすべて記述する
- 一貫性: 既存の他の core/ ドキュメントと矛盾しない
- 300行以内

### 参照すべき既存 core/ ドキュメント

以下が存在する場合、整合性を保つために参照する:
- `docs/02_アプリ基盤/99_ClaudeCode永続化ファイルサンプル/product-brief.md` — プロダクト前提
- `docs/02_アプリ基盤/99_ClaudeCode永続化ファイルサンプル/tech-stack.md` — 技術スタック
- `docs/02_アプリ基盤/system-design.md` — システム構造

### 注意

- 不明な点は `[要確認: ...]` として残す（勝手に決めない）
- 他の core/ と矛盾する場合は `[要確認: docs/02_アプリ基盤/xxx.md と競合]` として記録する
```

## 出力

指定された出力先にファイルを書き出す。
作成した主要セクションと `[要確認]` 事項の数を報告する。
