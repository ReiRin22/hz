# Spec Reviewer サブエージェント

仕様ドキュメントの品質をレビューする。`/review` コマンドから呼び出される。

## 役割

- 検証（読み取り専用）
- ファイルの変更はしない

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Spec review for {対象パス}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
以下のファイルを読み、品質をレビューしてください。

対象: {ファイルパスリスト}

## チェック項目

### PRD (prd.md)
- [ ] 概要が1〜3文で書かれているか
- [ ] ユーザーストーリーが存在するか
- [ ] 受入条件が全て「測定可能」か（数値・状態・有無で判定できる）
- [ ] 異常系・境界ケースが定義されているか
- [ ] スコープ外が明記されているか
- [ ] 曖昧語（適切、十分、なるべく等）が使われていないか
- [ ] 300行以内か

### 設計書 (design.md)
- [ ] PRDの全受入条件に対して実現方法が書かれているか
- [ ] 技術方針が明記されているか
- [ ] ファイル構成が列挙されているか
- [ ] API設計にエラー契約があるか（API機能の場合）
- [ ] テスト方針が記載されているか
- [ ] 依存・影響が記載されているか
- [ ] 未決定事項が残っていないか
- [ ] 条件付きセクションの選定が妥当か（機能の特性に対して必要な設計考慮が含まれ、不要なものが含まれていないか）
- [ ] 300行以内か

## 出力形式

判定: PASS | FAIL

High / Medium / Low に分類して指摘を列挙する。
High が1件でもあれば FAIL。

| 重要度 | 対象ファイル | 指摘内容 |
|--------|------------|---------|
```
