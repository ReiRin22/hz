# Frontend Detail Design Drafter サブエージェント

フロントエンド個別詳細設計書のドラフトを作成する。機能設計書と Figma Make コードを受け取り、テンプレートに従って詳細設計書を書き出す。

## 役割

- 作成（ファイルを書き出す）

## 起動方法

```
Task tool:
  subagent_type: "general-purpose"
  description: "Frontend detail design draft for {画面ID}_{画面名}"
  prompt: 下記のプロンプトテンプレート
```

## プロンプトテンプレート

```
以下の情報をもとに、フロントエンド個別詳細設計書のドラフトを作成してください。

画面ID / 画面名: {画面ID} / {画面名}
出力先: {出力先パス（例: docs/02_アプリ基盤/01_フロントエンド・BFF/02_詳細設計書/フロントエンド個別詳細設計書_【{画面ID}】{画面名}.md）}

## 入力情報

### 機能設計書
{docs/01_アプリ/{domain}/Fxx_{機能名}/design.md の内容}

### Figma Make ソースコード
以下のファイルを読み、コンポーネント構造・型定義・初期フェッチパターンを把握する。
- pages/{PageName}.tsx          ← ページコンポーネント（状態管理・イベントハンドラー）
- lib/types.ts                  ← 型定義（フィールド名・ステータス値の確認）
- features/{domain}/hooks/*.ts  ← データフェッチ・操作ロジック（useEffect の呼び出し順）

Figma Make URL または fileKey: {figma_make_file_key}

### メインエージェントからの補足指示
{確定スコープ・ロール分岐・Figma Make との差異など、事前に確認済みの決定事項}

## 作成ルール

テンプレート `docs/templates/frontend-detail-design.md` に従って作成する。

### Figma Make コードの扱い方

Figma Make はUI構造とフックパターンの参照源として使う。以下の点に注意する。

- **採用してよいもの**: コンポーネント分割・型定義・useEffect による初期フェッチ順序
- **採用してはいけないもの**: Figma Make が独自実装した業務ロジック（機能設計書に記載のないもの）
- 機能設計書と Figma Make に差異がある場合は `[要確認: Figma Make が {内容} を独自実装しているが機能設計書に定義なし]` として残す

### UIコンポーネントID 採番規約

セクション2の表示項目テーブルとセクション4のフロー記述で同じIDを使い、追跡可能にする。

| プレフィックス | 用途 |
| -------------- | ---- |
| HDR_ | ヘッダー系コンポーネント |
| TAB_ | タブ |
| BTN_ | ボタン |
| TBL_ | テーブル |
| COL_ | テーブル列 |
| BDG_ | バッジ |
| SRCH_ | 検索フィールド |
| RDO_ | ラジオボタン |
| TXT_ | テキストエリア |
| ICON_ | アイコン |
| LBL_ | ラベル |
| CHK_ | チェックボックス |
| DRP_ | ドロップダウン |

### セクション別の作成ルール

**セクション2 権限列**
- 空欄禁止。ロール制御をセクション4の前提条件で記述する場合は「セクション4参照」と明記する

**セクション2 条件別サブテーブル**
- フィールドAの値によってフィールドBの活性・入力可否が変わる場合は `=={条件名}の場合==` のサブテーブルを展開する

**セクション4 フロー記述**
- 成功/失敗分岐を必ず記述する
- ロールによる分岐は最外側に記載する
- 保存・確定系APIには確定スコープ（全行/選択行のみ）を必ず明記する

**セクション4 ACT_ID と EVT_ID の使い分け**
- ACT_ID: UIボタン起点の意図宣言（セクション4で使用）
- EVT_ID: システム処理単位（セクション8.1で使用）
- 同一操作に両IDが存在する場合は、両方の表に備考として対応関係を明記する

**セクション8.1 EVT_INIT01**
- 初期表示時に複数のAPIを呼ぶ場合、EVT_INIT01 の備考に「セクション4のフロー記述を参照」と記載し、呼び出し順序はセクション4に記述する

**セクション8.1 確定スコープ**
- 保存・確定系イベントの備考欄に「確定スコープ: 全行 / 選択行のみ」を必ず記載する

### 品質基準

- 機能設計書の全操作フロー・イベントがセクション4に対応していること
- 機能設計書の全エラーメッセージがセクション5に定義されていること
- セクション6の API一覧がセクション4の呼び出しと整合していること
- 300行以内（超える場合は設計書を画面・ダイアログ単位で分割する）

### 注意

- 不明な点は `[要確認: ...]` として残す（勝手に決めない）
- Figma Make コードが機能設計書にない業務ロジックを実装している場合は必ず `[要確認]` を付ける
- 対応する BFF定義書が未作成の場合は `[要確認: BFF定義書_{名前} 未作成]` として記録する

## 出力

指定された出力先にファイルを書き出す。
書き出した内容の要約（UIコンポーネントID数、イベント数、要確認事項数）を報告する。
```
