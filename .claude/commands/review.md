# /review {{対象パス}}

指定されたパスの仕様または実装をレビューする。

**レビューはすべてサブエージェントが実行する。メインエージェントは結果を見て判定を下す。**
**人間への判断委譲は `Skill('common-decision-gate')` のプロトコルに従う。**

---

## 手順

### ステップ1: レビュー実行 [サブエージェント: 検証]

対象の種類に応じてサブエージェントを起動する。

**仕様レビュー（対象が docs/01_アプリ/ の場合）:**

| サブエージェント | 参照 | やること |
|---|---|---|
| **spec-reviewer** | `.claude/agents/app-spec-reviewer.md` | PRD + 設計書の品質をチェック |

spec-reviewer を起動する前に、対応する `.steering/YYYYMMDD-機能名/` が存在するか確認し、存在する場合はそのパスをプロンプトの `調査MDディレクトリ` に渡す。存在しない場合は「なし」を渡す。

**実装レビュー（対象が src/ の場合）:**

| サブエージェント | 参照 | やること |
|---|---|---|
| **impl-validator** | `.claude/agents/impl-validator.md` | 仕様と実装の整合性をチェック |
| **impl-reviewer** | `.claude/agents/app-impl-reviewer.md` | コード品質・型安全性・ルール違反をチェック |

※ impl-validator と impl-reviewer は**並列実行**する。

**両方必要な場合（機能全体のレビュー）:**
- 上記2つを **並列実行** する

### ステップ2: 整合性チェック [サブエージェント: 検証]

| サブエージェント | 参照 | やること |
|---|---|---|
| **consistency-checker** | `.claude/agents/consistency-checker.md` | メタデータの整合性をチェック |

※ ステップ1と並列実行可

### ステップ3: 判定 [メインエージェント: 判断]

サブエージェントの結果を統合し、最終判定を下す。

- **判断**: 各サブエージェントの指摘を統合し、重複を排除する
- **判断**: High が1件でもあれば FAIL
- **判断**: 技術的負債があれば `docs/meta/debt.md` に記録する

### ステップ4: 知見の記録 [メインエージェント: 必須・ゲート前に実行]

**判定結果にかかわらず（PASS・FAIL 両方で）必ず実行する。ゲートを出す前に完了させること。**

#### 4-1. design-review-findings.md への追記

`docs/01_アプリ/design-review-findings.md` を Read してから追記する。

| 項目 | ルール |
|---|---|
| セクション形式 | `## {機能ID} {機能名}（{レイヤー}）` / レイヤー: `フロントエンド` / `BFF` / `バックエンド` |
| 書く内容 | High / Medium 指摘の中から「再発しやすいパターン」のみ（個別 typo は不要） |
| 累積テーブル | 新たな汎用パターンがあれば再発防止チェック一覧に行を追加する |
| 指摘がない場合 | セクションを追加せず、スキップしてよい |

#### 4-2. review-missing-perspectives.md の確認

`impl-reviewer` がステップ1で追記済みかを確認する。**追記されていない場合はメインエージェントが追記する**（impl-reviewer への委譲は保証されないため）。

追記条件: 既存カテゴリに含まれない新しい見落としパターンがあった場合のみ。件数サマリーも更新する。

## 出力形式

```
/review 完了

対象: {{パス}}
判定: PASS | FAIL

High:
- {{指摘内容}}（FAIL の場合のみ）

Medium:
- {{指摘内容}}

技術的負債（発見した場合）:
- {{docs/meta/debt.md に転記する内容}}

整合性:
- {{consistency-checker の結果要約}}

知見記録:
- design-review-findings.md: {{追記あり / 指摘なしにつきスキップ}}
- review-missing-perspectives.md: {{追記あり / 新パターンなし}}

次のアクション:
- PASS → 次フェーズへ進む（人間が判断）
- FAIL → High を解消して再レビュー
```

---

## 判定後のゲート

### PASSの場合 [メインエージェント: 判断]

**[Gate: PHASE]** 次フェーズへの遷移:
```
header: "次のフェーズ"
question: "レビューがPASSしました。次のステップは？"
options:
  - "/implement に進む (推奨)" / description: "設計レビューPASS後の場合"
  - "設計を追加修正する" / description: "軽微な改善を加えてから進む"
  - "一旦保留して別の機能へ" / description: "他の優先作業がある場合"
```

※ 実装レビューPASSの場合:
```
header: "次のフェーズ"
question: "実装レビューがPASSしました。この機能を完了としますか？"
options:
  - "完了にする (推奨)" / description: "INDEX.md を done に更新"
  - "追加の実装をする" / description: "まだ残タスクがある"
  - "一旦保留する"
```

### FAILの場合 [メインエージェント: 判断]

**[Gate: APPROACH]** 対応方針の選択:
```
header: "対応方針"
question: "レビューがFAILしました。High指摘: {指摘の要約}。どう対応しますか？"
options:
  - "High指摘を全て修正する (推奨)" / description: "{修正の概要}"
  - "一部のみ修正して再レビュー" / description: "段階的に対応する"
  - "設計から見直す" / description: "根本的な問題がある場合"
```

---

## ルール

- High が1件でもあれば FAIL
- FAIL の場合、次フェーズへの遷移を禁止する
- レビュー時に対象パス以外のファイルを変更しない
- メインエージェントはサブエージェントの結果を伝達する。自分で再検証はしない
