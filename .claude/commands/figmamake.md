# /figmamake {{機能ID}}

Figma Make の応答ログから機能設計書を自動生成するコマンド。

## 前提条件

以下が **事前に準備されていること**:

1. **応答ログファイル**: `docs/01_アプリ/フロントエンド/{LV1}/{LV2}/{機能ID}-conversation.md`
   - Figma Make で生成した会話履歴をMarkdown形式で保存したもの
   
2. **ソースコード**: `product/frontend/src/features/{LV1}/{LV2}/{画面ID}/`
   - Figma Make で生成した TSX コンポーネント群が配置済み

3. **出力先ディレクトリ**: `docs/01_アプリ/フロントエンド/{LV1}/{LV2}/`
   - 設計書の出力先ディレクトリが存在すること

## 使用例

```bash
/figmamake REC005
```

上記の場合、以下のパスを想定:
- 応答ログ: `docs/01_アプリ/フロントエンド/01_diagnosis/02_medical-info-reference/REC005-conversation.md`
- ソースコード: `product/frontend/src/features/01_diagnosis/02_medical-info-reference/01_medical-info-view/`
- 出力先: `docs/01_アプリ/フロントエンド/01_diagnosis/02_medical-info-reference/design-REC005_診療記録情報参照.md`

## 実行フロー

### ステップ0: 応答ログファイル存在確認（必須）

**❗ 最初に必ず実行すること: 応答ログファイルの存在確認**

1. **機能IDから応答ログファイルを検索**:
   ```bash
   find docs/01_アプリ/フロントエンド -name "${機能ID}-conversation.md" -type f
   ```

2. **見つからない場合は即座に終了**:
   ```
   ❌ エラー: 応答ログファイルが見つかりません
   
   必要なファイル: {機能ID}-conversation.md
   検索パス: docs/01_アプリ/フロントエンド/
   
   対処方法:
   1. Figma Make の画面で会話履歴をコピー
   2. 以下のパスに保存:
      docs/01_アプリ/フロントエンド/{LV1}/{LV2}/{機能ID}-conversation.md
   
   例: REC005 の場合
      docs/01_アプリ/フロントエンド/01_diagnosis/02_medical-info-reference/REC005-conversation.md
   
   ファイル保存後、再度 /figmamake {機能ID} を実行してください。
   ```
   
   **ここで処理終了。以降のステップは実行しない。**

3. **見つかった場合のみ続行**:
   - 応答ログファイルのパスを記録: `{conversation_file_path}`
   - 親ディレクトリを出力先として記録: `{docs_path}`

### ステップ1: パス解決

1. **ソースコードディレクトリを検索**:
   ```bash
   find product/frontend/src/features -name "*${機能ID}*" -type d
   ```

2. **見つからない場合はエラーを表示して終了**:
   ```
   ❌ エラー: ソースコードディレクトリが見つかりません
   
   必要なディレクトリ: product/frontend/src/features/*/{機能ID}/
   
   対処方法:
   1. Figma Make で生成したコードを配置
   2. ディレクトリ構造を確認
   
   準備完了後、再度 /figmamake {機能ID} を実行してください。
   ```

3. **見つかった場合**:
   - ソースコードパスを記録: `{src_path}`

### ステップ2: スキル起動

**`app-figma-design-workflow` スキルを起動**:
```
Skill('app-figma-design-workflow', args: "{機能ID}")
```

このスキルが以下を指示:
- 必要なエージェントの順序
- ファイルパスの命名規則
- 完了条件

### ステップ3: 画面構造サマリー生成 [サブエージェント]

`.claude/agents/app-figma-screen-extractor.md` のプロンプトテンプレートに従ってエージェントを起動:

```markdown
Agent(
  subagent_type: "general-purpose",
  description: "Figma screen extraction: {機能ID}",
  prompt: """
Figma make で生成した TSX ソースを読み取り、機能設計書作成用の画面構造サマリーを出力してください。

## 入力

- ソースフォルダ: {src_path}/
- 出力先: {docs_path}/screen-summary-{機能ID}.md

## 作業手順

### Step1: エントリポイントを読む
- エントリポイントファイル（メインコンポーネント）を Read で読み込む
- 画面全体のパネル構成を把握する
- **対象機能のメインコンポーネント**を特定する

### Step2: 対象機能のコンポーネントのみ読む
- `components/` 配下を Glob で列挙する
- 対象機能のメインパネル・ダイアログを読む
- 対象機能が呼び出す子コンポーネントを読む

### Step3: hooks/ と types/ を読む（対象機能分のみ）
- hooks/ 配下の状態管理フックを確認
- types/ 配下の型定義を確認

### Step4: 画面構造サマリーを作成
- 下記フォーマットに従って screen-summary.md を作成

## 出力フォーマット

\```markdown
# {機能ID} {機能名} 画面構造サマリー

## 画面全体構成

（エントリポイントファイルのレイアウト構造を記述）

## コンポーネント一覧

### {カテゴリ名}
- {ComponentName}.tsx
  - 機能: （主要な機能を箇条書き）
  - 表示項目: （表示される項目）

## 状態管理

（hooks/ 配下のフックと役割を記述）

## データ型

（types/ 配下の主要な型定義を記述）
\```

## 制約

- 各TSXファイルを読み取り、主要な機能・項目を抽出する
- コード全体をコピーせず、**要約のみ** を記述する
- 出力先: `{docs_path}/screen-summary-{機能ID}.md`

開始してください。
"""
)
```

### ステップ4: 機能設計書生成 [サブエージェント]

`.claude/agents/app-design-from-figma-drafter.md` のプロンプトテンプレートに従ってエージェントを起動:

```markdown
Agent(
  subagent_type: "general-purpose",
  description: "Design draft from Figma: {機能ID}",
  prompt: """
以下の情報を基に、機能設計書（design.md）のドラフトを作成してください。

## 入力

- 応答ログ: {docs_path}/{機能ID}-conversation.md
- 画面構造サマリー: {docs_path}/screen-summary-{機能ID}.md
- 出力先: {docs_path}/{機能ID}_{機能名}_機能設計書.md

## 作業手順

### Step1: インプットを読む
- 応答ログを Read で読み込み、Figma Make での会話内容・生成意図を把握する
- 画面構造サマリーを Read で読み込み、パネル構成・UI要素・ダイアログを把握する

### Step2: 設計書を作成する
- 下記フォーマットに従って機能設計書を作成する
- 応答ログのユーザー要件・AI提案を設計書に反映する
- 画面構造サマリーからパネル・ダイアログ・UI要素を設計に落とし込む
- 不明な点は `[要確認: ...]` として残す（勝手に決めない）

### Step3: 出力する
- Write ツールで出力先に保存する
- 保存後、セクション数・要確認事項数を報告する

## 出力フォーマット

\```markdown
# {機能ID} {機能名} 機能設計書

## 1. 機能概要

（機能の目的・スコープを2-3文で記述）

## 2. 画面構成

### 2.1 全体レイアウト

（レイアウト構造の説明）

### 2.2 {主要セクション名}

（主要な機能・表示項目）

## 3. 主要機能

### 3.1 {機能名}

（機能の詳細）

## 4. データ型・状態管理

### 4.1 主要データ型

（主要な型定義）

### 4.2 状態管理フック

（使用するフック）

## 5. 非機能要件

### 5.1 パフォーマンス

（パフォーマンス要件）

### 5.2 セキュリティ

（セキュリティ要件）

## 6. 実装上の注意点

（重要な実装パターン・制約事項を箇条書き）
\```

## 制約

- 約1000字で簡潔にまとめる
- 技術的な詳細（TSXコード）は含めない
- 設計書として必要な情報（機能・データ・フロー）に絞る

開始してください。
"""
)
```

## エラーハンドリング

### 応答ログファイル不足の場合（最優先チェック）

**ステップ0で即座に終了**:

```
❌ エラー: 応答ログファイルが見つかりません

必要なファイル: {機能ID}-conversation.md
検索パス: docs/01_アプリ/フロントエンド/

対処方法:
1. Figma Make の画面で会話履歴をコピー
2. 以下のパスに保存:
   docs/01_アプリ/フロントエンド/{LV1}/{LV2}/{機能ID}-conversation.md

例: REC005 の場合
   docs/01_アプリ/フロントエンド/01_diagnosis/02_medical-info-reference/REC005-conversation.md

ファイル保存後、再度 /figmamake {機能ID} を実行してください。
```

### ソースコード不足の場合

**ステップ1で終了**:

```
❌ エラー: ソースコードディレクトリが見つかりません

必要なディレクトリ: product/frontend/src/features/*/{機能ID}/

対処方法:
1. Figma Make で生成したコードを配置
2. ディレクトリ構造を確認

準備完了後、再度 /figmamake {機能ID} を実行してください。
```

### パス解決失敗の場合

```
❌ エラー: 機能ID "{機能ID}" に該当するディレクトリが見つかりません

以下のコマンドで手動検索してください:
  find docs/01_アプリ/フロントエンド -name "*{機能ID}*" -type d
  find product/frontend/src/features -name "*{機能ID}*" -type d

該当ディレクトリが見つからない場合:
1. ソースコードが正しく配置されているか確認
2. 機能IDのスペルミスがないか確認
3. ディレクトリ構造が想定通りか確認
```

## 注意事項

1. **応答ログファイルの命名規則**: `{機能ID}-conversation.md` で統一すること
2. **ソースコードの配置**: Figma Make 生成コードは `product/frontend/src/features/{LV1}/{LV2}/{画面ID}/` 配下に配置
3. **300行制限**: 生成される設計書が300行を超える場合があるが、REC002準拠のため許容される
4. **手動調整が必要な場合**: 生成後に `/review` で品質を確認し、必要に応じて手動調整する
