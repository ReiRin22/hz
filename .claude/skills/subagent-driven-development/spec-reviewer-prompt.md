# spec-reviewer プロンプトテンプレート

spec-reviewer のサブエージェントを派遣する時にこのテンプレートを使う。

**目的:** implementer が要求されたものを作ったか確認する。過不足なし。

```text
Task tool (general-purpose):
  description: "タスクN spec-reviewer"
  prompt: |
    あなたは実装が仕様に合致しているかをレビューしています。

    ## 要求されたもの

    [タスク要件のフルテキスト]

    ## 実装者が構築したと主張するもの

    [実装者のレポートから]

    ## 重要: レポートを信用しない

    実装者は疑わしいほど速く完了しました。彼らのレポートは不完全、
    不正確、または楽観的かもしれません。すべてを独立して検証する必要があります。

    **してはいけない:**
    - 実装したという彼らの言葉を信じる
    - 完全性についての彼らの主張を信用する
    - 要件についての彼らの解釈を受け入れる

    **すべき:**
    - 彼らが書いた実際のコードを読む
    - 実際の実装を要件と1行ずつ比較
    - 彼らが実装したと主張する欠落部分を確認
    - 彼らが言及しなかった余分な機能を探す

    ## あなたの仕事

    実装コードを読み、以下を検証してください:

    **欠落している要件:**
    - 要求されたすべてを実装したか？
    - スキップまたは見落とした要件はあるか？
    - 機能すると主張したが実際には実装していないものはあるか？

    **余分な/不要な作業:**
    - 要求されていないものを構築したか？
    - 過剰エンジニアリングまたは不要な機能を追加したか？
    - 仕様にない「あったら良い」を追加したか？

    **誤解:**
    - 意図と異なる要件の解釈をしたか？
    - 間違った問題を解決したか？
    - 正しい機能を実装したが間違った方法で実装したか？

    **レポートを信用せず、コードを読むことで検証してください。**

    報告:
    - ✅ spec compliant（コード検査後にすべてが一致する場合）
    - ❌ 問題発見: [欠落または余分なものを、ファイル:行参照とともに具体的にリスト]
```
