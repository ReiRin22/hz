# implement-phase0-test: Phase 0 完了確認

Phase 0（T0-1〜T0-6）の全タスクが完了したら、このスキルを実行する。
目的は「tasklist.md の記録」と「コード内タグの実在」を照合し、
Phase 1 を安全に開始できる状態かどうかを確認すること。

---

## 前提: 対象パスの特定

`.steering/{日付-機能名}/tasklist.md` のパスを呼び出し時に確認する。
パスが不明な場合は `.steering/` 配下を `find` で確認する。

```bash
find .steering -name "tasklist.md" | sort
```

対象機能のディレクトリ（例: `product/frontend/src/features/01_diagnosis/...`）も
呼び出し時に確認する。

---

## ステップ 1: tasklist.md を読み込む

対象の `tasklist.md` を Read で読み込み、T0-1〜T0-6 の各セクションが存在するか確認する。

---

## ステップ 2: 各タスクの完了条件をチェック

### T0-1: コンポーネント一覧

tasklist.md に以下が記録されているか確認する:
- コンポーネント一覧（層 / 名前 / 責務）が存在する
- Atoms / Molecules / Organisms / Page の4層が何らかの形で言及されている

### T0-2: スコープ内/外リスト

tasklist.md に以下が記録されているか確認する:
- 「スコープ内」または「スコープ外」のセクションが存在する
- 少なくとも1件以上の項目が列挙されている

### T0-3: 他機能との境界

以下のいずれかが満たされているか確認する:
- tasklist.md に境界に関する記述がある
- コード内に `[SCOPE-OUT:` タグまたは境界コメントが存在する

```bash
# 対象ディレクトリ配下の境界コメントを確認
grep -r "SCOPE-OUT\|担当領域\|他機能\|境界" {対象ディレクトリ} \
  --include="*.tsx" --include="*.ts" -l 2>/dev/null | head -10
```

### T0-4: shared 振り分けリスト

tasklist.md に以下が記録されているか確認する:
- 「shared 振り分け」または「T0-4」のセクションが存在する
- 以下の3分類のいずれかが明示されている:
  - 「アプリ全体 shared に移動」するファイル
  - 「LV3内 src/ 二重化解消」の対象
  - 「LV3に留める」ファイル
- **全てLV3留まりの場合も「移動対象なし」と明示的に記録されていること**

### T0-5: スコープ外コードのコメントアウト

以下の両方を確認する:

①  tasklist.md に「スコープ外管理」または T0-5 の記録がある

② コード内に `[SCOPE-OUT:` タグが実在する（スコープ外コードが0件の場合はスキップ可）

```bash
# [SCOPE-OUT:] タグの実在確認
grep -r "\[SCOPE-OUT:" {対象ディレクトリ} \
  --include="*.tsx" --include="*.ts" --include="*.css" -l 2>/dev/null
```

### T0-6: プレースホルダーの配置

以下の両方を確認する:

① tasklist.md に T0-6 またはプレースホルダーの記録がある

② コード内に `[PLACEHOLDER:` タグが実在する（プレースホルダーが0件の場合はスキップ可）

```bash
# [PLACEHOLDER:] タグの実在確認
grep -r "\[PLACEHOLDER:" {対象ディレクトリ} \
  --include="*.tsx" --include="*.ts" -l 2>/dev/null
```

```
- T0-Y: {理由}

```

```

```
