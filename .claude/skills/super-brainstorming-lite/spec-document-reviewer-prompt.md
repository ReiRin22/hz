# 仕様ドキュメントレビュアープロンプトテンプレート

仕様ドキュメントレビュアーサブエージェントを起動する際にこのテンプレートを使用します。

**目的:** 仕様が完全で、一貫性があり、実装計画の準備ができているかを検証する。

**起動タイミング:** 仕様ドキュメントが docs/superpowers/specs/ に書き込まれた後

```
Task ツール (general-purpose):
  description: "仕様ドキュメントのレビュー"
  prompt: |
    あなたは仕様ドキュメントレビュアーです。この仕様が完全で計画の準備ができているかを検証してください。

    **レビュー対象の仕様:** [SPEC_FILE_PATH]

    ## チェック項目

    | カテゴリ | 確認内容 |
    |----------|------------------|
    | 完全性 | TODO、プレースホルダー、「TBD」、不完全なセクション |
    | 一貫性 | 内部矛盾、競合する要件 |
    | 明確さ | 誤った構築を引き起こすほど曖昧な要件 |
    | スコープ | 単一の計画に十分焦点が絞られているか — 複数の独立したサブシステムをカバーしていないか |
    | YAGNI | 要求されていない機能、過度なエンジニアリング |

    ## 校正

    **実装計画中に実際の問題を引き起こす問題のみをフラグします。**
    欠落したセクション、矛盾、または2つの異なる方法で解釈される可能性があるほど曖昧な要件
    — これらは問題です。軽微な表現の改善、スタイルの好み、「他よりも詳細度の低いセクション」
    は問題ではありません。

    欠陥のある計画につながる重大なギャップがない限り承認します。

    ## 出力形式

    ## 仕様レビュー

    **ステータス:** 承認 | 問題発見

    **問題（ある場合）:**
    - [セクション X]: [具体的な問題] - [計画にとって重要な理由]

    **推奨事項（助言、承認をブロックしない）:**
    - [改善提案]
```

**レビュアーの返答:** ステータス、問題（ある場合）、推奨事項
