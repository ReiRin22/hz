# PRD品質基準

このスキルはPRDの「書き方ガイド」である。テンプレートは `docs/templates/prd.md`。

## いつ読むか

- `/design` コマンドのPRD作成・推敲時
- 毎セッション読み直してよい（品質基準のリマインドとして機能する）

## PRDの品質チェックリスト

### 受入条件（最重要）

- [ ] 全ての受入条件が「測定可能」である
  - NG: 「ユーザーが快適に使えること」
  - OK: 「画面遷移が200ms以内に完了すること」
  - OK: 「エラー時にエラーコードとメッセージが表示されること」
- [ ] 正常系・異常系・境界値が網羅されている
- [ ] 各条件がテストケースに変換可能である

### 要件の明確さ

- [ ] 曖昧語を使っていない（適切、十分、なるべく、基本的に、可能な限り）
- [ ] 主語が明確（「ユーザーが」「システムが」「管理者が」）
- [ ] 数値や状態で判定できる条件になっている

### 構造

- [ ] 概要が1〜3文で書かれている
- [ ] ユーザーストーリーが「誰が・何を・なぜ」の形式
- [ ] スコープ外が明記されている（やらないことの宣言）
- [ ] 依存する他機能があれば記載されている

### 非機能要件

- [ ] パフォーマンス基準が数値で定義されている（該当する場合）
- [ ] セキュリティ要件が明記されている（該当する場合）

## アンチパターン

- 1つのPRDに複数の独立した機能を詰め込む → 分割する
- 実装方法（HOW）を書く → PRDは要件（WHAT）のみ。HOWは design.md
- 「〜も検討する」「将来的には〜」→ スコープ外に移す。PRDは今作るものだけ
