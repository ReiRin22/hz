# 実装計画の実行

## 概要

計画を読み込み、批判的にレビューし、すべてのタスクを実行し、完了時に報告する。

**開始時のアナウンス:** "executing-plans スキルを使用してこの計画を実装します。"

**注意:** Superpowers はサブエージェントへのアクセスがあると大幅に品質が向上します。サブエージェントをサポートするプラットフォーム（Claude Code や Codex など）で実行すると、作業品質が大幅に向上します。サブエージェントが利用可能な場合は、このスキルの代わりに subagent-driven-development を使用してください。

## プロセス

### ステップ0: ローカルサーバー起動（Phase プランの場合）

計画ファイルが `.steering/*/phase*-plan.md` の場合:
1. **必須サブスキル:** `plan-progress-viewer` を起動する
2. ローカルサーバーで進捗をリアルタイム表示
3. サーバー起動を待ってから次のステップへ進む

### ステップ0.5: ワークスペース戦略の選択

**ユーザーに確認:**
"この実装で git worktree を使用しますか？（npm install に時間がかかる場合は No を推奨）"

**選択肢:**

**A. Worktree を使用する:**
- 隔離された環境で安全に作業
- **必須サブスキル:** `using-git-worktrees` を実行
- 完了後に `finishing-a-development-branch` を使用

**B. Worktree をスキップ（推奨）:**
- カレントブランチで直接作業
- `using-git-worktrees` をスキップ
- `finishing-a-development-branch` もスキップ
- 実装完了後は手動で commit & push

**選択を記録:**
- ユーザーの選択を TodoWrite にメモ
- ステップ3 で参照して適切な完了処理を実行

### ステップ1: 計画の読み込みとレビュー

1. 計画ファイルを読む
2. 批判的にレビュー - 計画に関する質問や懸念を特定する
3. 懸念がある場合: 開始前に人間のパートナーに相談する
4. 懸念がない場合: TodoWrite を作成して進む

### ステップ2: タスクの実行

各タスクについて:
1. in_progress としてマークする
2. 各ステップを正確に従う（計画には一口サイズのステップが含まれている）
3. 指定された検証を実行する
4. completed としてマークする

### ステップ3: 開発の完了

すべてのタスクが完了し検証された後:

**ステップ0.5 で worktree を使用した場合:**
- アナウンス: "finishing-a-development-branch スキルを使用してこの作業を完了します。"
- **必須サブスキル:** finishing-a-development-branch を使用する
- そのスキルに従ってテストを検証し、オプションを提示し、選択を実行する

**ステップ0.5 で worktree をスキップした場合:**
- アナウンス: "実装が完了しました。手動で commit と push を実行してください。"
- 推奨コミットメッセージを提示:
  ```
  git add .
  git commit -m "実装: [機能名]"
  git push
  ```
- ユーザーが手動でコミット・プッシュを実行

## 停止して助けを求めるタイミング

**以下の場合は即座に実行を停止:**
- ブロッカーに遭遇（依存関係の欠落、テスト失敗、指示が不明確）
- 計画に開始を妨げる重大なギャップがある
- 指示を理解できない
- 検証が繰り返し失敗する

**推測するのではなく、明確化を求める。**

## 以前のステップに戻るタイミング

**レビュー（ステップ1）に戻る場合:**
- パートナーがフィードバックに基づいて計画を更新した
- 基本的なアプローチを再考する必要がある

**ブロッカーを無理に押し通さない** - 停止して尋ねる。

## 覚えておくこと

- 最初に計画を批判的にレビューする
- 計画のステップに正確に従う
- 検証をスキップしない
- 計画がスキルを参照している場合はスキルを使用する
- ブロックされたら停止し、推測しない
- ユーザーの明示的な同意なしに main/master ブランチで実装を開始しない

## 統合

**ワークフロースキル:**
- **using-git-worktrees** - （任意）隔離されたワークスペースを確保（新規作成または既存を検証）
- **writing-plans** - このスキルが実行する計画を作成
- **plan-progress-viewer** - Phase プランファイル実行時に進捗を可視化
- **finishing-a-development-branch** - （任意）worktree 使用時のみ、すべてのタスク後に開発を完了

**Phase プランファイルの検出:**
- ファイル名が `phase*-plan.md` パターンにマッチする場合
- 自動的に `plan-progress-viewer` を起動する
- 進捗は http://localhost:52341 でリアルタイム表示される
