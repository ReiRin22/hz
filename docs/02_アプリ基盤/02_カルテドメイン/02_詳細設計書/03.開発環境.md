## .NET プロジェクト設定

### .csproj の設定項目

`product/backend/KarteDomainService/KarteDomainService.csproj` の各設定を説明する。

```xml
<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Microsoft.EntityFrameworkCore.Design" Version="10.0.3">
      <IncludeAssets>runtime; build; native; contentfiles; analyzers; buildtransitive</IncludeAssets>
      <PrivateAssets>all</PrivateAssets>
    </PackageReference>
    <PackageReference Include="Microsoft.OpenApi" Version="2.4.1" />
    <PackageReference Include="NLog.Web.AspNetCore" Version="6.1.2" />
    <PackageReference Include="Npgsql.EntityFrameworkCore.PostgreSQL" Version="10.0.1" />
    <PackageReference Include="Scrutor" Version="7.0.0" />
    <PackageReference Include="Swashbuckle.AspNetCore" Version="10.1.7" />
  </ItemGroup>
</Project>
```

#### PropertyGroup の設定

| 設定 | 値 | 意図 |
| --- | --- | --- |
| `TargetFramework` | `net10.0` | .NET 10（最新 LTS）。変更時は Dockerfile のイメージバージョンも合わせる |
| `Nullable` | `enable` | null 許容参照型を有効化。`?` なしの参照型は non-nullable として扱われ、コンパイル警告が出る |
| `ImplicitUsings` | `enable` | `System`・`System.Linq` 等の頻用 using を暗黙インポート。各ファイルへの明示記述が不要 |

#### ItemGroup の設定（NuGet パッケージ）

パッケージの追加・更新は `<PackageReference>` で管理する。

| パッケージ | PrivateAssets | 用途 |
| --- | --- | --- |
| `Microsoft.EntityFrameworkCore.Design` | `all` | EF Core マイグレーション生成ツール。ビルド成果物には含めない |
| `Microsoft.OpenApi` | （なし） | OpenAPI モデル定義（Swashbuckle の依存） |
| `NLog.Web.AspNetCore` | （なし） | 構造化ログ（NLog の ASP.NET Core 統合） |
| `Npgsql.EntityFrameworkCore.PostgreSQL` | （なし） | PostgreSQL 用 EF Core プロバイダー |
| `Scrutor` | （なし） | アセンブリスキャンによる DI 自動登録 |
| `Swashbuckle.AspNetCore` | （なし） | Swagger UI 生成 |

#### バージョン管理方針

| バージョン種別 | 内容 | 更新方針 | 理由 |
| --- | --- | --- | --- |
| **メジャー** | 大規模な API・動作変更 | 固定（手動更新・基盤チーム検証必須） | 破壊的変更により既存実装が動作しなくなる可能性があるため、慎重な検証が必要 |
| **マイナー** | 部分的な機能改善・機能追加 | 手動更新可（影響範囲確認後） | 後方互換性があり、バグ修正・新機能の恩恵を受ける |
| **パッチ** | バグ・セキュリティ修正 | 優先適用 | 適用しないことがリスクとなる |

**`csproj` での記述方針：**

```xml
<!-- バージョンは完全固定値で記載する（範囲指定 * は使用しない） -->
<PackageReference Include="NLog.Web.AspNetCore" Version="6.1.2" />
```

**その他の管理ルール：**
- 新しいパッケージを追加する場合は、ライセンス・メンテナンス状況・セキュリティ評価を確認する
- ビルド専用ツールは `<PrivateAssets>all</PrivateAssets>` を付与して成果物に含めない

```bash
dotnet outdated                                             # 更新可能なパッケージを確認
dotnet add package NLog.Web.AspNetCore --version 6.1.2    # 特定パッケージの更新
```

## 環境変数・設定値の管理

### appsettings.json の設定項目

`appsettings.json` は全環境共通のデフォルト値を定義する。

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "ConnectionStrings": {
    "DefaultConnection": "Host=harz-db;Port=5432;Database=harz_db;Username=harz_user;Password=password"
  }
}
```

#### 各項目の意図と変更ルール

| 項目 | 意図 | 変更タイミング |
| --- | --- | --- |
| `Logging.LogLevel.Default` | アプリ全体のログ出力レベル（Information 以上を出力） | デバッグ時は `Debug` に変更してよい |
| `Logging.LogLevel.Microsoft.AspNetCore` | フレームワーク内部のログをWarning以上に抑制（ノイズ削減） | 通常変更不要 |
| `AllowedHosts` | `"*"` で全ホストからのアクセスを許可（開発環境向け） | 本番環境では特定ホストに制限する |
| `ConnectionStrings.DefaultConnection` | `Host=harz-db` は docker-compose のサービス名。ローカル直接起動時は `localhost` に変更 | 接続先 DB 変更時 |

### appsettings.Development.json の設定項目

`appsettings.Development.json` は開発環境専用の上書き設定。`ASPNETCORE_ENVIRONMENT=Development` の場合に `appsettings.json` を上書きして適用される。

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

開発環境専用の設定を追加する場合はここに記載する（例: 詳細ログ、Swagger 設定等）。

### 環境別設定の切り替えルール

| 環境 | ファイル | `ASPNETCORE_ENVIRONMENT` |
| --- | --- | --- |
| 開発（DevContainer） | appsettings.json + appsettings.Development.json | `Development`（docker-compose で設定済み） |
| ステージング | appsettings.json + appsettings.Staging.json（作成時） | `Staging` |
| 本番 | appsettings.json + appsettings.Production.json（作成時） | `Production` |

本番の機密情報（DB パスワード等）は `appsettings.json` に直接書かず、環境変数で渡す。

### NLog 設定

`nlog.config` でログの出力先・フォーマットを定義する。`Program.cs` で `builder.Host.UseNLog()` を呼ぶことで読み込まれる。

```xml
<targets>
  <!-- JSON形式でファイル出力（日付ローテーション） -->
  <target xsi:type="File" name="jsonFile" fileName="logs/app-${shortdate}.json">
    <layout xsi:type="JsonLayout">
      <attribute name="timestamp"  layout="${date:format=yyyy-MM-ddTHH\:mm\:ss.fffZ:universalTime=true}" />
      <attribute name="level"      layout="${level:upperCase=true}" />
      <attribute name="message"    layout="${message}" />
      <attribute name="exception"  layout="${exception:format=tostring}" />
      <attribute name="tenant_id"  layout="${mdlc:item=TenantId}" />
      <attribute name="actor"      layout="${mdlc:item=Actor}" />
      <attribute name="action"     layout="${mdlc:item=Action}" />
      <attribute name="resource"   layout="${mdlc:item=Resource}" />
      <attribute name="status"     layout="${mdlc:item=Status}" />
      <attribute name="trace_id"   layout="${mdlc:item=TraceId}" />
    </layout>
  </target>
  <!-- コンソールにも同時出力 -->
  <target xsi:type="Console" name="logconsole"
          layout="${longdate}|${level:upperCase=true}|${message} ${exception:format=tostring}" />
</targets>

<rules>
  <logger name="*" minlevel="Info" writeTo="jsonFile,logconsole" />
</rules>
```

#### ログ出力項目

| フィールド | 役割 | 型 / 内容 |
| --- | --- | --- |
| `timestamp` | 発生時刻 | ISO 8601 形式（ミリ秒精度・UTC） |
| `level` | ログレベル | `INFO` / `WARN` / `ERROR` 等 |
| `message` | ログ本文 | 処理内容・エラー概要 |
| `exception` | 例外詳細 | スタックトレース（例外なしは空） |
| `tenant_id` | テナント識別 | 医療機関 ID・テナントコード（論理・物理分離のキーとして使用） |
| `actor` | 操作主体 | ユーザー ID・クライアント IP・ロール |
| `action` | 操作内容 | `CREATE` / `READ` / `UPDATE` / `DELETE` 等 |
| `resource` | 操作対象 | 患者 ID・文書 ID 等の機微情報キー |
| `status` | 処理結果 | `SUCCESS` / `FAILURE` / `DENIED` |
| `trace_id` | 関連性 | BFF が `X-Trace-ID` ヘッダーで送信する一意な ID。`TraceIdMiddleware` が取り出し MDLC にセット |

| 設定 | 内容 |
| --- | --- |
| ファイル出力先 | `logs/app-{日付}.json`（日付ローテーション） |
| フォーマット | JSON（上記フィールド） |
| コンソール出力 | `longdate\|LEVEL\|message exception` 形式 |
| 最低出力レベル | `Info` 以上 |
| テナント追跡 | `${mdlc:item=TenantId}` で `TenantMiddleware` がセットした値を出力 |
| トレース追跡 | `${mdlc:item=TraceId}` で `TraceIdMiddleware` がセットした `X-Trace-ID` を出力 |

## Program.cs の起動設定

`Program.cs` はアプリケーションのエントリーポイントであり、サービス登録（DI）・ミドルウェアパイプライン・起動設定を集約的に記述する。

### サービス登録（DI）

#### Scrutor によるアセンブリスキャン

機能を追加するたびに `Program.cs` へ `AddScoped` を手動追記する煩雑さを避けるため、**Scrutor** によるアセンブリスキャン自動登録を採用する。

```csharp
// Program.cs — 新機能追加時に変更不要
builder.Services.Scan(scan => scan
    .FromAssemblyOf<Program>()
    .AddClasses(classes => classes
        .InNamespaces("KarteDomainService.Features")
        .Where(t => t.Name.EndsWith("Repository") || t.Name.EndsWith("Service")))
    .AsSelf()
    .WithScopedLifetime());
```

この設定により、`Features/` 配下に `XxxRepository.cs` または `XxxService.cs` を作成するだけで DI に自動登録される。**`Program.cs` への追記は不要。**

#### 手動登録が必要なクラス

以下は自動スキャン対象外のため、引き続き `Program.cs` に明示的に登録する：

| クラス | 理由 |
| --- | --- |
| `TenantService` | `Shared/Services/` 配下のため対象外 |
| `TenantSchemaInterceptor` | `Shared/Data/` 配下のため対象外 |
| `ApplicationDbContext` | `AddDbContext<T>` で別途設定が必要 |

### ミドルウェアパイプライン登録順序

ミドルウェアの登録順序は重要。リクエストは登録順に上から処理され、レスポンスは逆順（下から上）に通過する。

```csharp
var app = builder.Build();

// 開発環境のみ Swagger UI を有効化
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}

// ミドルウェアパイプライン
app.UseMiddleware<ExceptionMiddleware>();  // 1. 最初（全例外をキャッチ）
app.UseMiddleware<TenantMiddleware>();     // 2. テナント ID 取得
app.UseAuthentication();                   // 3. 認証
app.UseAuthorization();                    // 4. 認可
app.MapControllers();                      // 5. ルーティング

app.Run();
```

**登録順序の理由:**
1. **ExceptionMiddleware** は最初に登録し、後続のミドルウェア・Controller で発生した例外をすべてキャッチする
2. **TenantMiddleware** は認証の前にテナント ID を取得・検証する（認証処理でテナント情報が必要なため）
3. **UseAuthentication → UseAuthorization** の順序は ASP.NET Core の標準順序
4. **MapControllers** は最後に登録する

## デバッグ設定

### launchSettings.json の設定項目

`product/backend/KarteDomainService/Properties/launchSettings.json` は `dotnet run` / `dotnet watch run` 時の起動設定。DevContainer 内での実行プロファイルを定義する。

```json
{
  "profiles": {
    "http": {
      "commandName": "Project",
      "dotnetRunMessages": true,
      "launchBrowser": false,
      "applicationUrl": "http://localhost:5027",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    },
    "https": {
      "commandName": "Project",
      "launchBrowser": false,
      "applicationUrl": "https://localhost:7121;http://localhost:5027",
      "environmentVariables": {
        "ASPNETCORE_ENVIRONMENT": "Development"
      }
    }
  }
}
```

#### 各プロファイルの使い分け

| プロファイル | URL | 用途 |
| --- | --- | --- |
| `http` | `http://localhost:5027` | DevContainer 内で直接起動する場合 |
| `https` | `https://localhost:7121` + `http://localhost:5027` | HTTPS 対応が必要な場合（開発用証明書が必要） |

**docker-compose 経由での起動時は `launchSettings.json` は使用されない。** Dockerfile の `CMD ["dotnet", "watch", "run", "--urls", "http://0.0.0.0:7121"]` が実際の起動コマンド。

Dockerfile には以下の環境変数が設定されており、`dotnet watch` の挙動を制御する：

| 環境変数 | 値 | 効果 |
| --- | --- | --- |
| `DOTNET_WATCH_RESTART_ON_RUDE_EDIT` | `true` | `.csproj` 変更など通常はリロード不可な「破壊的編集」でも自動再起動する |

### Swagger UI でのデバッグ

`ASPNETCORE_ENVIRONMENT=Development` の場合、Swagger UI が自動的に有効化される。

アクセス URL: `http://localhost:7121/swagger`

#### テナント ID の入力方法

Swagger UI ではリクエストヘッダーに `X-Tenant-ID` を付与する必要がある（TenantMiddleware による検証）。

1. Swagger UI 上部の `Authorize` ボタンをクリック
2. `X-Tenant-ID` 欄にテナント ID（例: `tenant_001`）を入力
3. `Authorize` をクリックして全リクエストにヘッダーを付与

`Program.cs` の Swagger 設定：

```csharp
// using Microsoft.OpenApi; が必要
c.AddSecurityDefinition("X-Tenant-ID", new OpenApiSecurityScheme
{
    In = ParameterLocation.Header,
    Name = "X-Tenant-ID",
    Type = SecuritySchemeType.ApiKey
});
c.AddSecurityRequirement(document => new OpenApiSecurityRequirement
{
    [new OpenApiSecuritySchemeReference("X-Tenant-ID", document)] = Array.Empty<string>()
});
```

## コード品質管理

### 命名規則

C# / .NET 標準ガイドラインに準拠する。

| 対象 | 規則 | 例 |
| --- | --- | --- |
| クラス・メソッド | PascalCase | `PatientService`, `GetPatientAsync` |
| プライベートフィールド | `_camelCase`（アンダースコアプレフィックス） | `_repository`, `_logger` |
| パラメーター・ローカル変数 | camelCase | `patientId`, `result` |
| エンティティ（トランザクション） | `T` プレフィックス + PascalCase | `TChiefComplaint`, `TVitalInfo` |
| エンティティ（マスタ） | `M` プレフィックス + PascalCase | `MBloodType`, `MRhFactor` |
| ファイル名 | クラス名と完全一致 | `PatientService.cs` |

### 静的解析

.NET プロジェクトはビルド時に Roslyn アナライザーが自動実行される。警告はビルドログで確認できる。

警告をエラーとして扱う場合は `.csproj` に追加：

```xml
<PropertyGroup>
  <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
</PropertyGroup>
```

### 文言・ラベル管理規定

エラーメッセージ・例外メッセージ・ログメッセージ等の文言は、各ソースファイル内にハードコードせず、`Resources/Resources.resx` で一元管理する。

#### 管理対象

| 種別 | 例 |
| --- | --- |
| エラーメッセージ（レスポンス） | `"不正なリクエストです。"` |
| 例外メッセージ | `"テナントIDが不明です。"` |
| ログメッセージ | `"予期せぬエラーが発生しました。"` |
| バリデーションメッセージ | `"ファイルサイズは5MB以下にしてください。"` |

#### ファイル構成

```
KarteDomainService/
  Resources/
    Resources.resx              ← 文言定義（XML）
    Resources.Designer.cs       ← 自動生成のアクセサクラス（直接編集しない）
```

#### キー命名規則

| パターン | 用途 | 例 |
| --- | --- | --- |
| `E{HTTPステータスコード}{連番3桁}` | HTTP エラーに対応する汎用メッセージ | `E400000`, `E500001` |
| `E_{ドメイン}_{内容}` | 業務固有のエラーメッセージ | `E_UPLOAD_SIZE_EXCEEDED`, `E_TENANT_ID_MISSING` |
| `LOG_{内容}` | ログ出力専用メッセージ | `LOG_UNEXPECTED_ERROR` |

#### 運用方法

**1. 新しい文言を追加する**

`Resources.resx` に `<data>` エントリを追加する：

```xml
<data name="E_PATIENT_NOT_FOUND" xml:space="preserve">
  <value>患者が見つかりませんでした。</value>
</data>
```

`Resources.Designer.cs` に対応するプロパティを追加する：

```csharp
internal static string E_PATIENT_NOT_FOUND => GetString("E_PATIENT_NOT_FOUND");
```

**2. ソースコードから参照する**

```csharp
using KarteDomainService.Resources;

// エラーレスポンス
return NotFound(new { Message = Resources.E_PATIENT_NOT_FOUND });

// 例外メッセージ
throw new InvalidOperationException(Resources.E_TENANT_ID_MISSING);

// ログ
_logger.LogError(ex, Resources.LOG_UNEXPECTED_ERROR);
```

**3. やってはいけないこと**

```csharp
// NG: 文字列リテラルを直接記述する
return BadRequest("ファイルが選択されていないか、空です。");
throw new Exception("テナントIDが不明です。");
_logger.LogError(ex, "予期せぬエラーが発生しました。");
```

### 開発フロー

1. DevContainer を VS Code で開く（`Remote-Containers: Reopen in Container`）
2. コンテナ起動後、ターミナルで確認：`dotnet --version`（10.x.x が表示されれば OK）
3. コード変更 → `dotnet watch run` が自動再起動 → Swagger UI で動作確認
4. テスト実行：`dotnet test` または VS Code テストエクスプローラー
