# API設計

本章では、カルテドメインサービスが公開する REST API の設計規約・エンドポイント命名規則・リクエスト/レスポンス形式・バージョン管理方式を定義する。新規 API を追加する際は必ず本章に準拠すること。

---

## API 設計原則

### RESTful 設計の基本方針

カルテドメインサービスのすべての API は RESTful 設計に準拠する。

- **リソース指向**: URL はリソース（名詞）を表現し、動詞は HTTP メソッドで表す
- **HTTP メソッドの使い分け**

| HTTP メソッド | 用途 | 冪等性 |
| --- | --- | --- |
| `GET` | リソースの取得（副作用なし） | あり |
| `POST` | リソースの作成・検索（患者 ID を body に含める場合） | なし |
| `PUT` | リソースの完全更新 | あり |
| `PATCH` | リソースの部分更新 | あり |
| `DELETE` | リソースの削除 | あり |

- **単一責任**: 1 つのエンドポイントで 1 種類の操作のみ行う。複数リソースをまたぐ集約はBFF 側で実施する

### 個人情報のプライバシー保護規約

**個人情報は URL パスおよびクエリパラメーターに含めてはならない。必ずリクエスト Body（POST）で渡す。**

理由: URL はサーバーアクセスログ・ブラウザ履歴・プロキシキャッシュ等に残るため、個人情報が URL に含まれると情報漏洩リスクがある。

個人情報に該当する項目の例:

| 項目 | 例 |
| --- | --- |
| 患者 ID | `P0001` |
| 氏名 | `山田太郎` |
| 生年月日 | `1980-04-01` |
| 住所 | `東京都渋谷区...` |
| 電話番号 | `090-XXXX-XXXX` |

```csharp
// NG: 患者IDをURLパスやクエリパラメーターに含める
[HttpGet("patients/{patientId}/chief-complaints")]         // 禁止
[HttpGet("patients/chief-complaints?patientId=P0001")]     // 禁止

// OK: 患者IDをPOSTのBodyに含める
[HttpPost("patients/chief-complaints")]
public async Task<IActionResult> GetChiefComplaint([FromBody] ChiefComplaintRequest request)
// request.PatientId で受け取る
```

## URL 設計規約

### エンドポイントの命名規則

```
/api/v{バージョン番号}/{業務ドメイン}/{リソース}
```

| 要素 | 規則 | 例 |
| --- | --- | --- |
| プレフィックス | 常に `/api` で始める | `/api/...` |
| バージョン | `v1`・`v2` 形式。URLパスバージョニングを採用 | `/api/v1/...` |
| 業務ドメイン | kebab-case・複数形 | `clinical-entries`, `masters` |
| リソース | kebab-case・複数形 | `chief-complaints`, `vital-infos` |

### エンドポイント例

```
GET    /api/v1/masters/blood-types          # 血液型マスタ一覧取得
POST   /api/v1/clinical-entries/chief-complaints          # 主訴・所見の取得（患者IDをbodyに含む）
POST   /api/v1/clinical-entries/chief-complaints/create   # 主訴・所見の登録
PUT    /api/v1/clinical-entries/chief-complaints/{id}     # 主訴・所見の更新
DELETE /api/v1/clinical-entries/chief-complaints/{id}     # 主訴・所見の削除
```

## リクエスト/レスポンス形式

### リクエスト形式

- Content-Type: `application/json`
- 文字コード: UTF-8
- 必須ヘッダー:

| ヘッダー名 | 必須 | 説明 |
| --- | --- | --- |
| `X-Tenant-ID` | 必須 | テナント識別子。TenantMiddleware が検証する |
| `X-Trace-ID` | 必須 | BFF が発行するトレース ID（UUID v4 等）。TraceIdMiddleware が取り出しログ・エラーレスポンスに付与する |
| `Content-Type` | Body ありの場合必須 | `application/json` |
| `Authorization` | 将来必須 | JWT Bearer トークン（現在はサイドカーで検証済みのため不要） |

### リクエスト Body の設計ルール

```csharp
// Models/ 配下に配置するリクエスト型の例
public record ChiefComplaintRequest(
    string PatientId      // 患者ID（Body で渡す・URLパス禁止）
);

public record CreateChiefComplaintRequest(
    string PatientId,
    string ChiefComplaint,
    string? Findings      // nullable は ? で明示
);
```

- `record` 型を使用する（イミュータブル・簡潔）
- プロパティ名は PascalCase
- nullable フィールドは `?` を付ける
- バリデーションアノテーション（`[Required]`・`[MaxLength]` 等）を付与する

### レスポンス形式

#### 正常レスポンス

```json
// GET / POST（取得系）: 単一リソース
{
  "patientId": "P0001",
  "chiefComplaint": "頭痛・発熱",
  "findings": "体温38.5度"
}

// GET（一覧系）: 配列
[
  { "id": "A", "name": "A型" },
  { "id": "B", "name": "B型" }
]

// POST（作成系）: 作成したリソースを返す。HTTP 201 Created
{
  "id": "newly-created-id",
  ...
}

// DELETE: HTTP 204 No Content（Body なし）
```

#### エラーレスポンス

全エラーは `ExceptionMiddleware` が RFC 9457（Problem Details for HTTP APIs）準拠の統一フォーマットで返却する（詳細は `06.エラーハンドリングとログ.md` 参照）。

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `type` | string | MUST | エラー種別 URI（`/problems/{種別}`） |
| `title` | string | SHOULD | エラー種別の短い説明 |
| `status` | int | SHOULD | HTTP ステータスコード |
| `detail` | string | OPT | エラー詳細（本番では省略） |
| `instance` | string | OPT | エラーが発生したリクエスト URI |
| `traceId` | string | MUST | 1 BFF リクエストごとに発行するトレース ID。障害調査に使用する |
| `errors` | array | 4xx 時 MUST / 5xx 時 OPT | フィールド別エラー詳細（下表） |

`errors` 配列の各要素:

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `field` | string \| null | エラーが発生したフィールド名（全体エラーの場合は `null`） |
| `code` | string | エラーコード（`REQUIRED`・`INVALID_FORMAT` 等） |
| `message` | string | エラーの詳細メッセージ |

**バリデーションエラー（400）の例**:

```json
{
  "type": "/problems/validation-error",
  "title": "不正なリクエストです。",
  "status": 400,
  "detail": "入力内容に不備があります。各項目の詳細を確認してください。",
  "instance": "/api/v1/clinical-entry/vital-info",
  "traceId": "2ab1312c-aec2-4de8-a9d0-6841715ffe80",
  "errors": [
    {
      "field": "bloodPressure",
      "code": "INVALID_FORMAT",
      "message": "血圧は「収縮期/拡張期」の形式で入力してください。"
    },
    {
      "field": "bloodType",
      "code": "REQUIRED",
      "message": "血液型は必須です。"
    }
  ]
}
```

**サーバーエラー（500）の例**（`errors` は省略）:

```json
{
  "type": "/problems/internal-error",
  "title": "サーバーエラーが発生しました。管理者に連絡してください。",
  "status": 500,
  "instance": "/api/v1/clinical-entry/chief-complaints",
  "traceId": "2ab1312c-aec2-4de8-a9d0-6841715ffe80"
}
```

### HTTP ステータスコードの使い分け

| ステータス | 返却タイミング |
| --- | --- |
| `200 OK` | GET・POST（取得系）の正常応答 |
| `201 Created` | POST（作成系）の正常応答。`Location` ヘッダーにリソースURIを付与 |
| `204 No Content` | DELETE の正常応答 |
| `400 Bad Request` | バリデーションエラー・不正なリクエスト |
| `401 Unauthorized` | 認証エラー（JWT 無効等） |
| `403 Forbidden` | 認可エラー（権限不足） |
| `404 Not Found` | 対象リソースが存在しない |
| `500 Internal Server Error` | 予期しないサーバー内部エラー |

## Controller の実装規約

### 基本構造

```csharp
[ApiController]
[Route("api/v1/[controller]")]          // ルートはクラス名から自動生成
public class ClinicalEntryController : ControllerBase
{
    private readonly ClinicalEntryService _service;

    public ClinicalEntryController(ClinicalEntryService service)
    {
        _service = service;
    }

    /// <summary>主訴・所見を取得する</summary>
    [HttpPost("chief-complaints")]
    [ProducesResponseType(typeof(ChiefComplaint), StatusCodes.Status200OK)]
    [ProducesResponseType(StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetChiefComplaint([FromBody] GetChiefComplaintRequest request)
    {
        var result = await _service.GetChiefComplaintAsync(request.PatientId);
        if (result == null) return NotFound();
        return Ok(result);
    }
}
```

#### Controller 実装の禁止事項

- ビジネスロジックを Controller に書かない（Service に委譲する）
- DB 操作を Controller に書かない（Repository に委譲する）

### Swagger（OpenAPI）アノテーション

各エンドポイントには `[ProducesResponseType]` を付与し、Swagger UI に型情報を表示する。

```csharp
[ProducesResponseType(typeof(ChiefComplaint), StatusCodes.Status200OK)]
[ProducesResponseType(StatusCodes.Status404NotFound)]
[ProducesResponseType(StatusCodes.Status400BadRequest)]
```

## バージョン管理方式

### バージョニング方針

- URLパスバージョニング（`/api/v1/`・`/api/v2/`）を採用
- **後方互換性を持たない変更（Breaking Change）が発生した場合のみ** バージョンを上げる
- 後方互換性のある変更（フィールド追加等）はバージョンを上げない

### Breaking Change の定義

以下の変更は Breaking Change として新バージョンを発行する：

- 既存フィールドの削除・リネーム
- 既存フィールドの型変更
- 既存エンドポイントの URL 変更
- 必須パラメーターの追加

### 旧バージョンのサポート方針

旧バージョンの API は新バージョンリリース後も一定期間サポートし、利用状況を踏まえて廃止時期を決定する。廃止予告は `Deprecated` レスポンスヘッダーで通知する。

```
Deprecated: true
Sunset: 2027-04-01
```

## Swagger UI の設定

`Program.cs` における Swagger 設定。開発環境（`ASPNETCORE_ENVIRONMENT=Development`）でのみ有効化する。

```csharp
// Program.cs
if (app.Environment.IsDevelopment())
{
    app.UseSwagger();
    app.UseSwaggerUI();
}
```

アクセス URL: `http://localhost:7121/swagger`

`X-Tenant-ID` ヘッダーの入力方法は `03.開発環境.md` のデバッグ設定を参照。
