# テスト設計

本章では、カルテドメインサービスのテスト方針・テスト種別ごとの対象と手法・テストコードの実装パターン・CI/CD 連携を定義する。

---

## テスト方針

### テスト対象と種別

| 種別 | 対象 | 目的 | ツール |
| --- | --- | --- | --- |
| 単体テスト | Controller / Service / Repository の個別モジュール | モジュール単位の機能検証・例外・境界値確認 | NUnit 4.x + Moq |
| 結合テスト | DB 連携・複数コンポーネントの連携 | モジュール間の正しい連携とデータ整合性の確認 | NUnit + 実 DB |
| API テスト | API エンドポイント | 正常系・異常系・境界値ケースの検証 | Swagger UI・Postman |

### テストプロジェクトの配置

```
backend/
  KarteDomainService.sln
  KarteDomainService/              ← 本体プロジェクト
  KarteDomainService.Tests/        ← テストプロジェクト
    Features/
      {業務グループ名}/
        {業務名}ControllerTests.cs
        {業務名}ServiceTests.cs
        {業務名}RepositoryTests.cs
    KarteDomainService.Tests.csproj
```

### Controller のテスト

Controller は Service をモック化し、HTTP ステータスコードと返却値の正しさを検証する。`TenantService` は `HttpContext.RequestServices` 経由で取得されるため、`IServiceProvider` をモック化して注入する。

```csharp
[TestFixture]
public class ClinicalEntryControllerTests
{
    private Mock<ClinicalEntryService> _serviceMock;
    private ClinicalEntryController _controller;

    [SetUp]
    public void SetUp()
    {
        _serviceMock = new Mock<ClinicalEntryService>();

        // TenantService は RequestServices 経由で取得されるためモック化
        var tenantServiceMock = new Mock<ITenantService>();
        tenantServiceMock.Setup(t => t.TenantId).Returns("tenant_test");

        var serviceProviderMock = new Mock<IServiceProvider>();
        serviceProviderMock
            .Setup(sp => sp.GetService(typeof(ITenantService)))
            .Returns(tenantServiceMock.Object);

        var httpContext = new DefaultHttpContext
        {
            RequestServices = serviceProviderMock.Object
        };

        _controller = new ClinicalEntryController(_serviceMock.Object)
        {
            ControllerContext = new ControllerContext { HttpContext = httpContext }
        };
    }

    [Test]
    public async Task GetChiefComplaint_存在する場合_200OKを返す()
    {
        // Arrange
        var expected = new TChiefComplaints { PatientId = "P001", Text = "頭痛" };
        _serviceMock.Setup(s => s.GetChiefComplaintAsync("P001")).ReturnsAsync(expected);

        // Act
        var result = await _controller.GetChiefComplaint(new GetChiefComplaintRequest("P001"));

        // Assert
        var okResult = result as OkObjectResult;
        Assert.That(okResult, Is.Not.Null);
        Assert.That(okResult!.StatusCode, Is.EqualTo(200));
        Assert.That(okResult.Value, Is.EqualTo(expected));
    }

    [Test]
    public async Task GetChiefComplaint_存在しない場合_404NotFoundを返す()
    {
        _serviceMock.Setup(s => s.GetChiefComplaintAsync("P999")).ReturnsAsync((TChiefComplaints?)null);

        var result = await _controller.GetChiefComplaint(new GetChiefComplaintRequest("P999"));

        Assert.That(result, Is.InstanceOf<NotFoundResult>());
    }
}
```

### Service のテスト

Service は Repository をモック化し、バリデーション・ログ出力・業務ロジックの正しさを検証する。

```csharp
[TestFixture]
public class ClinicalEntryServiceTests
{
    private Mock<ClinicalEntryRepository> _repositoryMock;
    private Mock<ILogger<ClinicalEntryService>> _loggerMock;
    private ClinicalEntryService _service;

    [SetUp]
    public void SetUp()
    {
        _repositoryMock = new Mock<ClinicalEntryRepository>();
        _loggerMock = new Mock<ILogger<ClinicalEntryService>>();
        _service = new ClinicalEntryService(_repositoryMock.Object, _loggerMock.Object);
    }

    [Test]
    public async Task GetChiefComplaintAsync_正常系_Repositoryの結果を返す()
    {
        var expected = new TChiefComplaints { PatientId = "P001", Text = "頭痛" };
        _repositoryMock.Setup(r => r.GetChiefComplaintAsync("P001")).ReturnsAsync(expected);

        var result = await _service.GetChiefComplaintAsync("P001");

        Assert.That(result, Is.EqualTo(expected));
    }

    [Test]
    public void GetChiefComplaintAsync_患者ID空文字_ArgumentExceptionを投げる()
    {
        // Service のバリデーションが ArgumentException を throw することを確認
        Assert.ThrowsAsync<ArgumentException>(
            () => _service.GetChiefComplaintAsync(""));
    }
}
```

### AAA パターン

テストコードは **Arrange / Act / Assert** の 3 ステップで記述する。

```csharp
[Test]
public async Task テストケース名_前提条件_期待する結果()
{
    // Arrange: テストの前提条件を設定
    var expected = ...;
    _mock.Setup(...).Returns(...);

    // Act: テスト対象メソッドを実行
    var result = await _target.MethodAsync(...);

    // Assert: 結果を検証
    Assert.That(result, Is.EqualTo(expected));
}
```

### テストケース名の命名規則

```
{メソッド名}_{前提条件}_{期待する結果}
```

例: `GetChiefComplaintAsync_患者ID空文字_ArgumentExceptionを投げる`

## テストの実行方法

### コマンドラインで実行

```bash
# DevContainer 内で実行
cd /workspaces/harz/poc/backend

# 全テスト実行
dotnet test KarteDomainService.Tests/KarteDomainService.Tests.csproj

# 詳細出力付き
dotnet test KarteDomainService.Tests/KarteDomainService.Tests.csproj --verbosity normal

# カバレッジ計測（coverlet が必要）
dotnet test --collect:"XPlat Code Coverage"
```

### VS Code テストエクスプローラーで実行

DevContainer に `formulahendry.dotnet-test-explorer` 拡張機能を追加すると、VS Code の Testing パネルからテストを実行できる。

## CI/CD 連携

全テストは CI パイプラインに組み込み、テスト失敗時はリリース不可とする。テスト結果はログとして保持し、障害解析・リリース判断に活用する。

---

## テストカバレッジの方針

- Controller: 全エンドポイントの正常系・異常系（404・400 等）を網羅する
- Service: バリデーション条件（空文字・null・境界値）を網羅する
- Repository: 単体テストはモック化。DB との整合性は結合テストで確認する
