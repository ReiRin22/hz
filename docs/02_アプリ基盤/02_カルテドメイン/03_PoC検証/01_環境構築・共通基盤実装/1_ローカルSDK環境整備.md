# 技術検証報告書：.NET 10 および PostgreSQL 接続基盤の構築

## 1. 検証の目的

次期カルテドメインサービスの開発基盤として、最新の **.NET 10** および **PostgreSQL** を採用する。本検証では、ローカル開発環境における実行ランタイムの正常性と、データベース（DB）への接続・ビルドが安定して行える「開発基盤の最小構成」を確立することを目的とした。

## 2. 実施内容と結果

### ① APIサーバーの疎通確認（ランタイム検証）

* **内容**: `dotnet new webapi` コマンドにて作成した初期プロジェクトを実行。
* **結果**:
* `weatherforecast` エンドポイントに対し正常にリクエスト・レスポンス（JSON）が行われることを確認。
* ルートパス（/）へのアクセスで「404 Not Found」が発生したものの、これはルーティング設定による仕様であり、**.NET 10 ランタイム自体は正常に稼働**していると判断した。



### ② PostgreSQL接続ライブラリの導入

* **内容**: ORM（Entity Framework Core）を介して PostgreSQL を操作するため、以下の NuGet パッケージを導入。
* `Npgsql.EntityFrameworkCore.PostgreSQL`


* **結果**: 依存関係の競合なく、正常にプロジェクトへインストールを完了。

### ③ DB接続情報の定義とインジェクション設定

* **内容**:
* `appsettings.Development.json` にローカルDB（Host: localhost / Port: 5432）への接続文字列を定義。
* `Program.cs` において、`AddDbContext` メソッドを使用し、アプリケーション起動時にDB接続設定をサービスコンテナへ登録。


* **結果**: アプリケーション設定値から正常に接続情報が読み取れる構成となった。

### ④ DBアクセス窓口（DbContext）の試作

* **内容**: `Data` フォルダを作成し、プログラムとDBを仲介する `ApplicationDbContext` クラスを定義。
* **結果**: `dotnet build` を実行し、**「ビルドに成功しました」** の出力を確認。コードレベルでの「配線」に問題がないことを検証した。
