# ADR-1: バージョン管理にキャレット記法（`^X.0.0`）を採用する

* **ステータス**: Accepted
* **決定日**: 2026-05-21
* **関連設計書**: [開発環境規約.md](../開発環境規約.md) §2
* **関連 ADR**: なし

## 背景（Context）

本プロジェクトは複数のライブラリ（React、Next.js、Axios 等）を使用する。
メジャーアップデートは破壊的変更を含む可能性があるため慎重な判断が必要だが、
マイナー・パッチ更新は後方互換性があり、放置するとセキュリティリスクになる。

## 検討した選択肢（Options）

### 案A: バージョン完全固定（`19.0.0` 形式）
* メリット: 環境の完全な再現性。サプライチェーン攻撃への耐性
* デメリット: セキュリティパッチを手動で全ライブラリに適用する運用コストが高い。更新漏れによるリスク

### 案B: キャレット記法（`^19.0.0` 形式）— 採用
* メリット: メジャーバージョンを固定しつつ、マイナー・パッチ更新は `npm update` で自動化。セキュリティとメンテナンス性のバランスが取れる
* デメリット: `package-lock.json` がなければ環境差異が生まれる可能性がある（lock ファイルで管理することで解決）

### 案C: チルダ記法（`~19.0.0` 形式）
* メリット: パッチ更新のみ自動。より保守的
* デメリット: バグ修正を含むマイナー更新を手動適用しなければならず、案Aと同様の運用コスト

## 決定（Decision）

案Bのキャレット記法（`^X.0.0`）を採用する。
`package-lock.json` を Git 管理下に置くことで環境の再現性を確保しつつ、`npm update` によるマイナー・パッチの自動更新でセキュリティパッチの適用漏れを防ぐ。
メジャーバージョンアップは基盤チームが事前検証してから実施することで、破壊的変更のリスクをコントロールする。

**バージョン種別ごとの根拠**:

| バージョン種別 | 固定/自動 | 理由 |
|---|---|---|
| メジャー | 固定 | 破壊的変更により既存実装が動作しなくなる可能性があるため、慎重な検証が必要 |
| マイナー | 自動更新 | 後方互換性があり、新機能追加・バグ修正の恩恵を受ける |
| パッチ | 自動更新 | 適用しないことがセキュリティリスクとなる |

## 影響（Consequences）

* `npm update` 実行時にマイナー・パッチが自動更新されるため、ビルド後のテスト実行が重要
* メジャーバージョンアップは必ず基盤チームを経由する（アプリチームの独断変更は禁止）
* 見直しトリガー: ライブラリのマイナー更新で重大な破壊的変更が発生した場合（稀だが発生しうる）
