## 1. ファイル構成

```
front_bff_shared/
└── i18n/
    ├── index.ts          # エントリーポイント（型エクスポート・messages オブジェクト）
    ├── labels.json       # 共通ラベル（患者ID・診療科等）
    ├── validation.json   # バリデーションエラーメッセージ
    └── errors.json       # ビジネスエラーメッセージ
```

| ファイル | 対象メッセージ | 共有理由 |
|---|---|---|
| `index.ts` | エントリーポイント | `messages` オブジェクトを1箇所でエクスポート |
| `labels.json` | 共通ラベル（"患者ID", "診療科"等） | 用語の統一 |
| `validation.json` | バリデーションエラーメッセージ | フロントエンドとBFFで同一メッセージを表示 |
| `errors.json` | ビジネスエラーメッセージ | BFFで発生したエラーをフロントエンドに通知 |

## 2. index.ts 公開 I/F

**ファイル**: `front_bff_shared/i18n/index.ts`

**インポートパス**: `import { messages } from '@/front_bff_shared/i18n'`

```typescript
/**
 * front_bff_shared 共通メッセージリソースのエントリーポイント。
 *
 * @remarks
 * 基盤チームが作成・管理する。JSON ファイルの追加・削除があった場合のみ修正する。
 * アプリチームは messages オブジェクト経由でメッセージを参照すること。
 *
 * @example
 * import { messages } from '@/front_bff_shared/i18n';
 * z.string().min(2, messages.validation.nameMinLength);
 */

import labels from './labels.json';
import validation from './validation.json';
import errors from './errors.json';

// JSONから型を推論（手書き型定義は不要）
export type LabelMessages = typeof labels;
export type ValidationMessages = typeof validation;
export type ErrorMessages = typeof errors;

export const i18nConfig = {
  defaultLocale: 'ja' as const,
  locales: ['ja'] as const,
} as const;

export type Locale = typeof i18nConfig.locales[number];

/** 統合されたメッセージオブジェクト（利用側はここからimport） */
export const messages = {
  labels,
  validation,
  errors,
} as const;
```

**公開エクスポート一覧**:

| エクスポート名 | 型 | 用途 |
|---|---|---|
| `messages` | `{ labels: LabelMessages; validation: ValidationMessages; errors: ErrorMessages }` | メッセージ参照の統一エントリーポイント |
| `messages.labels` | `LabelMessages` | 共通ラベル参照 |
| `messages.validation` | `ValidationMessages` | Zodスキーマのエラーメッセージ参照 |
| `messages.errors` | `ErrorMessages` | BFFビジネスエラーメッセージ参照 |
| `i18nConfig` | `{ defaultLocale: 'ja'; locales: readonly ['ja'] }` | ロケール設定 |
| `LabelMessages` | 型 | JSONから推論された型（手書き不要） |
| `ValidationMessages` | 型 | JSONから推論された型（手書き不要） |
| `ErrorMessages` | 型 | JSONから推論された型（手書き不要） |

## 4. 活用パターン

### 4-1. Zodスキーマでのメッセージ参照

```typescript
import { z } from 'zod';
import { messages } from '@/front_bff_shared/i18n';

export const userUpdateSchema = z.object({
  name: z.string().min(2, messages.validation.nameMinLength),
  email: z.string().email(messages.validation.emailInvalid),
});
```

### 4-2. BFFビジネスエラーメッセージ参照

```typescript
import { messages } from '@/front_bff_shared/i18n';

if (await this.userService.isDuplicate(data.patientId)) {
  throw new BadRequestException(messages.errors.patientIdDuplicate);
}
```

## 5. メッセージキーの追加手順

1. 対応するJSONファイル（`labels.json` / `validation.json` / `errors.json`）にキーと文字列を追加する
2. `index.ts` の修正は不要（JSONから型が自動推論される）
3. TypeScriptの補完でキー名が即座に反映される
