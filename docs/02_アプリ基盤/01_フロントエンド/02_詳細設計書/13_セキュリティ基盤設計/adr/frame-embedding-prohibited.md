# ADR-4: iframe 埋め込みを完全禁止する

* **ステータス**: Accepted
* **決定日**: 2026-05-22
* **関連設計書**: [セキュリティミドルウェア設計.md](../セキュリティミドルウェア設計.md) §3, §4
* **関連 ADR**: なし

## 背景

電子カルテ画面が悪意のあるサイト上の iframe 内に埋め込まれた場合、Clickjacking 攻撃（透明な iframe を重ねてユーザーのクリックを誘導する攻撃）により、医師・看護師が意図しない操作（処方変更・患者情報の改ざん等）を強制される可能性がある。

また、電子カルテ自身が外部ドメインの iframe を読み込む場合、フィッシングや XSS の経路となり得る。電子カルテのコンテキスト下で表示される外部コンテンツはユーザーから本物の画面と区別がつかないため、リスクが高い。

iframe を完全禁止するか、特定オリジンに限定して許可するかを決める必要がある。

## 検討した選択肢

### 案A: `X-Frame-Options: SAMEORIGIN`、CSP `frame-ancestors 'self'`（同一オリジンのみ許可）
* **メリット**: 自身のドメイン内で iframe を使用する余地を残す。
* **デメリット**: 電子カルテに iframe で埋め込む正当な業務要件が現時点で存在しない。許可する余地を残すこと自体が攻撃面となる（自身のドメイン内で XSS が成立すれば iframe 経由で操作される）。

### 案B: `X-Frame-Options: DENY`、CSP `frame-ancestors 'none'`、CSP `frame-src 'none'`（完全禁止）
* **メリット**: Clickjacking とフィッシングのリスクを最小化。設定がシンプル。攻撃面が最小。
* **デメリット**: 将来 iframe 利用要件が発生した場合、設計書・ADR 更新が必要。

### 案C: 特定の信頼ドメインのみ許可（ホワイトリスト）
* **メリット**: 必要に応じて柔軟に対応可能。
* **デメリット**: 現時点で該当ドメインが存在しない。早期から運用が複雑化する。

## 決定

**案B（完全禁止）を採用する**。

設定するヘッダー:

| ヘッダー | 設定値 | 役割 |
|---|---|---|
| `X-Frame-Options` | `DENY` | レガシーブラウザ向けの埋め込み禁止 |
| `Content-Security-Policy: frame-ancestors` | `'none'` | 自身が他サイトの iframe に埋め込まれることを禁止（X-Frame-Options の上位互換） |
| `Content-Security-Policy: frame-src` | `'none'` | 自身が外部 iframe を読み込むことを禁止（フィッシング対策） |

helmet の `frameguard` オプションで `X-Frame-Options: DENY` を、CSP 設定で `frame-ancestors` / `frame-src` を `'none'` に設定する。

## 影響

### 正の影響
* Clickjacking 攻撃のリスクを物理的に排除。
* 電子カルテ自身が外部 iframe を読み込まないことで、フィッシング・外部スクリプト混入の経路を1つ減らせる。
* セキュリティ監査で「フレーム埋め込みは完全禁止している」と説明可能。

### 負の影響
* 将来、業務要件で iframe が必要になった場合（外部ドキュメントビューア・部門システム連携 UI 等）は、本 ADR の見直しと CSP 設定変更が必要。
* 開発時に iframe を使ったプレビュー機能等を入れる場合、開発環境設定の差分管理が必要。

### 見直しトリガー
* 業務要件で外部システムを iframe 経由で表示する必要が確定した場合（ホワイトリスト方式への切替を検討）。
* 部門連携サービス（検査・放射線 PACS 等）の UI を iframe で組み込む要件が発生した場合。
