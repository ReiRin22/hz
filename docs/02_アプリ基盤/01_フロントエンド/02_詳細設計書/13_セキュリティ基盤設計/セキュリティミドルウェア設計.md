## 1. 役割

| 防御対象 | 設定内容 |
|---|---|
| **XSS（補助）** | CSP `script-src`, `connect-src`, `default-src`、HttpOnly Cookie によるトークン保護 |
| **CSRF（補助）** | helmet セキュリティヘッダー、CORS オリジン制限、SameSite Cookie |
| **Clickjacking** | `X-Frame-Options: DENY`、CSP `frame-ancestors 'none'` |

## 2. 公開 I/F: `setupSecurity(app)`

### 2.1 配置と公開対象

| 項目 | 内容 |
|---|---|
| ファイル | `bff/src/shared/plugins/security.middleware.ts` |
| 公開対象 | ❌ 基盤チームが BFF 起動時に配線（アプリ実装者は呼び出すのみ） |

### 2.2 型シグネチャ

```typescript
import type { NestExpressApplication } from '@nestjs/platform-express';

/**
 * BFF 起動時に呼び出し、セキュリティミドルウェアを一括設定する。
 *
 * 設定内容:
 * - helmet によるセキュリティヘッダー（CSP、X-Frame-Options、X-Content-Type-Options 等）
 * - CORS 設定（オリジン制限・許可メソッド・許可ヘッダー）
 * - 認証セッション Cookie の HttpOnly + Secure + SameSite=Strict 強制
 *
 * @param app - NestJS の `NestExpressApplication` インスタンス
 *
 * @throws Error 環境変数 `FRONTEND_URL` が未設定の場合（CORS オリジン未確定はセキュリティリスクのため起動を中断する）
 *
 * @remarks
 * - `main.ts` の `app.listen()` 前に1度だけ呼び出すこと（同一 `app` への二重呼び出し禁止）
 * - 環境変数 `FRONTEND_URL` で許可オリジンを動的制御する
 * - 個別エンドポイントで CORS 設定を上書きしてはならない
 * - JWT クイック検証は本関数のスコープ外（認証ガードで別ミドルウェアとして実装。詳細は認証認可サービス方式設計書を参照）
 *
 * @example
 * ```typescript
 * import { NestFactory } from '@nestjs/core';
 * import { setupSecurity } from '@/shared/plugins/security.middleware';
 *
 * async function bootstrap() {
 *   const app = await NestFactory.create<NestExpressApplication>(AppModule);
 *   setupSecurity(app);
 *   await app.listen(3000);
 * }
 * ```
 */
export function setupSecurity(app: NestExpressApplication): void;
```

### 2.3 設定詳細

#### CORS

| 項目 | 設定値 |
|---|---|
| `origin` | 環境変数 `FRONTEND_URL` で指定されたドメインのみ許可 |
| `credentials` | `true`（Cookie 送信を許可） |
| `methods` | `GET, POST, PUT, DELETE, PATCH` のみ許可 |
| `allowedHeaders` | `Content-Type, Authorization, X-Tenant-Id, X-CSRF-Token` |

#### HttpOnly Cookie

認証セッション/RT を格納する Cookie の標準属性:

```typescript
res.cookie('session_token', token, {
  httpOnly: true,        // JavaScriptからアクセス不可（XSS被害時のトークン窃取防止）
  secure: true,          // HTTPS通信のみ
  sameSite: 'strict',    // クロスサイトからのCookie送信制限（CSRF補助）
  maxAge: 3600000        // 有効期限（ミリ秒）
});
```

> 根拠: [adr/httponly-cookie.md](adr/httponly-cookie.md)

| Cookie 用途 | httpOnly | secure | sameSite | 配置対象 |
|---|---|---|---|---|
| 認証セッション | ✅ true | ✅ true | strict | 認証 API レスポンス |
| リフレッシュトークン (RT) | ✅ true | ✅ true | strict | 認証 API レスポンス |
| CSRFトークン (XSRF-TOKEN) | ❌ false | ✅ true | strict | `/api/csrf-token` レスポンス |

> CSRFトークン Cookie のみ `httpOnly: false`（フロントが JavaScript から読み取る必要があるため）。詳細は [CSRF対策設計.md](CSRF対策設計.md) §2.3。

## 3. CSP（Content Security Policy）

### 3.1 防御対象

| 防御対象 | 関連ディレクティブ |
|---------|-----------------|
| **XSS** | `script-src`, `connect-src`, `default-src` |
| **Clickjacking** | `frame-ancestors` |

### 3.2 初期ディレクティブ

| ディレクティブ | 初期設定値 | 説明 |
|--------------|----------|------|
| `defaultSrc` | `'self'` | デフォルトは自サイトのみ許可 |
| `scriptSrc` | `'self'` | スクリプトは自サイトのみ |
| `styleSrc` | `'self'`, `'unsafe-inline'` | スタイルは自サイト + インラインスタイル許可（Tailwind 対応） |
| `imgSrc` | `'self'`, `data:`, `https:` | 画像は自サイト + data URI + HTTPS全般 |
| `connectSrc` | `'self'` | API 接続は自サイトのみ（外部サービス確定後に追加） |
| `frameSrc` | `'none'` | 自身が外部 iframe を読み込むことを禁止（XSS 経由のフィッシング対策） |
| `frameAncestors` | `'none'` | 自身が他サイトの iframe 内に埋め込まれることを禁止（Clickjacking 対策） |

> 根拠: `styleSrc 'unsafe-inline'` の Tailwind トレードオフは [adr/csp-style-unsafe-inline.md](adr/csp-style-unsafe-inline.md)、`frameAncestors 'none'` は [adr/frame-embedding-prohibited.md](adr/frame-embedding-prohibited.md)

### 3.3 詳細化が必要なディレクティブ（残件）

外部サービスのドメイン確定後、基盤チームがホワイトリスト方式で追加する。

| ディレクティブ | 目的 | 追加候補ドメイン |
|--------------|------|----------------|
| `script-src` | 実行を許可するスクリプトドメイン | 認証基盤、Sentry |
| `connect-src` | API・WebSocket 接続先 | 業務 API、Socket.io、Sentry |
| `img-src` | 画像読み込み元 | CDN、医療画像ストレージ |

## 4. Clickjacking 対策

| ヘッダー | 設定値 | 説明 |
|---------|-------|------|
| `X-Frame-Options` | `DENY` | フレーム内での表示を完全禁止 |
| `CSP frame-ancestors` | `'none'` | CSP でフレーム表示を禁止（X-Frame-Options の上位互換） |

> 設定方法: helmet の `frameguard` オプションで自動設定。
> 根拠: [adr/frame-embedding-prohibited.md](adr/frame-embedding-prohibited.md)
