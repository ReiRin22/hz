## 2. モノレポ構成

```
harz/product/
├── frontend/          # Next.js アプリケーション本体
├── bff/               # フロントエンド専用のバックエンド
└── front_bff_shared/  # 共有型定義・スキーマ（シンボリックリンク）
```

| ディレクトリ | 責務 | 主な格納内容 |
|---|---|---|
| `frontend/` | UI 層、Presentation 層、フロントエンド固有の状態管理 | React コンポーネント、カスタム Hooks、Zustand stores、Tailwind 設定 |
| `bff/` | API 集約（Aggregator）とデータ整形（Mapping） | NestJS Controllers/Services、バックエンド API 通信 Client |
| `front_bff_shared/` | フロントエンドと BFF で共有する型定義・スキーマ・メッセージ | Request/Response 型、Zod スキーマ、i18n リソース |

> 階層構造の詳細は [00.ディレクトリ構成.md](../00.ディレクトリ構成.md) を参照。

### 2.1 front_bff_shared の役割

`front_bff_shared/` はフロントエンドと BFF 間の API 契約を一元管理する **Single Source of Truth (SSOT)** として機能する。

| 共有対象 | 格納場所 | 説明 |
|---|---|---|
| **Request 型** | `front_bff_shared/features/[LV1]/[LV2]/[LV3]/types/requests/` | BFF が受け取るリクエストボディ・クエリパラメータの型 |
| **Response 型** | `front_bff_shared/features/[LV1]/[LV2]/[LV3]/types/responses/` | BFF が返却し FE が受け取るレスポンスデータの型（ViewModel） |
| **Zod スキーマ** | `front_bff_shared/features/[LV1]/[LV2]/[LV3]/schemas/` | FE 入力検証と BFF ガードロジックで共用するバリデーションルール |
| **i18n リソース** | `front_bff_shared/i18n/` | UI 文言・バリデーションメッセージ（JSON + 型推論） |

> 詳細仕様は [03.TypeScript型管理とスキーマ共有.md](../03.TypeScript型管理とスキーマ共有.md) を参照。
>
> 根拠: [adr/front-bff-shared-ssot.md](adr/front-bff-shared-ssot.md)

## 3. Next.js 16 活用方針

### 3.1 App Router の活用

| コンポーネント種別 | 活用方針 |
|---|---|
| Server Components | 初期データ取得・SEO 対策が必要な画面（患者一覧、ダッシュボード等） |
| Client Components | ユーザーインタラクションが必要な画面（診療記録入力、検査結果参照等） |
| Streaming SSR | 大量データの段階的レンダリングによる初期表示高速化 |

### 3.2 next.config.ts 設定方針

`frontend/next.config.ts` は基盤チームが配置・管理する。アプリ実装者は触らない。設定方針は以下の通り。

| 観点 | 方針 |
|---|---|
| 開発ビルド | Turbopack を有効化（高速 HMR） |
| 本番ビルド | Webpack 5（安定性優先）。> 根拠: [adr/build-tool-strategy.md](adr/build-tool-strategy.md) |
| React Strict Mode | 有効 |
| 画像最適化 | `next/image` ＋ `sharp`、`remotePatterns` で許可ホストを限定 |

### 3.3 マイグレーション方針

| 項目 | 方針 |
|---|---|
| Next.js 15 からの移行 | 不要（新規プロジェクトとして 16 から開始） |
| Next.js 17 以降へのアップグレード | 安定運用実績を確認してから検討 |

## 4. 技術ロードマップとライフサイクル管理

長期的な保守性を担保するため、採用技術のサポート期間（EOL）に基づいたアップデート方針を以下の通り定義する。

| 技術要素 | 採用バージョン | リリース開始日 | サポート終了（予定） | アップデート・メンテナンス方針 |
|---|---|---|---|---|
| **Node.js** | 24 LTS | 2025 年 4 月 | 2028 年 4 月 | LTS 終了に合わせ、次期 LTS（v26 等）への移行を計画的に実施 |
| **Next.js** | 16.x | 2025 年 10 月 | 未定（通常 1.5〜2 年） | メジャーリリースサイクルとセキュリティパッチ提供状況に応じて最新安定版への追随を検討 |
| **React** | 19.x | 2024 年 12 月 | 未定 | Next.js の推奨バージョンに準拠。破壊的変更は共通基盤チームで先行調査 |

メジャーアップデートの判断基準・運用は [フロントエンド・BFF共通基盤規約.md](フロントエンド・BFF共通基盤規約.md) §5 を参照。
