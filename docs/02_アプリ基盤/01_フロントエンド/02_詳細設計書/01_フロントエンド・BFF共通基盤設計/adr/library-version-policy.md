# ADR-6: ライブラリバージョンはメジャー固定・マイナー以下自動追随とする

* **ステータス**: Accepted
* **決定日**: 2026-04-27
* **関連設計書**: [技術スタック設計.md](../技術スタック設計.md) §1, [フロントエンド・BFF共通基盤規約.md](../フロントエンド・BFF共通基盤規約.md) §5
* **関連 ADR**: なし

## 背景

`package.json` のバージョン記法には以下の選択肢がある。

* 完全固定（`"axios": "1.13.2"`）
* キャレット記法（`"axios": "^1.13.2"`）: メジャー固定・マイナー以下を `npm install/update` 時に最新まで追随
* チルダ記法（`"axios": "~1.13.2"`）: マイナー固定・パッチのみ追随
* レンジ記法（`"axios": ">=1.13.0 <2.0.0"`）

医療システムでは：

* セキュリティパッチ（マイナー・パッチ）は速やかに取り込みたい
* 破壊的変更を含むメジャーアップデートは慎重にレビューしたい
* 設計書本体に毎パッチごとのバージョン更新を反映するのは現実的ではない

## 検討した選択肢

### 案A: 完全固定

* メリット: 依存の再現性が最も高い
* デメリット: セキュリティパッチが取り込まれず、`Dependabot` 等の手動 PR 対応コストが膨大

### 案B: キャレット記法（`^X.Y.Z`）

* メリット
  * メジャーは固定でき、破壊的変更は意図的なアップデート時のみ発生
  * `npm update` でマイナー・パッチを自動取り込み可能
  * `package-lock.json` で実値の再現性も担保
* デメリット
  * マイナーアップデートでもまれに非互換が発生する可能性（ライブラリの SemVer 違反）

### 案C: チルダ記法

* メリット: パッチのみ自動追随。安定性が高い
* デメリット: マイナーアップデート（新機能・パフォーマンス改善・非破壊バグ修正）の取り込みに毎回 PR が必要となり、メンテナンスコストが増大

## 決定

**案 B（キャレット記法 `^X.0.0`）を採用する。**

理由:

* メジャー固定により破壊的変更を防ぎつつ、マイナー以下のセキュリティパッチを自動取り込みできるバランスが良い
* `package-lock.json` で実値の再現性を担保しつつ、CI で `npm ci` を使って lock の整合性を確認できる
* 設計書本体ではメジャーバージョンのみ記載（例: `"16.x"`）し、実値は `package.json` に委譲することで、設計書のメンテナンス負荷を下げる

## 影響

* 設計書（[技術スタック設計.md](../技術スタック設計.md) §1）はメジャー表記（`"16.x"`）で統一
* `package.json` の依存追加は `^X.0.0` 形式で記載
* CI では `npm ci` を使って `package-lock.json` の lock 整合性を強制
* マイナーアップデートで非互換が発生した場合は、暫定で完全固定し、原因調査・パッチ適用後にキャレット記法へ戻す運用とする

### 見直しトリガー

* SemVer 違反のマイナーアップデートにより本番障害が発生し、原則的にチルダ記法へ移行する判断が必要になった場合
* セキュリティポリシーが変更され、より厳格な依存固定が求められた場合
