# リスト仮想化基盤設計

大規模リスト表示における仮想化基盤（react-virtuoso）の利用方針と配置を定義する。

## 1. 仮想化の動作原理

| 観点 | 内容 |
|---|---|
| メモリ管理 | 1万件規模のデータ全体は JavaScript ヒープに保持 |
| DOM 制御 | 表示領域内（数十行）のみ DOM 要素として描画 |
| 再利用（Recycle） | スクロール時に DOM 要素を再利用し描画コストを最小化 |

> 採用ライブラリ選定の根拠は [ADR-3](adr/react-virtuoso.md)

---

## 2. 公開 I/F

### 2.1 利用するモジュール

`react-virtuoso` パッケージから `Virtuoso` コンポーネントを直接利用する。基盤側でのラッパーは設けない（react-virtuoso の API 自体がシンプルなため）。

```ts
import { Virtuoso } from 'react-virtuoso';
```

### 2.2 必須プロパティ

| プロパティ | 型 | 役割 |
|---|---|---|
| `style` | `React.CSSProperties` | 高さ指定（必須）。例: `{ height: '600px' }` |
| `totalCount` | `number` | 全件数。データ配列の `length` を渡す |
| `itemContent` | `(index: number) => React.ReactNode` | インデックスに対応する行コンテンツを返す関数 |

### 2.3 オプショナルプロパティ

| プロパティ | 型 | 役割 |
|---|---|---|
| `initialItemCount` | `number` | SSR 時の初期描画件数。SSR と組み合わせる際にちらつき抑制 |
| `overscan` | `number` | 表示領域外で先読みする件数（既定値で十分なケースが多い） |
| `endReached` | `() => void` | 末尾到達時のコールバック（無限スクロール用） |

## 3. 配置

| ファイル種別 | 配置 |
|---|---|
| 仮想化リストの実装 | `frontend/src/features/<LV1>/<LV2>/<LV3>/components/organisms/{Name}List.tsx` |
| 行コンポーネント（複雑な場合） | `frontend/src/features/<LV1>/<LV2>/<LV3>/components/molecules/{Name}Row.tsx` |

仮想化リストは **業務コンポーネント層（Organisms）** に配置する。Atoms / Molecules には配置しない。

## 4. 標準実装パターン

### 4.1 基本実装

```tsx
"use client";

import { Virtuoso } from 'react-virtuoso';
import Image from 'next/image';
import { KarteResponse } from '@/front_bff_shared/types/response/karte.response.type';

export default function VirtualizedKarteList({ data }: { data: KarteResponse[] }) {
  if (!data || data.length === 0) {
    return (
      <div className="border rounded bg-white p-8 text-center text-gray-500">
        <p>表示するデータがありません</p>
      </div>
    );
  }

  return (
    <div className="border rounded bg-white">
      <Virtuoso
        style={{ height: '600px' }}
        totalCount={data.length}
        itemContent={(index) => (
          <div className="flex items-center p-3 border-b h-[80px]">
            <div className="w-[60px] h-[60px] relative mr-4 bg-gray-100 rounded overflow-hidden">
              <Image
                src={data[index].imageUrl || '/no-image.png'}
                alt={data[index].name}
                fill
                sizes="60px"
                className="object-cover"
                priority={index < 10}
              />
            </div>
            <span className="w-24 text-gray-400 font-mono">{data[index].id}</span>
            <span className="flex-1 truncate font-bold">{data[index].name}</span>
            <span className="flex-1 truncate">{data[index].description}</span>
            <button
              onClick={() => handleDetailClick(data[index].id)}
              className="karte-button"
            >
              詳細
            </button>
          </div>
        )}
      />
    </div>
  );
}
```

### 4.2 SSR との併用

初期データはサーバー側で取得し、仮想化リストの初回描画に渡す。LCP 短縮に寄与する。

```tsx
// Page Component (SSR)
export default async function KarteListPage() {
  const data = await fetchKarteList();

  return (
    <div>
      <h1>カルテ一覧</h1>
      <VirtualizedKarteList data={data} />
    </div>
  );
}
```

### 4.3 行内ボタンのエラーハンドリング

```tsx
const handleDetailClick = (id: string) => {
  try {
    router.push(`/karte/${id}`);
  } catch (error) {
    console.error('詳細画面への遷移に失敗しました:', error);
    // エラートースト表示
  }
};
```

## 5. 利用基準

| データ件数 | 仮想化の必要性 |
|---|---|
| 1000件以上 | **必須** |
| 100〜999件 | 行内に画像・複雑な式を含むなら推奨 |
| 〜99件 | 不要（通常の `Array.map` でよい） |

> Do/Don't の詳細は [UIビジュアル規約.md](UIビジュアル規約.md) §3 を参照。

---

## 6. 制約事項

| 制約 | 内容 |
|---|---|
| 高さ指定 | `style` に明示的な高さ指定が必須。親要素の `height: 100%` だけでは動作しない |
| `"use client"` | クライアントコンポーネントとして実装する。SSR で初回 HTML を出すには `initialItemCount` を活用 |
| アクセシビリティ | スクロールにキーボードフォーカスが追従するよう、行コンポーネントは tabIndex 等の付与を検討 |
