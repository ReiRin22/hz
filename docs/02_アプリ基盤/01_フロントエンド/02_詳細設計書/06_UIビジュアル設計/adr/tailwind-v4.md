# ADR-1: Tailwind CSS v4 を採用する（v3 非選択）

* **ステータス**: Accepted
* **決定日**: 2026-05-22
* **関連設計書**: [デザインシステム基盤設計.md](../デザインシステム基盤設計.md) §1, §2
* **関連 ADR**: なし

## 背景

電子カルテシステムのフロントエンドにおけるユーティリティファースト CSS 基盤として、Tailwind CSS の採用が方式設計書で確定している。本判断は **v3 系（`tailwind.config.js` 中心）** と **v4 系（`@theme` 中心）** のどちらを採用するかを決定するもの。

前提:
- 開発開始時点（2026年）で v4 が安定版としてリリース済み
- デザイントークンは色・余白・フォント・角丸・影など中規模規模を扱う
- 設定ファイルがプロジェクトに散らばることを避けたい

## 検討した選択肢

### 案A: Tailwind CSS v3 系
* **メリット**
  * 既存ノウハウ・サンプルが豊富
  * 多くの shadcn/ui のドキュメントが v3 前提
* **デメリット**
  * `tailwind.config.js` と `globals.css` の二重管理
  * 動的 CSS 変数（`var(...)`）連携が手書きで複雑

### 案B: Tailwind CSS v4 系
* **メリット**
  * `@theme` ブロック内で CSS 変数として宣言するだけで Tailwind ユーティリティ（`bg-primary` 等）が自動生成される
  * `tailwind.config.js` 不要。`globals.css` 一箇所でデザインシステムが完結
  * ビルド速度が改善
* **デメリット**
  * v4 前提のサードパーティ情報がまだ少ない
  * shadcn/ui 側の v4 対応状況に依存

## 決定

**案B（Tailwind CSS v4）を採用する。**

理由:
- デザインシステムを `globals.css` に一元化することで、保守時の参照箇所が分散しない
- `@theme` ブロックによる宣言的トークン管理が、本システムの「テーマ変更を将来差し替え可能にする」要件と整合する
- shadcn/ui の v4 対応は進行しており、コピーペースト方式（[ADR-2](shadcn-copy-style.md)）であれば差分追従が可能

## 影響

正の影響:
- 設定ファイル削減により新規参加者の学習コストが下がる
- CSS 変数経由でテーマ差し替えが容易（ダーク／ハイコントラスト等の将来拡張）

負の影響:
- v4 リリース直後のため、外部記事・StackOverflow 情報は v3 が混在し、コピペで誤った設定を導入するリスクがある
- shadcn/ui のテンプレートに v3 互換コードが含まれる可能性があり、コピー時の手直しが発生しうる

見直しトリガー:
- v4 がメジャーバグや破壊的変更で実用に耐えない事態が判明した場合
- shadcn/ui が v3 にロールバックした場合（現実的に低確率）
