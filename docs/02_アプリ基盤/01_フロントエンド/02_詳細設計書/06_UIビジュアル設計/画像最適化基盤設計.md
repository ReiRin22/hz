# 画像最適化基盤設計

`next/image` を中心とした画像表示基盤の I/F・配置・許可ドメイン管理を定義する。

## 1. 公開 I/F

### 1.1 利用するモジュール

```ts
import Image from 'next/image';
```

`next/image` の `Image` コンポーネントを直接利用する。基盤側でのラッパーは設けない。

### 1.2 必須プロパティ

| プロパティ | 型 | 役割 |
|---|---|---|
| `src` | `string` | 画像 URL またはローカルパス |
| `alt` | `string` | 代替テキスト（アクセシビリティ・必須） |

### 1.3 サイズ指定（いずれか必須）

| パターン | プロパティ | 用途 |
|---|---|---|
| 固定サイズ | `width` + `height` | 画像サイズが既知の場合 |
| 親要素フィット | `fill` + `sizes` | レスポンシブ・親要素を埋める表示。親に `position: relative` が必要 |

### 1.4 LCP 制御プロパティ

| プロパティ | 型 | 役割 |
|---|---|---|
| `priority` | `boolean` | ファーストビュー画像に `true`。HTML `<head>` に preload が自動追加される |

---

## 2. 自動最適化機能

`next/image` は以下を自動実行する。アプリ実装者は明示的な記述不要。

| 機能 | 内容 |
|---|---|
| フォーマット変換 | JPEG/PNG を WebP/AVIF へ自動変換（ブラウザ対応に応じる） |
| リサイズ | 表示サイズに応じた最適解像度で配信 |
| 遅延読み込み | ビューポート外の画像は読み込みを遅延（`priority` 未指定時） |

画像処理エンジンとして `sharp` を内部利用する（POC 検証済み）。

> 根拠: [ADR-4](adr/next-image-mandatory.md)

## 3. 外部ドメイン許可（基盤チーム管理）

### 3.1 配置

| ファイル | 配置 | 管理者 |
|---|---|---|
| `next.config.ts` | `frontend/` | 基盤チーム |

### 3.2 許可ドメインの設定

外部ドメインの画像を `next/image` に渡すには、`next.config.ts` の `images.remotePatterns` でホワイトリスト方式の許可設定が必須。

```ts
// frontend/next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'images.example-hospital.jp',
      },
      {
        protocol: 'https',
        hostname: '*.partner-clinic.jp',
      },
    ],
  },
};

export default nextConfig;
```

| ルール | 内容 |
|---|---|
| プロトコル | `https` のみ許可。`http` は拒否 |
| 追加プロセス | アプリチームから基盤チームへ依頼 → 基盤チームが追加 → 開発環境再起動 |
| 拒否時の挙動 | `Invalid src prop` エラーで読み込み失敗 |

未許可ドメインを渡した場合のエラー例:

```
Error: Invalid src prop (https://example.com/image.jpg) on `next/image`,
hostname "example.com" is not configured under images in your `next.config.js`
```

## 4. 標準実装パターン

### 4.1 固定サイズ画像

```tsx
import Image from 'next/image';

<Image
  src="/logo.png"
  alt="ロゴ"
  width={120}
  height={40}
/>
```

### 4.2 レスポンシブ（親要素埋め込み）

```tsx
<div className="w-[60px] h-[60px] relative">
  <Image
    src={imageUrl}
    alt="患者画像"
    fill
    sizes="60px"
    className="object-cover"
  />
</div>
```

`fill` 利用時は親要素に `position: relative`（Tailwind の `relative` クラス）が必須。

### 4.3 LCP 対象画像

```tsx
<Image
  src={heroImage}
  alt="病院外観"
  width={1200}
  height={400}
  priority
/>
```

### 4.4 仮想化リスト内での `priority`

```tsx
<Virtuoso
  totalCount={data.length}
  itemContent={(index) => (
    <Image
      src={data[index].imageUrl || '/no-image.png'}
      alt={data[index].name}
      fill
      sizes="60px"
      priority={index < 10}  // 上位10件のみ優先ロード
    />
  )}
/>
```

---

## 5. `priority` 属性の使い分け基準

| 状況 | `priority` | 理由 |
|---|---|---|
| ファーストビュー内の主要画像 | `true` | LCP 対象となる可能性が高い |
| リスト上位（10件程度） | `true` | 初期表示で見える範囲 |
| リスト下位 | `false`（省略） | スクロール時に遅延読み込み |
| モーダル内の画像 | `false`（省略） | 開かれるまで不要 |

## 6. エラーハンドリング標準パターン

### 6.1 画像読み込み失敗時のフォールバック

```tsx
"use client";

import Image from 'next/image';
import { useState } from 'react';

export default function PatientAvatar({ imageUrl, name }: { imageUrl: string; name: string }) {
  const [hasError, setHasError] = useState(false);

  return (
    <div className="w-[60px] h-[60px] relative bg-gray-100 rounded overflow-hidden">
      {hasError ? (
        <div className="flex items-center justify-center h-full text-gray-400">
          <span className="text-2xl">{name.charAt(0)}</span>
        </div>
      ) : (
        <Image
          src={imageUrl || '/no-image.png'}
          alt={name}
          fill
          sizes="60px"
          className="object-cover"
          onError={() => setHasError(true)}
        />
      )}
    </div>
  );
}
```

### 6.2 ドメイン未許可エラーの対応手順

1. アプリ基盤チームに画像ドメイン追加を依頼
2. `next.config.ts` の `remotePatterns` への追加完了を確認
3. 開発環境を再起動して設定変更を反映
