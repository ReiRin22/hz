## 1. 開発規律の基本方針

本章は「コードの正しさ（型・構文）」ではなく「開発プロセスの規律と品質ゲート」を扱う。

| 観点 | 担当章 |
|---|---|
| コードの正しさ（型・構文・依存関係） | [02_開発環境設計](../02_開発環境設計/)（TypeScript・ESLint） |
| **コードの見た目（整形）** | **本章（Prettier）** |
| **UI コンポーネントの隔離検証** | **本章（Storybook）** |
| **マージ可否の判断基準** | **本章（品質ゲート）** |
| テストコードの書き方 | [12_自動テスト実装/自動テスト実装規約.md](../12_自動テスト実装/自動テスト実装規約.md) |

> **注**: 「コードの正しさ」のうち `any` 型禁止・未使用変数検出・依存関係ルール等の ESLint ルールは [02_開発環境設計](../02_開発環境設計/) で定義する。本章は ESLint ルールには関与せず、整形と品質ゲートに専念する。

## 2. 基盤 I/F 利用規約

> **警告**: 整形ルール・エディタ設定・ストーリー設定の各ファイルは**基盤チームが管理する**。アプリ実装者が個別に値を変更すると、CI 整形チェック失敗・メンバー間の整形差分・ビジュアルリグレッション誤検出といった事故につながるため、**基盤提供の設定を経由しない実装は禁止**する。

### 2.1 経由必須 I/F とバイパス禁止 API

| 用途 | ✅ 経由必須 I/F | ⛔ バイパス禁止 API・操作 | 詳細 |
|---|---|---|---|
| コード整形ルール | プロジェクトの `.prettierrc` | 個人の好みでの `.prettierrc` 改変、`// prettier-ignore` の濫用 | [Prettier整形基盤設計.md §2](Prettier整形基盤設計.md) |
| 整形対象除外 | プロジェクトの `.prettierignore` | 個人別 ignore 追加、コミット直前の手動 skip | [Prettier整形基盤設計.md §3](Prettier整形基盤設計.md) |
| エディタ統合（整形） | `.vscode/settings.json` の **Prettier 関連設定**（リポジトリ管理） | ユーザー設定（`User/settings.json`）でのフォーマッター上書き | [Prettier整形基盤設計.md §4](Prettier整形基盤設計.md) |
| 整形コマンド | `npx prettier --check .` / `npx prettier --write .` | 個別ファイルへの非統一コマンド、整形スキップ | [Prettier整形基盤設計.md §5](Prettier整形基盤設計.md) |
| UI 隔離検証 | Storybook（導入後）の Story | サンプルページでの個別検証、本番画面での目視確認のみ | [Storybook基盤設計.md §1](Storybook基盤設計.md) |

> **注**: `.vscode/settings.json` には ESLint 自動修正など [02_開発環境設計](../02_開発環境設計/) 由来の設定も含まれる。本章では Prettier 関連設定のみを管轄する。設定ファイル全体の配置は [Prettier整形基盤設計.md §6.1](Prettier整形基盤設計.md) を参照。

### 2.2 例外条件

| 例外 | 条件 |
|---|---|
| `.prettierrc` の修正 | 基盤チームが承認した PR でのみ可能 |
| `// prettier-ignore` | 表データのアスキーアートのように、整形が破壊的な箇所に限る。コメントで理由を明記する |
| `.prettierignore` の追加 | 自動生成ファイル・サードパーティ生成物・大容量データに限る |

### 2.3 PR レビュー観点（grep ターゲット）

バイパス検出のためのレビュー観点を以下に集約する。

| 検出対象 | 例 |
|---|---|
| `.prettierrc` の差分 | プロジェクトルートの `.prettierrc` が変更された PR は基盤チームレビュー必須 |
| `// prettier-ignore` の追加 | 理由コメントが無い場合は差し戻し |
| `.vscode/settings.json` のフォーマッター上書き | `editor.defaultFormatter` を Prettier 以外に変更している差分 |
| Story 未追加の UI コンポーネント変更 | `*.stories.ts(x)` が同梱されていない `components/` 配下の変更（Storybook 導入後） |

## 3. Prettier 利用ルール

### 3.1 やっていいこと

- 保存時の自動整形を有効化する（`.vscode/settings.json` の設定値に従う）
- コミット前に `npx prettier --check .` でチェックする
- 自動生成ファイル等は `.prettierignore` で除外する（基盤チーム承認の上で）

### 3.2 やってはいけないこと

- Prettier の整形結果を手動で上書きする（再保存で元に戻る）
- プロジェクト共通の `.prettierrc` を個人の好みで変更する
- 整形チェックをスキップしてコミットする
- VSCode のユーザー設定でフォーマッターを Prettier 以外に変更する

詳細な設定値・配置・実行コマンドは [Prettier整形基盤設計.md](Prettier整形基盤設計.md) を参照。

## 4. Storybook 利用ルール（導入後）

> Storybook の詳細仕様は本章執筆時点では未定義。導入後、以下のルールが [Storybook基盤設計.md](Storybook基盤設計.md) §3 で具体化される。

### 4.1 Story 作成・更新の必須化（予定）

- UI コンポーネント（`components/atoms/`, `components/molecules/`, `components/organisms/`）の追加・変更時は対応する Story を必ず作成・更新する
- Story 未作成・未更新のコンポーネントは PR マージ不可とする

### 4.2 やってはいけないこと（予定）

- Story を持たない UI コンポーネントを追加する
- Decorator のグローバル設定をローカル Story で上書きする（テーマ・モックの不整合防止）

## 5. 品質ゲート（マージ基準）

### 5.1 PR マージ必須条件

> 本節の品質ゲート方針は、方式設計書 [@フロントエンド方式設計書_sheet_23_7.運用・保守設計.md](../../01_方式設計書/@フロントエンド方式設計書_sheet_23_7.運用・保守設計.md) 7.2 開発方針 No.5 / 7.3 テスト方針 No.6 を上位根拠とする。

プルリクエストがマージ可能となるためには、以下の条件をすべて満たすこと。

| 条件 | 説明 |
|---|---|
| **静的解析の全パス** | TypeScript（型チェック）、ESLint（構文チェック）、Prettier（整形チェック）がすべてエラーなく完了。Prettier の CI 自動チェックは [Prettier整形基盤設計.md §5.3](Prettier整形基盤設計.md) に基づき今後実装予定。それまでは PR 作成者が `npx prettier --check .` をローカル実行する |
| **自動テストの全パス** | 単体テスト・コンポーネントテスト・E2E テストがすべて成功（詳細は [12_自動テスト実装/自動テスト実装規約.md](../12_自動テスト実装/自動テスト実装規約.md)） |
| **テストカバレッジ閾値** | 単体テストカバレッジが目標値以上（具体値は [12_自動テスト実装/自動テスト実装規約.md](../12_自動テスト実装/自動テスト実装規約.md) §1.4 で定義） |
| **Storybook Story の作成・更新** | UI コンポーネントを追加・変更した場合、対応する Story を作成・更新（Storybook 導入後） |
| **レビュー承認** | 最低 1 名以上のレビュアーから Approve を得る |

> **注**: マージ戦略・承認フロー等の詳細は [docs/00_環境構築手順書/02_GitLab運用手順書.md](../../../00_環境構築手順書/02_GitLab運用手順書.md) を参照。

### 5.2 マージ不可の条件

以下のいずれかに該当する場合、マージは不可とする。

| 条件 | 説明 |
|---|---|
| **ビルドエラー** | `npm run build` が失敗する場合 |
| **型エラー** | TypeScript の型チェック（`tsc --noEmit`）が失敗する場合 |
| **Lint エラー** | ESLint で `error` レベルのエラーが検出された場合（`warning` はマージ可能だが、早急に修正） |
| **テスト失敗** | 自動テストのいずれかが失敗した場合 |
| **レビュー未承認** | レビュアーからの承認が得られていない場合 |
