# ADR-1: Prettier `trailingComma` を `all` に設定する

* **ステータス**: Accepted
* **決定日**: 2025-10-01
* **関連設計書**: [Prettier整形基盤設計.md](../Prettier整形基盤設計.md) §2 整形ルール定義
* **関連 ADR**: [ADR-2](prettier-npm-and-vscode-extension.md)（Prettier 採用そのものの根拠と上位方針への紐付け）

## 背景（Context）

Prettier の `trailingComma` オプションは、配列・オブジェクト・関数引数の末尾カンマの付与方針を制御する。
本プロジェクトでは Git 上の差分レビュー量がコードレビュー効率に直結するため、変更行数を最小化する設定が望ましい。

主な要件:

- レビュー時のノイズ（末尾カンマ追加だけで前行が変更扱いになる diff）を排除する
- マージコンフリクトの解決容易性を高める
- 新規追加行の Git diff が「追加された行のみ」になるよう揃える

## 検討した選択肢（Options）

### 案A: `trailingComma: "all"`（採用）

* **メリット**
  * 配列・オブジェクト・関数引数すべての末尾にカンマを付与するため、項目追加時の Git diff が「追加行 1 行」のみになり、レビューが容易
  * マージコンフリクト時に「最後の項目」を意識せずに済む
  * ES2017 以降をサポートするモダンブラウザ前提の本プロジェクトでは互換性問題が発生しない
* **デメリット**
  * ES5 互換が必要な環境では関数引数末尾カンマが構文エラーになる（本プロジェクトでは該当なし）

### 案B: `trailingComma: "es5"`（見送り）

* **メリット**: ES5 互換環境でも動作する
* **デメリット**
  * 関数引数の末尾カンマが付与されないため、引数追加時に前行も変更されレビュー時のノイズになる
  * 本プロジェクトはモダンブラウザ前提（最新 TypeScript・React 環境）であり ES5 互換は不要

### 案C: `trailingComma: "none"`（見送り）

* **デメリット**: すべての末尾カンマが付与されないため、項目追加時の Git diff ノイズが最大化する

## 決定（Decision）

**案A: `trailingComma: "all"` を採用する。**

本プロジェクトはモダンブラウザのみをサポート対象としており ES5 互換制約がない。Git diff の最小化とマージコンフリクト解消の容易さを優先する。

## 影響（Consequences）

* **正**: 項目追加時の Git diff が綺麗になり、コードレビュー効率が向上する
* **負**: なし（ES5 互換が必要になった場合は再判断）
* **見直しトリガー**: ES5 互換環境のサポートが必要になった場合、または別の整形ツールへの移行を検討する場合
