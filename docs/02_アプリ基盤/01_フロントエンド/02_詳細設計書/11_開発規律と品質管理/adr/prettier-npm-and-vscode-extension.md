# ADR-2: Prettier は npm パッケージと VSCode 拡張機能の両方を併用する

* **ステータス**: Accepted
* **決定日**: 2025-10-01
* **関連設計書**: [Prettier整形基盤設計.md](../Prettier整形基盤設計.md) §1 構成方針
* **関連 ADR**: なし

## 背景（Context）

Prettier は「コマンドライン経由で動作する npm パッケージ」と「エディタ統合する VSCode 拡張機能」の 2 形態で利用できる。
本プロジェクトでは、CI/CD での品質ゲートと開発者の体験向上の両立が必要であり、どちらか一方では要件を満たせない可能性がある。

主な要件:

- チームメンバー全員が **同一バージョン** の Prettier を使用すること（整形結果のばらつき防止）
- CI/CD パイプラインで `npx prettier --check .` による整形チェックを品質ゲートとして機能させること
- 開発者が保存時に自動整形され、手動コマンド実行を不要とすること
- リポジトリ内の `.prettierrc` を全員が同一ルールとして適用できること

## 検討した選択肢（Options）

### 案A: npm パッケージと VSCode 拡張機能の両方を併用（採用）

* **メリット**
  * `package.json` でバージョン固定 → メンバー間の整形結果が完全一致する
  * `npx prettier --check .` を CI に組み込み品質ゲートを成立させられる
  * VSCode 拡張機能は内部的に **`node_modules/prettier`** を呼び出すため、エディタ整形と CLI 整形が同じバージョンで動く
  * 保存時自動整形により開発体験を最大化できる
* **デメリット**
  * 新規参加者は npm install と拡張機能インストールの 2 手順が必要

### 案B: npm パッケージのみ（見送り）

* **メリット**: バージョン固定・CI ゲート可能
* **デメリット**
  * 保存時自動整形ができず、毎回 `npx prettier --write <file>` を手動実行する必要があり、開発効率が悪い
  * 整形漏れが発生しやすく、CI でリジェクトされる頻度が高くなる

### 案C: VSCode 拡張機能のみ（見送り）

* **メリット**: 保存時自動整形による高い開発体験
* **デメリット**
  * 拡張機能内蔵バージョンを使用するため、メンバー間でバージョンが異なる可能性がある
  * CI/CD で実行できないため、品質ゲートとして機能しない
  * VSCode 以外のエディタを使う開発者が排除される

## 決定（Decision）

**案A: npm パッケージと VSCode 拡張機能の両方を併用する。**

VSCode 拡張機能はあくまで「VSCode 内で Prettier を呼び出す UI」と位置づけ、整形処理の実体は `node_modules/prettier` が担う。
これによりエディタ整形・CLI 整形・CI 整形のすべてが同一バージョン・同一ルールで動作する。

**動作フロー**:

1. `npm install -D prettier` でプロジェクトに Prettier をインストール
2. `.prettierrc` で整形ルールを定義
3. VSCode 拡張機能をインストール
4. ファイル保存 → 拡張機能が `node_modules/prettier` を呼び出し `.prettierrc` のルールで整形

## 影響（Consequences）

* **正**: エディタ・CLI・CI の整形結果が完全一致する。CI 品質ゲート成立
* **負**: 新規参加者のセットアップ手順が増える（README で明示）
* **見直しトリガー**: Prettier の代替ツール（dprint 等）採用、または VSCode 以外のエディタが標準になった場合
