# Storybook 基盤設計

本章は、UI コンポーネント開発のための Storybook 基盤の位置づけ・役割・今後の定義事項を定義する。
本基盤の利用ルール（Story 作成必須化等）は [開発規律と品質管理規約.md](開発規律と品質管理規約.md) §4 を参照。

## 1. Storybook の位置づけ

UI コンポーネントのカタログ化および単体確認を可能にするツールとして、Storybook を導入する。

### 1.1 基盤としての役割

| 役割 | 内容 |
|---|---|
| **コンポーネントカタログ** | 全 UI コンポーネントの状態（Props）を一覧化し、デザインシステムを可視化する |
| **隔離開発環境** | アプリケーションのロジック・データから切り離し、コンポーネントの全状態を再現・検証できる |
| **ビジュアルリグレッションテスト基盤** | ビジュアルリグレッションサービス（具体的なサービスは §3.4 で選定）と連携し、CSS 修正等による画面崩れを早期検出する |
| **ドキュメント基盤** | Props の自動ドキュメント化、デザインチームとの仕様共有 |

## 3. 今後の定義事項

本章執筆時点では、以下の項目が未定義である。Storybook 導入フェーズで本セクションを更新する。

### 3.0 状態区分

各サブセクションの確定度を以下に区分する。

| サブセクション | 状態区分 | 備考 |
|---|---|---|
| §3.1 Story 作成規約 | **詳細未定（合意済み）** | コンポーネント直下併置 / `*.stories.ts(x)` 命名は方針として合意済み。具体的な命名規則・Args 方針は導入時確定 |
| §3.2 Decorator によるコンテキスト再現 | **詳細未定（合意済み）** | Tailwind / globals.css / テーマ / MSW 連携を含むことは合意済み。実装は導入時確定 |
| §3.3 Storybook Test Runner との連携 | **未合意** | 12 章（自動テスト実装）との整合性検討が必要 |
| §3.4 デザインレビューでの活用 | **未合意** | ビジュアルリグレッションサービスの選定が未着手 |
| §3.5 運用ルール | **詳細未定（合意済み）** | Atoms / Molecules / Organisms 全てを Story 対象とする方針は合意済み（[05_コンポーネント設計](../05_コンポーネント設計/) と整合） |


### 3.1 Story 作成規約

- ファイル配置: コンポーネント直下に `*.stories.ts(x)` を併置するか、`stories/` サブディレクトリに集約するか
- 命名規則: ファイル名・タイトル（`title:`）の構造
- Args による Props のカスタマイズ方針
- Default / Variants の Story 命名

### 3.2 Decorator によるコンテキスト再現

- グローバルスタイル（Tailwind / globals.css）の読み込み
- テーマプロバイダーの装着
- React Query / Zustand のモック化（MSW 連携を含む）

### 3.3 Storybook Test Runner との連携

- Play function によるインタラクション自動化
- アクセシビリティ検証（`@storybook/addon-a11y`）
- CI でのテスト実行戦略（12 章と整合）

### 3.4 デザインレビューでの活用

- デザイナー・PdM との Story 共有方法
- Chromatic 等のビジュアルリグレッションサービス連携

### 3.5 運用ルール

- Story 作成の必須化スコープ（Atoms / Molecules / Organisms のいずれを対象とするか）
- Story メンテナンス責務（コンポーネント変更時の Story 同時更新義務）
- 古い Story の削除フロー

## 4. 公開対象（アプリ実装者から見た位置づけ）

| 項目 | 公開対象判定 |
|---|---|
| `.storybook/main.ts` / `.storybook/preview.ts` | ❌ 基盤チーム管理（アプリ実装者は変更不可） |
| Story ファイル（`*.stories.ts(x)`） | ✅ アプリ実装者が **作成する**（規約に従う） |

アプリ実装者は **基盤の設定ファイルは触らず、Story ファイルのみを作成する**。Story 作成規約は §3.1 で具体化する。
