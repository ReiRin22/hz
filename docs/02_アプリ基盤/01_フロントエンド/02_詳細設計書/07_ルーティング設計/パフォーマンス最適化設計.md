# パフォーマンス最適化設計

## 1. 描画負荷の制御

### 1.1 リスト表示の仮想化（react-virtuoso）

100件を超える動的リストには仮想化を適用し、描画DOM数を100個以下に制限する。

```tsx
import { Virtuoso } from 'react-virtuoso';

// 例: 大量の診察記録一覧
<Virtuoso
  data={diagnosisRecords}
  itemContent={(index, record) => (
    <DiagnosisRecordItem key={record.id} record={record} />
  )}
/>
```

**適用基準**: リストアイテム数が100件を超える、または超える可能性がある場合は必ず仮想化する。

### 1.2 画像最適化（next/image）

```tsx
import Image from 'next/image';

// ✅ next/image を使用
<Image src="/patient-photo.jpg" alt="患者写真" width={80} height={80} />

// ❌ 禁止: <img> タグの直接使用
<img src="/patient-photo.jpg" alt="患者写真" />
```

## 2. Code Splitting（next/dynamic）

### 2.1 適用判断基準

| 適用ケース | 具体例 | 実装パターン |
|---|---|---|
| 初回表示に不要 | モーダル、ドロワー、タブの2枚目以降、アコーディオンの中身 | `{ ssr: false }` |
| 大きな外部ライブラリ（200KB以上） | Chart.js、Recharts、PDF.js、Monaco Editor、XLSX | `{ ssr: false }` |
| 条件付き表示 | 管理者専用パネル、特定権限でのみ表示する機能 | `{ ssr: false }` |
| 低頻度の機能 | 印刷プレビュー、CSVエクスポート、高度な設定画面 | `{ ssr: false }` |

**適用しないケース**:
- 初回表示に必須のコンポーネント（ヘッダー、メインコンテンツ、ナビゲーション）
- 50KB未満の小さいコンポーネント
- Atoms/Moleculesの基本的なUI部品

### 2.2 実装パターン

```tsx
import dynamic from 'next/dynamic';

// 基本パターン: 重い外部ライブラリを使用するコンポーネント
const MedicalRecordChart = dynamic(
  () => import('./components/MedicalRecordChart'),
  {
    ssr: false,
    loading: () => <LoadingSkeleton variant="chart" />,
  }
);

// Named Exportの場合
const AdminPanel = dynamic(
  () => import('./components/AdminPanel').then(mod => mod.AdminPanel),
  { ssr: false }
);

// 権限制御パターン
const AdminFeature = dynamic(() => import('./AdminFeature'), { ssr: false });

export function FeaturePage({ isAdmin }: Props) {
  return (
    <div>
      <MainContent />
      {isAdmin && <AdminFeature />}
    </div>
  );
}
```

### 2.3 実装上の注意点

| 注意点 | 詳細 |
|---|---|
| Named Export への対応 | `dynamic(() => import('./Component').then(mod => mod.ComponentName))` のように明示的に指定 |
| Props の型安全性 | 動的読み込みでも型情報は保持される |
| Suspense との併用 | `loading` プロパティの代わりに、親コンポーネントで `<Suspense>` を使用することも可能 |
| SSR の無効化 | `{ ssr: false }` を指定することでクライアントサイドのみでロード。ブラウザAPIを使用するコンポーネントに必須 |

## 3. プリフェッチ制御

Next.jsの `<Link>` コンポーネントによるプリフェッチを戦略的に管理し、UX向上とBFF負荷抑制を両立させる。

### 3.1 使い分けルール

| 状況 | 設定 |
|---|---|
| 標準遷移（ナビゲーション・一般ボタン） | `prefetch={true}`（デフォルト） |
| 大規模リスト（カルテ履歴一覧等） | `prefetch={false}` |

### 3.2 実装コード例

```tsx
import Link from 'next/link';

export function NavigationComponent({ listData }) {
  return (
    <nav>
      {/* 1. 通常の遷移: UX優先（デフォルトのプリフェッチを活用） */}
      <Link href="/dashboard" className="btn-primary">
        ダッシュボードへ戻る
      </Link>

      {/* 2. 大規模リスト: BFF負荷抑制のため、ホバー時のみ取得に制限 */}
      <div className="list-wrapper">
        {listData.map((item) => (
          <Link
            key={item.id}
            href={`/karte/${item.id}`}
            prefetch={false}
            className="list-item"
          >
            カルテID: {item.id} の詳細
          </Link>
        ))}
      </div>
    </nav>
  );
}
```
