# ルーティング構造設計

## 1. App Router によるディレクトリ構造

本システムでは `src/app`（URLパス・レイアウト定義）と `src/features`（業務ロジック・UI実体）を明確に分離する。

> 根拠: [ADR-1](adr/app-router-adoption.md)

### 1.1 app ディレクトリの構成

```
src/app/
├── layout.tsx          ← Root Layout: html/bodyタグ, 全画面共通Provider, globals.css読み込み
├── loading.tsx         ← システム起動時の全画面スケルトン
├── error.tsx           ← グローバルError Boundary
│
└── (karte)/            ← ルートグループ: URLパスに影響しない共通レイアウト境界
    ├── layout.tsx      ← サイドメニュー, 患者ヘッダー, ドメイン共通Providerを定義
    ├── loading.tsx     ← ページ遷移用スケルトン（サイドバー維持）
    └── diagnosis/
        └── record-management/
            └── clinical-entry/
                └── [id]/
                    └── page.tsx  ← LV3画面のエントリポイント
```

### 1.2 features ディレクトリの構成

```
src/features/
  {LV1}/                         例: diagnosis
    {LV2}/                       例: record-management
      {LV3}/                     例: clinical-entry
        components/
        hooks/
        stores/
        repository/
        api/
        types/
        assets/
        test/
        index.ts
  {LV1}_shared/                  同一LV1ドメイン内の共有資産
src/shared/                      システム全体の共有資産
```

## 2. 依存関係の強制（ESLint設定）

### 2.1 使用ツール・プラグイン

| 分類 | 名称 | 役割 |
|---|---|---|
| 標準ルールセット | `eslint-config-next` | Next.js / React のベストプラクティス強制 |
| 拡張プラグイン | `eslint-plugin-import` | ディレクトリ間の依存関係・インポート順序チェック |

### 2.2 適用ルール一覧

| ルール名 | 役割 | 具体的な運用例 |
|---|---|---|
| `no-restricted-imports` | 特定パスのインポート禁止 | `features/` から `app/` への逆参照禁止。他機能の `api/` や `repository/` を `index.ts` を介さず直接参照することをエラーにする |
| `import/no-cycle` | 循環参照の禁止 | A と B のファイルが互いに呼び出し合う循環状態を検知してビルドエラーにする |
| `import/order` | インポート順序の固定 | `ライブラリ（node_modules）` → `src/shared/` → `機能内 repository/ api/` の順に統一 |
| `@typescript-eslint/no-unused-vars` | 未使用変数の禁止 | 定義しただけで使用されていない変数・インポートをエラーとする |
| `@typescript-eslint/no-explicit-any` | `any` 型の禁止 | 型定義の放棄を禁止し、型安全性を強制する |

## 3. データフロー（app/features間）

`app/page.tsx` と `features/` は「指揮者とオーケストラ」の関係。`page.tsx` は *何を・どこに配置するか* を決め、実際の処理はすべて `features/` に委ねる。

```
src/app/(karte)/diagnosis/.../[id]/page.tsx   ← ① URLパラメータ解決 (await params)
  │
  ├─ ② features/.../repository/getDiagnosisRepository.ts  呼び出し
  │       └─ features/.../api/getDiagnosisAPI.ts           HTTP通信
  │
  └─ ③ features/.../components/DiagnosisOrganism          に initialData を Props で渡す
               └─ 以降のロジック・描画・状態管理はすべて features 側が担う
```

## 4. front_bff_shared の階層構造

フロントエンドとBFF間の型定義を共有するディレクトリ。シンボリックリンクで `frontend/src/front_bff_shared` と `bff/src/front_bff_shared` の両方から参照される。

### 4.1 ディレクトリ構成

```
front_bff_shared/
  {LV1}/
    {LV2}/
      {LV3}/
        types/
          request/   ← BFF Controllerが受け取るリクエスト型
          response/  ← BFF Serviceが返すレスポンス型
        schemas/     ← Zodバリデーションルール（フロント・BFF共用）
    _shared/         ← LV1ドメイン内共有型
  _shared/           ← システム全体共有型
```

### 4.2 フロントエンド側の使用例

```tsx
/**
 * LV3: 診察入力画面 API定義
 * 物理パス: src/features/diagnosis/create/entry/api/getDiagnosisAPI.ts
 */
import { axiosClient } from '@/shared/plugins/axiosClient';
import type { GetDiagnosisResponse } from '@/front_bff_shared/diagnosis/create/entry/types/response/entry.api.response';

export const getDiagnosisData = async (id: string): Promise<GetDiagnosisResponse> => {
  const response = await axiosClient.get<GetDiagnosisResponse>(`/api/diagnosis/${id}`);
  return response.data;
};
```

> 型SSOTの根拠: [01章ADR: front-bff-shared-ssot.md](../01_フロントエンド・BFF共通基盤設計/adr/front-bff-shared-ssot.md)

### 4.3 BFF側の実装例

```ts
/**
 * LV3: 診察入力画面 BFF Service
 * 物理パス: bff/src/features/diagnosis/create/entry/entry.service.ts
 */
import { Injectable } from '@nestjs/common';
import type { GetDiagnosisResponse } from 'front_bff_shared/diagnosis/create/entry/types/response/entry.api.response';

@Injectable()
export class EntryService {
  async findOne(id: string): Promise<GetDiagnosisResponse> {
    // front_bff_sharedの型定義に合致しない戻り値はビルドエラーになる
    return {
      patientId: id,
      patientName: '山田 太郎',
      diagnosisDate: '2026-03-09',
      soap: {
        subjective: '頭痛がする',
        objective: '熱 37.5度',
        assessment: '感冒の疑い',
        plan: '解熱剤の処方',
      },
    };
  }
}
```
