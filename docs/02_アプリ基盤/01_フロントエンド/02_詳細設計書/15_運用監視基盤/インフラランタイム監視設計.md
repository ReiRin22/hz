# インフラランタイム監視設計

[監視指標カタログ.md](監視指標カタログ.md) で定義された **インフラ層（Node.js ランタイム）** コンポーネントの監視仕様。**リソース指標** に基づき、BFF（NestJS / Node.js）のランタイムメトリクスを Prometheus / Grafana で監視する設計を確定する。あわせて、BFF（NestJS）API 監視の検討事項を【TBD】として記録する。

> 統合監視基盤（Prometheus / Grafana）の構成・保持・アラート設定は `システム監視・通知サービス方式設計書` を参照のこと。本書はフロントエンド詳細設計として把握すべき監視項目の概要と接続点のみ確定する。

---

## 1. 監視対象と方針

| 項目 | 内容 |
|---|---|
| **監視対象** | BFF（NestJS / Node.js）のランタイム、コンテナ、OS リソース |
| **収集メトリクス** | [監視指標カタログ.md](監視指標カタログ.md) §4 リソース指標 |
| **収集方式** | node-exporter + cAdvisor + Prometheus（統合監視基盤側で収集） |
| **可視化** | Grafana ダッシュボード（統合監視基盤側で構築）|

> 責務分界の根拠: [adr/monitoring-layer-responsibility.md](adr/monitoring-layer-responsibility.md)

---

## 2. 監視対象メトリクス（概要）

本書ではフロントエンド詳細設計書として把握すべき監視項目の概要のみを記載する。具体的な収集方式・保持ポリシー・アラート設定は `システム監視・通知サービス方式設計書` を参照のこと。

| カテゴリ | 監視項目 | 収集方法 |
|---|---|---|
| **システムリソース** | メモリ使用量（Heap、RSS）、CPU 負荷、ディスク I/O | node-exporter + Prometheus |
| **アプリケーション** | HTTP リクエスト数、レスポンスタイム（P50/P90/P99）、エラー率 | cAdvisor / カスタムメトリクス |
| **コンテナ** | Container 再起動回数、リソース制限到達頻度 | cAdvisor + Prometheus |

### Grafana ダッシュボード

統合監視基盤の Grafana ダッシュボードでは、以下のビューが提供される予定:

- BFF 全体のリソース使用状況（CPU / メモリトレンド）
- テナント別リクエスト数・エラー率
- WebSocket 接続数トレンド
- アラート発報履歴

詳細は `システム監視・通知サービス方式設計書` を参照のこと。

## 4. BFF（NestJS）API 監視【TBD】

[監視指標カタログ.md](監視指標カタログ.md) で定義された **BFF（NestJS）** コンポーネントの監視について、**性能指標**（API 応答時間 P50/P90/P99）および **エラー指標**（API エラー率）を収集・監視する予定である。

### 4.1 検討事項

- BFF からバックエンド API（Base、Profile 等）へのリクエスト時間（エンドポイント別、テナント別）
- React Query のキャッシュヒット率
- エンドポイント別のレスポンスタイム集計（P50/P90/P99）
- API エラー率（HTTP 4xx/5xx）の監視

### 4.2 現状

フロントエンドと BFF の詳細設計書は作成済みだが、バックエンドサービス側の設計はこれから開始する段階である。バックエンド API の仕様（エンドポイント設計、認証方式、レスポンス構造等）が確定次第、本監視項目の詳細を定義する。

### 4.3 検討時期

バックエンドサービスの詳細設計書作成と並行して、API 監視仕様を策定。
