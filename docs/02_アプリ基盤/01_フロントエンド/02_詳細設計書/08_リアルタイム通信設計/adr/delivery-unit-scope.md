# ADR-2: 配信単位をユーザー単位・テナント単位の2種に限定

* **ステータス**: Accepted
* **決定日**: 2025-01-01
* **関連設計書**: [リアルタイム通信規約.md](../リアルタイム通信規約.md) §1, [BFF通知Gateway設計.md](../BFF通知Gateway設計.md) §3
* **関連 ADR**: なし

## 背景（Context）

リアルタイム通知の配信単位として、ユーザー単位・テナント単位に加え、役職（医師・看護師など）や組織（病棟・外来）などのグループ単位での配信需要が将来的に存在する可能性があった。初期設計時点で配信単位の範囲を決める必要があった。

## 検討した選択肢（Options）

### 案A: ユーザー単位・テナント単位の2種のみ
* メリット: Room 命名規則がシンプル（`{tenantId}:{userId}` と `{tenantId}`）。マルチテナント安全性の検証が容易
* デメリット: グループ単位の配信が必要になった場合に Room 設計を変更する必要がある

### 案B: グループ単位（役職・組織）を含めた多粒度配信
* メリット: 将来のグループ通知要件に対応できる
* デメリット: グループ定義・メンバーシップ管理の仕組みが別途必要。現時点で要件が未確定

## 決定（Decision）

**案A（2種のみ）を採用**。

グループ単位の配信要件が設計時点で未確定であり、未確定要件に基づく設計は後の変更コストを増大させるリスクがある。現時点の要件（ユーザー宛・テナント全体宛）は案Aで完全に充足できる。

## 影響（Consequences）

* Room 命名規則が固定されるため、グループ配信を追加する際は Room 設計の拡張が必要になる
* 初期実装の複雑度が最小化され、マルチテナント安全性の担保が容易になる
* **見直しトリガー**: 役職・組織単位での通知配信要件が機能仕様として確定した場合
