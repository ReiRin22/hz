## 1. 本章の範囲

**対象とする通信パターン**：
- サーバー主導のプッシュ通知（医師からの指示・アラート・検査結果到着など）
- マルチテナント環境での安全な通知配信

**配信単位**（2種のみ）：

| 配信単位 | Room 名 | 用途例 |
|---|---|---|
| ユーザー単位 | `{tenantId}:{userId}` | 特定ユーザーへの通知（検査結果到着・担当患者のアラートなど） |
| テナント単位 | `{tenantId}` | テナント全スタッフへの通知（システムメンテナンス・緊急一斉通知など） |

> 根拠: [ADR-2](adr/delivery-unit-scope.md)

**対象外**：
- チャット機能などの双方向リアルタイム通信
- REST API による通常のデータ取得・更新
- グループ（役職・組織）単位での配信

## 2. 基盤 I/F 利用規約

> ⚠️ **基盤が提供する I/F を経由しない実装は禁止する。** バイパスすると、Socket.io 接続の多重化・マルチテナント Room 混入・通知履歴のデータ残留が発生する。

### 2.1 経由必須 I/F

| 用途 | ✅ 経由必須 I/F | ⛔ バイパス禁止 API | 詳細参照 |
|---|---|---|---|
| リアルタイム通知の受信・接続 | `useNotification()` （ルートレイアウトで1回のみ） | `io()` 直接呼び出し・各ページでの個別接続 | [Socket接続基盤設計.md](./Socket接続基盤設計.md) §2 |
| 通知履歴の参照・既読管理 | `useNotificationStore()` | Zustand `create()` 直接呼び出し・ローカル state での通知保持 | [通知ストア基盤設計.md](./通知ストア基盤設計.md) §2 |
| 通知メッセージ型のバリデーション | `notificationMessageSchema.parse()` | 手書き型ガード・`as` キャスト | [Payload型定義設計.md](./Payload型定義設計.md) §3 |
| BFF からの通知配信 | `sendNotificationToUser()` / `sendNotificationToTenant()` | `this.server.emit()`（ブロードキャスト） | [BFF通知Gateway設計.md](./BFF通知Gateway設計.md) §3 |

### 2.2 例外条件

| 条件 | 適用範囲 |
|---|---|
| 基盤チームによる `useNotification` 本体の実装・改修 | 基盤チームのみ |
| PoC・プロトタイプ環境での一時的な直接接続 | 基盤チームが明示的に承認した場合のみ |

### 2.3 PR レビュー観点

以下を grep して直接使用が含まれていないか確認する。

```bash
# Socket.io 直接接続
grep -rn "io(" frontend/src/features/ --include="*.ts" --include="*.tsx"
grep -rn "socket\.io-client" frontend/src/features/ --include="*.ts" --include="*.tsx"

# ブロードキャスト配信（BFF）
grep -rn "this\.server\.emit(" bff/src/

# 手書き通知 state
grep -rn "useState.*notif" frontend/src/features/ --include="*.tsx"
```

## 3. フロントエンド実装規約

### 3.1 接続初期化

- `useNotification()` はルートレイアウト（`frontend/src/app/layout.tsx`）でアプリ全体を通じて1回のみ呼び出す
- 各ページコンポーネントで個別に Socket 接続を初期化してはいけない
- `<Toaster />` もルートレイアウトの1箇所のみに配置する

```tsx
// ✅ Do: ルートレイアウトで1回のみ
// frontend/src/app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  useNotification();
  return (
    <html>
      <body>
        {children}
        <Toaster position="top-right" toastOptions={{ duration: 4000 }} />
      </body>
    </html>
  );
}

// ⛔ Don't: 各ページで個別に接続
// frontend/src/features/dashboard/page.tsx
export default function DashboardPage() {
  useNotification(); // 禁止: 接続数が増加し重複受信が発生する
}
```

### 3.2 通知履歴の参照

- 通知一覧・既読管理は必ず `useNotificationStore()` を通じて操作する
- 受信した通知を `useState` 等のローカル state で保持してはいけない

```tsx
// ✅ Do
import { useNotificationStore } from '@/shared/stores/notification.store';

const { notifications, unreadCount, markAsRead } = useNotificationStore();

// ⛔ Don't
const [notifications, setNotifications] = useState([]); // 禁止: 基盤ストアを経由しない
```

### 3.3 再接続

- Socket.io のデフォルト自動再接続機能をそのまま使用する（`reconnectionAttempts: 10`、Exponential Backoff）
- 手動での再接続試行コードを実装してはいけない（Socket.io 自動再接続と競合する）
- 詳細は [Socket接続基盤設計.md §6](./Socket接続基盤設計.md) を参照

### 3.4 クリーンアップ

- ログアウト時は `resetAllStores()` を呼び出して通知履歴をクリアする（マルチテナント安全性）
- `§2 の通り、useNotification` 内部のイベントリスナー削除（`socket.off()`）・接続終了（`socket.close()`）は基盤が自動処理する
- コンポーネントアンマウント時に `socket.off()` / `socket.close()` を呼ぶのは基盤内部の責務であり、アプリ側で重複して呼び出してはいけない（メモリリーク防止の二重処理）

### 3.5 エラーハンドリング

- 接続エラー（`connect_error`）はユーザーへのトースト表示を行わない
- 不正な Payload（Zod バリデーション失敗）はサイレントフェイルとし、コンソールログのみ出力する
- 開発環境での接続状態確認はコンソールログ（`connect_error` / `disconnect` イベント）で行う

### 3.6 パフォーマンス

- アプリ全体で Socket 接続は1つのみ（ルートレイアウトで初期化）。各ページで個別接続してはいけない
- 通知履歴は最新 100 件のみ保持される（基盤が自動削除）。アプリ側で別途バッファリングしてはいけない

## 4. BFF 実装規約

### 4.1 配信方法

- ユーザー宛: `sendNotificationToUser(tenantId, userId, payload)` のみ使用する
- テナント宛: `sendNotificationToTenant(tenantId, payload)` のみ使用する
- `this.server.emit()` によるブロードキャスト配信は禁止する（テナント分離が破綻する）

> 根拠: [ADR-3](adr/rest-websocket-separation.md)

### 4.2 Room 管理

- クライアントから送信された Room 名をそのまま信頼してはいけない
- JWT から取得した `tenantId` と `userId` のみで Room 参加を許可する（JWT 認証実装後）

## 5. 責務サマリ

| 担当 | やること | 使う I/F |
|---|---|---|
| アプリチーム (FE) | 通知受信・表示の初期化 | `useNotification()` をルートレイアウトで呼ぶ |
| アプリチーム (FE) | 通知履歴の参照・既読管理 | `useNotificationStore()` |
| アプリチーム (FE) | ログアウト時のクリア | `resetAllStores()` に包含（自動） |
| アプリチーム (BFF) | 通知の送信 | `sendNotificationToUser()` / `sendNotificationToTenant()` |
| 基盤チーム | Socket 接続・Room 参加・再接続 | `useNotification` 内部で自動処理 |
| 基盤チーム | 通知履歴の永続化 | `notification.store` 内部で自動処理 |
