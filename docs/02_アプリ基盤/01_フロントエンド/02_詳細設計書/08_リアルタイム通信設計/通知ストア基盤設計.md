# 通知ストア基盤設計

> 規約: [リアルタイム通信規約.md](./リアルタイム通信規約.md) §2.1 の通り、通知履歴の参照・操作は `useNotificationStore` 経由とする。

## 1. ファイル配置

| ファイル | 配置パス | 役割 |
|---|---|---|
| `notification.store.ts` | `frontend/src/shared/stores/` | 通知履歴・既読状態を管理する Zustand ストア |

---

## 2. 公開 I/F

### 2.1 `useNotificationStore`

```typescript
import { useNotificationStore } from '@/shared/stores/notification.store';

/**
 * 通知履歴・既読状態を管理する Zustand ストア。
 *
 * @remarks
 * - `persist` ミドルウェアにより LocalStorage（キー: `notification-storage`）に永続化される。
 * - 通知履歴は最新 100 件のみ保持し、超過分は自動削除される。
 * - ログアウト時は `resetAllStores()` により自動クリアされる（手動クリア不要）。
 * - タブ間のリアルタイム既読同期は現時点では未対応（BroadcastChannel API は将来実装）。
 */
function useNotificationStore(): NotificationStore
```

**呼び出し例**:

```tsx
import { useNotificationStore } from '@/shared/stores/notification.store';

// 通知一覧パネルの例
export function NotificationPanel() {
  const { notifications, unreadCount, markAsRead, markAllAsRead } = useNotificationStore();

  return (
    <div>
      <span>未読: {unreadCount}</span>
      <button onClick={markAllAsRead}>全て既読</button>
      {notifications.map((n) => (
        <div key={n.notificationId} onClick={() => markAsRead(n.notificationId)}>
          {n.title}
        </div>
      ))}
    </div>
  );
}
```

## 3. State 型定義

```typescript
import type { NotificationMessageResponse } from '@front_bff_shared/features/notification/realtime/types/responses/notification-message.response';

interface NotificationStore {
  // State
  notifications: NotificationMessageResponse[];
  unreadCount: number;

  // Actions
  /**
   * 受信した通知を履歴の先頭に追加する。
   * @remarks 追加後に最新 100 件を超えた分は自動削除される。
   */
  addNotification: (notification: NotificationMessageResponse) => void;

  /**
   * 指定した通知を既読にする。
   * @param notificationId - 既読にする通知の UUID
   */
  markAsRead: (notificationId: string) => void;

  /**
   * 全通知を既読にする。
   */
  markAllAsRead: () => void;

  /**
   * 全通知履歴を削除する。
   * @remarks ログアウト時は `resetAllStores()` から自動呼び出しされるため、直接呼び出し不要。
   */
  clearNotifications: () => void;
}
```

## 4. 永続化設定

| 項目 | 値 | 説明 |
|---|---|---|
| ミドルウェア | `persist` | Zustand 標準の永続化ミドルウェア |
| ストレージ | `localStorage` | ブラウザ再起動後も通知履歴を保持 |
| LocalStorage キー | `notification-storage` | 他ストアのキーと競合しないよう命名 |
| 履歴上限 | 最新 100 件 | `notifications.slice(0, 100)` で自動制限 |

---

## 5. マルチテナント安全性

- ログアウト時は `resetAllStores()`（状態管理設計 §4 参照）が通知ストアを含む全ストアをリセットする
- `clearNotifications()` を直接呼び出す必要はない
- 通知データには `tenantId` が含まれないが、ログアウト時のクリアにより他テナントのデータ残留を防止する
