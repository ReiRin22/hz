## 2. キー構造の契約

### 2.1 ユーザー定義キー（必須構造）

```typescript
// 各ドメインの factory 関数が返す queryKey 配列の構造
type UserDefinedKey = readonly [tenantId: string, params?: object];
```

| 要素 | 必須 | 内容 |
|---|---|---|
| `tenantId` | ✅ | ログイン中のテナント ID。第1階層に固定し、別テナントとの参照を物理的に隔離する |
| `params` | ⏸ | 検索条件・ページング情報・ID 等の動的パラメータ |

### 2.2 実際に生成されるキー（factory 自動付与込み）

```typescript
type ActualQueryKey = readonly [
  domain: string,    // factory 自動付与（`createQueryKeyStore` のキー）
  scope: string,     // factory 自動付与（domain 内のメソッド名）
  tenantId: string,  // ユーザー定義（必須）
  params?: object    // ユーザー定義（任意）
];
```

### 2.3 例

```typescript
// 呼び出し
queries.diagnosis.patientList('tenant-001', { page: 1 })

// 生成される queryKey
['diagnosis', 'patientList', 'tenant-001', { page: 1 }]
//  ^^^^^^^^^^^^^^^^^^^^^^^ factory 自動付与
//                          ^^^^^^^^^^^^^^^^^^^^^^^^^^^ ユーザー定義
```

## 3. queryKeyStore の I/F

### 3.1 エクスポート

```typescript
import { createQueryKeyStore } from '@lukemorales/query-key-factory';

/**
 * 全クエリキーを一元管理する factory ストア。
 *
 * @remarks
 * - ドメイン単位（`createQueryKeyStore` の第1階層キー）にエントリを追加する。
 * - 各メソッドの戻り値は `{ queryKey: [tenantId, params?] }` 構造の必要がある。
 * - `useQuery` / `invalidateQueries` / `removeQueries` 等のキー指定は本ストア経由で行う。
 */
export const queries: QueryKeyStore;
```

### 3.2 ドメインエントリの追加方法

新ドメイン・新スコープの追加はアプリ実装チームが行う（基盤提供は雛形のみ）。

```typescript
export const queries = createQueryKeyStore({
  // ドメイン名（ディレクトリ構成 LV1 に準拠）
  diagnosis: {
    // スコープ名（リソース・機能単位）
    patientList: (tenantId: string, filters?: { search?: string; page?: number }) => ({
      queryKey: [tenantId, filters],
    }),
    patientDetail: (tenantId: string, patientId: string) => ({
      queryKey: [tenantId, patientId],
    }),
    // ...
  },
  master: {
    staff: (tenantId: string) => ({
      queryKey: [tenantId],
    }),
  },
  medicalRecords: {
    list: (tenantId: string, patientId: string, filters?: { from?: string; to?: string }) => ({
      queryKey: [tenantId, patientId, filters],
    }),
    detail: (tenantId: string, recordId: string) => ({
      queryKey: [tenantId, recordId],
    }),
  },
});
```

> 各 factory メソッドは **第1引数を `tenantId`** とし、`queryKey` 配列の先頭に配置すること（[状態管理規約.md](状態管理規約.md) §3）。

### 3.3 `_def` プロパティ（factory 自動付与）

`@lukemorales/query-key-factory` は各ドメイン・各スコープに `_def` を自動付与する。

| プロパティ | 値 | 用途 |
|---|---|---|
| `queries.diagnosis._def` | `['diagnosis']` | ドメイン全体の階層識別子 |
| `queries.diagnosis.patientList._def` | `['diagnosis', 'patientList']` | スコープの階層識別子 |

## 4. 利用パターン

### 4.1 useQuery

```typescript
import { queries } from '@/shared/keys/queryKeyStore';

export const useGetPatients = (filters: PatientFilters) => {
  const { currentTenantId } = useTenantStore();

  return useQuery({
    queryKey: queries.diagnosis.patientList(currentTenantId, filters).queryKey,
    queryFn: () => fetchPatientList(currentTenantId, filters),
    staleTime: 1000 * 60,
    gcTime: 1000 * 60 * 5,
  });
};
```

> `staleTime` / `gcTime` / `refetchOnWindowFocus` の標準値は [状態管理規約.md](状態管理規約.md) §2 を参照。

### 4.2 invalidateQueries（ドメイン単位の無効化）

```typescript
export const useSaveDiagnosis = () => {
  const queryClient = useQueryClient();
  const { currentTenantId } = useTenantStore();

  return useMutation({
    mutationFn: (data: DiagnosisFormData) => saveDiagnosis(currentTenantId, data),
    onSuccess: () => {
      // diagnosis ドメイン配下を一斉無効化
      queryClient.invalidateQueries(queries.diagnosis._def);
    },
  });
};
```

### 4.3 removeQueries（テナント条件で安全に削除）

`_def` を直接渡すと **scope 配下の全テナント分** が削除される。テナント条件を AND する `predicate` を使用する。

```typescript
// ドメイン全体を「現テナント分のみ」削除
queryClient.removeQueries({
  predicate: (query) => {
    const key = query.queryKey as readonly unknown[];
    // key[0] = domain, key[1] = scope, key[2] = tenantId
    return key[0] === 'diagnosis' && key[2] === currentTenantId;
  },
});
```

特定リソース（例: 患者 ID 指定）に絞る場合は `JSON.stringify` で完全一致比較する。

```typescript
// 特定患者のキャッシュのみ削除
const targetKey = queries.diagnosis.patientDetail(currentTenantId, patientId).queryKey;
queryClient.removeQueries({
  predicate: (query) => JSON.stringify(query.queryKey) === JSON.stringify(targetKey),
});
```

### 4.4 全削除（ログアウト時）

ログアウト時は `queryClient.clear()` を使用する（[クリーンアップ基盤設計.md](クリーンアップ基盤設計.md) §3 Step 1）。

---

## 5. 無効化／削除 API 対比

| 操作 | API | 効果 | 主な用途 |
|---|---|---|---|
| 無効化 | `invalidateQueries(_def)` | 「stale」マークのみ。次回参照時に再取得 | Mutation 後の同期、画面表示時の鮮度確保 |
| 削除（条件付き） | `removeQueries({ predicate })` | キャッシュ自体を破棄 | テナント切替・特定リソースの強制リセット |
| 全削除 | `queryClient.clear()` | 全ドメイン・全テナントのキャッシュを破棄 | ログアウト時 |
