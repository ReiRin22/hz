# ADR-4: ログアウト時はハードリダイレクトを必須とする

* **ステータス**: Accepted
* **決定日**: 2026-05-12
* **関連設計書**: [クリーンアップ基盤設計.md](../クリーンアップ基盤設計.md) §ログアウトシーケンス Step 4
* **関連 ADR**: [logout-step-order.md](logout-step-order.md)

## 背景

電子カルテはマルチテナント環境で運用される。ログアウト後に別テナントでログインし直した際、前テナントのデータ（メモリ上のJS変数・React コンポーネントの内部状態・サードパーティ SDK が握る変数等）が残存していると、別病院の患者情報が画面に表示されるなどの重大事故に直結する。

`queryClient.clear()` と `resetAllStores()` で React Query キャッシュ・Zustand ストアの状態は初期化できるが、以下はカバーできない。

* React の Reconciler が握っているコンポーネント内ローカル state
* `useRef` 等で保持されたミュータブルな参照
* サードパーティ SDK（Sentry、計測ツール、Socket.io クライアント等）が内部で持つ変数
* メモリリークによる残留オブジェクト

## 検討した選択肢

### 案A: ソフトリダイレクト（`router.push('/login')`）
* **メリット**: 高速。Next.js のクライアントサイドルーティングを活かせる。
* **デメリット**: JS ランタイムが継続するため、上記の残留オブジェクトを抱えたままログイン画面に遷移する。`queryClient.clear()` 等で対処漏れがあった場合、検出が困難。

### 案B: ハードリダイレクト（`window.location.href = '/login'`）
* **メリット**: ブラウザがページを完全に再ロードし、JS ランタイムごと初期化される。残留オブジェクトの心配が原理的に不要。
* **デメリット**: 再ロード分のレイテンシが発生する。HTML/JS の再ダウンロードが必要（キャッシュは効くが、解析・実行は走る）。

### 案C: `window.location.reload()` 後に遷移
* リロード後に `/login` へ移動する2ステップ案。Bが1ステップで同等の効果を得られるため不採用。

## 決定

**案B を採用する**。

* ログアウト時は `window.location.href = '/login'` を **例外なく** 使用する。
* ソフトリダイレクト（`router.push()` / `router.replace()`）は通常の画面遷移にのみ使用する。
* 認証エラー時の自動ログアウト（401 応答時）も同経路（`useTenantCleanup` 経由）を通すこと。

## 影響

### 正の影響
* JS ランタイムごと初期化されるため、Step 0〜3 の部分失敗（例: WebSocket 切断失敗、persist 書き戻しの想定外動作）が次回ロード時に確実に解消される。
* マルチテナント安全性のガードレールとして「最後の砦」を提供する。
* 将来サードパーティ SDK が増えても、各 SDK のクリーンアップ API を個別に呼ぶ必要がない。

### 負の影響
* ログアウト所要時間がソフト遷移より長くなる（数百ms〜1s 程度）。
* オフラインキャッシュ（Service Worker）等のキャッシュ戦略と相互作用する可能性がある。

### 見直しトリガー
* Service Worker / オフラインモード対応で、ハードリダイレクトが UX 上致命的になった場合。
* React 19 以降で「ルートからの完全な再マウント」が標準提供された場合、ソフト方式での同等保証が可能か再評価する。
