# エラーハンドリング統合設計

BFF が返却するエラーレスポンスを、フロントエンドへ統一フォーマットで返すための Filter 配線・Service 層の捕捉パターンを定義する。

> 規約は [BFF設計規約.md §2](BFF設計規約.md#2-基盤-if-利用規約最重要) を参照。
> 統一エラーレスポンスのフォーマットは [09章 BFFエラーレスポンス設計](../09_監視エラーハンドリング設計/BFFエラーレスポンス設計.md) を参照。

---

## 1. グローバル Exception Filter 構成

NestJS のルートモジュール（`app.module.ts`）に以下の2つを **グローバル Filter** として登録する。

| フィルタ | 役割 | 捕捉対象 |
|---|---|---|
| `ZodExceptionFilter` | Zod スキーマ検証失敗を統一フォーマットに変換 | `ZodError`（HTTP 400） |
| `HttpExceptionFilter` | 上記以外の全例外を統一フォーマットに変換 | `HttpException` 派生クラス・未捕捉例外（HTTP 401〜504） |

両者ともレスポンスは [09章 BFFエラーレスポンス設計](../09_監視エラーハンドリング設計/BFFエラーレスポンス設計.md) の統一フォーマット（`{ title, status, detail, instance, errors[], traceId }`）で返す。

---

## 2. HTTP ステータス別の処理方針

| 発生源 | BFF での処理 | 返却ステータス | 主な `errors[].code` |
|---|---|:---:|---|
| Controller 層の入力バリデーション失敗（Zod） | `ZodExceptionFilter` が `ZodError` を捕捉して統一フォーマットに変換 | 400 | `REQUIRED` / `INVALID_FORMAT` / `INVALID_TYPE` |
| 業務ルール違反（例: 自動連携行の削除試行） | Service 層で `BusinessException` を throw、`HttpExceptionFilter` が変換 | 400 | `VALIDATION_DELETE` 等の機能固有コード |
| 認証失敗（JWT 検証失敗） | `AuthGuard` が `UnauthorizedException` を throw、`HttpExceptionFilter` が変換 | 401 | `UNAUTHORIZED` |
| 認可失敗（権限不足） | バックエンド 403 を捕捉、`HttpExceptionFilter` が変換 | 403 | `FORBIDDEN` |
| バックエンド API の 404 | エラー内容を解釈、`HttpExceptionFilter` が変換 | 404 | `NOT_FOUND` |
| 排他競合（編集ロック・期限切れ） | バックエンド 409 を捕捉、`errors[].meta.lockedByUserName` を付与 | 409 | `CONFLICT` |
| バックエンド API の 5xx | `HttpExceptionFilter` が `502 Bad Gateway` に変換 | 502 | `BAD_GATEWAY` |
| バックエンド API の接続タイムアウト | `HttpExceptionFilter` が `504 Gateway Timeout` に変換 | 504 | `TIMEOUT` |
| BFF 内部のサーバーエラー（未捕捉例外） | `HttpExceptionFilter` が `500 Internal Server Error` に変換 | 500 | `SYSTEM_ERROR` |

## 3. ZodExceptionFilter

| 項目 | 内容 |
|---|---|
| 配置 | `bff/src/shared/filters/zod-exception.filter.ts` |
| 16章マスター登録 | No.38（参照章: 03章） |
| 捕捉対象 | `ZodError`（Controller 層で `parse()` を呼んだ時に発生） |
| 返却ステータス | 400 |
| アプリ実装者の責務 | Controller 層で Zod スキーマの `parse()` を呼ぶのみ。エラー応答の組み立ては不要 |

### 3.1 アプリ実装パターン

```typescript
@Controller('users')
@UseGuards(AuthGuard)
export class UserController {
  @Post()
  async createUser(@Body() body: unknown) {
    const validated = userCreateSchema.parse(body);  // 失敗時 ZodError → ZodExceptionFilter が 400 に変換
    return this.userService.create(validated);
  }
}
```

> 実装の詳細（`ZodExceptionFilter` のコード例・Zod 内部コードからプロジェクトコードへの変換）は [03_TypeScript型管理/BFFバリデーション基盤設計.md §2](../03_TypeScript型管理/BFFバリデーション基盤設計.md#2-zodexceptionfilter-公開-if) を参照。
> Controller 層で `parse()` を直接呼ぶ実装ルールは `.claude/skills/app-bff-zod-validation/SKILL.md` を参照。

## 4. HttpExceptionFilter

| 項目 | 内容 |
|---|---|
| 配置 | `bff/src/shared/filters/http-exception.filter.ts` |
| 捕捉対象 | NestJS の `HttpException` 派生クラス（`UnauthorizedException` / `BusinessException` / `NotFoundException` 等）および未捕捉例外 |
| 返却フォーマット | [09章 BFFエラーレスポンス設計](../09_監視エラーハンドリング設計/BFFエラーレスポンス設計.md) の統一フォーマット |
| `errors[].code` 割り当て | HTTP ステータス → コードのマッピングは [09章 BFFエラーレスポンス設計 §3 `errors[].code` 一覧](../09_監視エラーハンドリング設計/BFFエラーレスポンス設計.md#3-errorscode-一覧) を参照 |
| `errors[].meta` 付与例 | CONFLICT 時の `lockedByUserName` 等は同セクションを参照 |

## 5. Service 層のエラー捕捉パターン

Client へのパラメータ渡しはオブジェクト形式を標準とする（フィルタ条件追加時にシグネチャを変えずに拡張可能・POST/PUT 系と書き方を統一できるため）。

```typescript
async getUserFullDetails(id: string): Promise<UserGetResponse> {
  try {
    const [base, profile] = await Promise.all([
      this.client.fetchBase({ targetId: id }),
      this.client.fetchProfile({ targetId: id }),
    ]);
    return this.mapToViewModel(base, profile);
  } catch (error) {
    // バックエンドAPIエラーを BFF 固有の例外に変換（HttpExceptionFilter が統一フォーマットに整形）
    throw new ServiceUnavailableException('データ取得に失敗しました');
  }
}
```

| 規約 | 内容 |
|---|---|
| ✅ 必須 | バックエンド API エラーは BFF 固有の `HttpException` 派生に変換して throw する |
| ✅ 必須 | 業務ルール違反は専用例外（`BusinessException` 等）を throw する |
| ⛔ 禁止 | Controller / Service でレスポンス Body を手組み（`res.status().json()` 等）する |
| ⛔ 禁止 | エラーを握りつぶして正常レスポンスを返す（フロント側のキャッシュ整合崩壊の原因） |

## 6. フロントエンドとの責務分担

| レイヤー | 役割 |
|---|---|
| BFF（本章） | 全エラーを統一フォーマットに変換し HTTP ステータスで返却 |
| フロントエンド（[09章](../09_監視エラーハンドリング設計/監視エラーハンドリング規約.md)）| 統一フォーマットを解釈してトースト・モーダル・リダイレクト等の UI を制御 |
