# ADR-8: Breadcrumbs と 14章操作ログを別経路にする

* **ステータス**: Accepted
* **決定日**: 2026-05-22
* **関連設計書**: [GlitchTip連携設計.md](../GlitchTip連携設計.md) §3.1, [監視エラーハンドリング規約.md](../監視エラーハンドリング規約.md) §1
* **関連 ADR**: なし

## 背景

ユーザーの操作履歴を記録する仕組みは本プロジェクトに 2 種類存在する。

* **Breadcrumbs（09章）**: Sentry SDK が自動収集し、エラー発生時に GlitchTip イベントへ添付される「エラー直前の操作履歴」
* **操作ログ（14章）**: 業務証跡として全操作を常時記録し、監査目的で長期保存される

両者を「ユーザー操作の記録」として一元化したい誘惑があるが、目的・要件・保存先・参照者がそれぞれ異なる。

## 検討した選択肢

### 案A: 両者を一元化（GlitchTip Breadcrumbs を業務証跡としても流用、または逆方向）
* **メリット**: 操作記録を 1 箇所で管理できる
* **デメリット**: GlitchTip はエラー発生時にしか送信されないため、エラーが起きない正常系操作の記録が残らない。逆に 14章の操作ログを Breadcrumbs に流すと、エラー時の文脈が大量の業務証跡で埋もれる。法的証拠としての要件（改竄防止・長期保存）を Breadcrumbs では満たせない

### 案B: 両者を完全に別経路で管理
* **メリット**: 各々の目的・要件に最適化できる。Breadcrumbs は開発調査用、操作ログは法的証跡として明確化される
* **デメリット**: 同じ操作が 2 箇所に記録される（情報の重複）

## 決定

**案B を採用する**。

* **Breadcrumbs（本章）**: Sentry SDK が自動収集（最大50件）。エラー発生時のみ GlitchTip イベントへ添付。開発調査用であり、**法的証拠ではない**
* **操作ログ（14章）**: アプリ実装者が `axiosClient` 経由で BFF に送信。監査ログ DB に長期保存される業務証跡

両者の使い分けは [監視エラーハンドリング規約.md](../監視エラーハンドリング規約.md) §1 で明示する。

## 影響

### 正の影響
* 各経路が目的に最適化される（エラー調査用 vs 監査証跡）
* 14章の監査ログ要件（改竄防止・長期保存）を 09章で気にする必要がない
* GlitchTip ストレージが業務証跡で消費されない

### 負の影響
* 同じ操作が 2 箇所に記録される（情報の重複）
* アプリ実装者が「これは Breadcrumbs か操作ログか」を判断する場面で混乱が発生しうる（規約での明示が必要）

### 見直しトリガー
* 14章の監査ログを GlitchTip と統合する全社方針が出た場合
* Breadcrumbs を法的証跡として認めるホスティング・監査要件が整備された場合
