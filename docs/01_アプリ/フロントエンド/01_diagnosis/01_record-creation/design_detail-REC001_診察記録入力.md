# フロントエンド個別詳細設計書_【REC001】診察記録入力

## 文書概要

- **目的**: 医師・研修医が患者の主訴・現病歴・身体所見・診断・治療方針などをSOAP形式で電子的に記録し、多職種間で共有する機能
- **対象システム／サブシステム**: 【REC001】診察記録入力
- **対象範囲**
  - 本書は「【REC001】診察記録入力画面」の詳細設計を示す。
- **用語定義**

| 用語 | 説明 |
| --- | --- |
| 診察記録 | SOAP形式で記録する患者の診療情報 |
| 下書き | 一時保存された未確定の診察記録 |
| Myコメント | ユーザーが登録した定型コメント |
| 確定 | 診察記録を正式保存する操作 |
| 承認待ち | クラーク代行入力後、医師の承認を待つ状態 |
| 編集可能期間 | 記載日から管理者設定日数（初期値30日）以内 |

- **参照資料**
  - 個別機能設計書_診察記録入力（design-REC001_診察記録入力.md）
    ※ 本設計は上記機能設計書に基づき作成する。

- **入力制御（必須、文字種、桁数）**
  - 以下の形式的入力制御のみを実施する
    - 桁数制限（診察記録: 1000文字、コメント内容: 200文字）
    - 文字種制限（禁則文字: `<>` など）
    - 日付形式・未来日禁止（記載日）
  - 業務的な妥当性チェックは実装しない
  - APIレスポンスを正とし、独自判定は禁止

- **UI制御**
  - 記載日：新規作成時のみ活性。修正時は非活性（変更不可）
  - 下書きボタン：一時保存データが1件以上存在する場合のみ表示
  - 音声・コメント・テンプレート・シェーマ・文字装飾・一時保存：記載権限なし（看護師）の場合は非活性
  - 確定ボタン押下後：確定ボタンを非活性化する（多重送信防止）
  - Myコメント管理の保存ボタン：内容フィールドが空の場合は非活性
  - 編集可能期間超過の診察記録：診察記録テキストエリアを非活性（参照のみ）
  - コメント選択ポップアップ：常に最前面表示。×ボタンまたはEscキーで閉じる

## 画面遷移／状態管理

- 遷移元：なし（カルテ画面から直接表示）
- 遷移先：【REC002】シェーマ作成（シェーマボタン押下時）
- **状態管理**
  - 新規作成モード：カルテ画面から診察記録入力を開いた場合
  - 修正モード：既存診察記録の編集時。記載日は非活性
  - 確定ボタン押下時に非活性にする
- **多重送信対策**
  - 確定ボタン押下後は再操作不可とし、APIの多重呼び出しを防止する

- **遷移 or API 呼び出し**
  - カルテ画面から診察記録入力を開く
    - [`GET /bff/records/{patientId}/soap`]()を実行する（修正モード時）
      - 成功: 既存診察記録を読み込んで表示する
      - 失敗: 共通エラーダイアログを表示する
    - 新規作成モード時は API 呼び出しなし

  - [一時保存]ボタン押下
    - フロントエンドバリデーションを実行する
    - [`POST /bff/records/{patientId}/soap/draft`]()を実行する
      - 成功: 下書き保存完了。下書きボタンを表示する
      - 失敗: 共通エラーダイアログを表示する

  - [確定]ボタン押下
    - フロントエンドバリデーションを実行する
      - 記載日が未来日の場合（E001）: エラーラベルを表示し処理を中断する
      - 禁則文字が含まれる場合（E002）: エラーラベルを表示し処理を中断する
    - 確定ボタンを非活性化する
    - [`POST /bff/records/{patientId}/soap`]()（新規）または[`PUT /bff/records/{patientId}/soap/{soapId}`]()（修正）を実行する
      - 成功（医師・研修医）: 「確定」に更新。画面を閉じる
      - 成功（クラーク）: 「承認待ち」に更新
      - 失敗: 共通エラーダイアログを表示する。確定ボタンを再活性化する

  - [シェーマ]ボタン押下
    - 現在の入力内容を保持した状態で【REC002】シェーマ作成画面に遷移する
    - 戻り時にシェーマデータを診察記録テキストエリアの現在カーソル位置に挿入する

  - [コメント]ボタン押下
    - [`GET /bff/comments?type={type}&patientId={patientId}`]()を実行する
      - 成功: コメント選択ポップアップを表示する
      - 失敗: 共通エラーダイアログを表示する

  - [Myコメント管理の保存]ボタン押下
    - [`POST /bff/comments/my`]()または[`PUT /bff/comments/my/{commentId}`]()を実行する
      - 成功: コメント一覧を更新する
      - 失敗: 共通エラーダイアログを表示する

- **前提条件（ロール・ステータス）**
  - ロール：　[医師]、[研修医]、[看護師]、[医療事務作業補助者（クラーク）]
  - 看護師は参照のみ。入力・確定操作は不可

## 占有制御における操作状態の定義

本画面では、編集ロックの延長判定に使用するため、ユーザーの操作状態を以下の通り定義する。

### 操作状態（操作あり）

以下のいずれかが検知された場合、「操作あり」と判定する。

- マウス操作（クリック、ダブルクリック）
- キーボード入力（keydown、input 等）
- フォーカス変更
- ボタン押下、選択変更などの明示的なUI操作
- API通信を伴う画面操作

### 無操作状態

- 一定時間、操作状態が検知されない状態

※一定時間の閾値は占有制御仕様に従う。

### ロック延長トリガ

- 操作状態が検知された場合、ロック延長処理を実施する
- 無操作状態が継続した場合、ロック延長処理は行わない
