## 実装対象範囲

  - UI / 状態表示 / 操作イベント / Canvas描画制御

## 文書概要

- **目的**: 診察記録にシェーマ（医療図表）を作成・添付できる機能
- **対象システム／サブシステム**: 【REC002】シェーマ作成
- **対象範囲**
  - 本書は「【REC002】シェーマ作成画面」の詳細設計を示す。
- **用語定義**

| 用語 | 説明 |
| --- | --- |
| シェーマ | 患部や所見を図示した医療図表 |
| テンプレート | 人体の部位別に用意された描画の下地となる図 |
| 確定 | 描画内容を確定し、Base64画像として親画面に返す |
| キャンセル | 描画内容を破棄し、画面を閉じる |
| 元に戻す/やり直す | 操作履歴の巻き戻し・やり直し機能 |
| お気に入り | よく使うテンプレートをマークする機能 |

- **UI制御**
  - BTN_UNDO：`undoStack.length === 0` の場合は非活性
  - BTN_REDO：`redoStack.length === 0` の場合は非活性
  - BTN_CLEAR：`hasDrawContent === false` の場合は非活性
  - BTN_FLIP：`hasDrawContent === false` の場合は非活性（白紙時は操作不可）
  - ツールボタンは排他選択（1つのみアクティブ）。選択中ツールは視覚的に強調表示
  - 確定ボタン押下後：isSubmitting を true にして非活性化（多重送信防止）。API失敗時は false に戻す
  - GRID_TEMPLATES：お気に入り登録済みテンプレートは同一カテゴリ内の先頭に表示
  - 画像取込：image/png, image/jpeg のみ許可。取込画像はキャンバス中央に配置（アスペクト比維持）
  - キャンセル確認ダイアログの編集内容判定（`hasDrawContent` を参照）
    - `undoStack.length === 0`（初期状態）の場合：ダイアログなしで直接 onCancel 呼び出し
    - `undoStack[undoStack.length - 1].type === 'clear'`（最新操作がクリア）の場合：ダイアログなしで直接 onCancel 呼び出し
    - 上記以外（`hasDrawContent === true`）：キャンセル確認ダイアログを表示

## 画面遷移／状態管理

- 遷移元／遷移先：【REC001】診察記録入力の「シェーマ」ボタン
- **状態管理**
  - キャンセルボタン押下時、編集内容がある場合は確認ダイアログを表示
  - クリア実行直後または初期状態（履歴位置が0）の場合、キャンセル時は確認なしで直接閉じる
  - 白紙状態での反転操作は履歴に保存しない
  - 元に戻す／やり直すボタンは操作履歴の存在に応じて活性制御
  - クリアボタンは描画内容の存在に応じて活性制御
- **多重送信対策**
  - 確定ボタン押下後は再操作不可とし、APIの多重呼び出しを防止する

- **遷移 or API 呼び出し**
  - 【REC001】診察記録入力の[シェーマ]ボタン押下
    - 画面マウント時の初期化（呼び出し順序）
      1. **並列実行**（順序依存なし）: [`GET /bff/templates?category=全身`]() と [`GET /bff/favorites`]() を同時に呼び出す
      2. **直列実行**（編集モードのみ）: テンプレート一覧・お気に入り取得完了後に [`GET /bff/schemas/{schemaUuid}`]() を実行し、取得データをキャンバスに描画する
         - 新規作成モードの場合: 手順2はスキップし空白キャンバスで表示する
    - 各APIの失敗処理
      - `GET /bff/templates` 失敗：共通エラーダイアログを表示しテンプレートパネルをエラー表示にする
      - `GET /bff/favorites` 失敗：お気に入り状態を空配列で初期化して処理を続行する（非致命的）
      - `GET /bff/schemas` 失敗：共通エラーダイアログを表示する
  - [部位選択]ドロップダウン変更
    - [`GET /bff/templates?category={category}`]()を実行しテンプレート一覧を更新する
      - 成功：選択した部位のテンプレートをお気に入り順で表示する
      - 失敗：共通エラーダイアログを表示する
  - [テンプレートサムネイル]押下
    - 描画内容がある場合：確認ダイアログ（E005）を表示する
      - 「はい」：テンプレートを背景に設定し描画履歴スタックをクリアする
      - 「いいえ」：ダイアログを閉じて操作をキャンセルする
    - 描画内容がない場合：そのままテンプレートを背景に設定する
  - [☆ お気に入りボタン]押下（楽観的更新）
    - `favoriteTemplateIds` を即座に更新しUIに反映する（楽観的更新）
    - 未登録の場合：[`POST /bff/favorites`]()を実行する
    - 登録済みの場合：[`DELETE /bff/favorites/{templateId}`]()を実行する
      - 成功：そのまま（楽観的更新の結果が正）
      - 失敗：`favoriteTemplateIds` を元の状態にロールバックしテンプレート一覧の並び順を復元する。共通エラーダイアログを表示する
  - [確定]ボタン押下
    - 描画エリアが空白の場合（E002）：空白確定確認ダイアログを表示する
      - 「確定」を選択：次処理へ
      - 「キャンセル」：処理を中断する
    - 確定ボタンを非活性化する
    - [`POST /bff/schemas`]()（新規）/ [`PUT /bff/schemas/{schemaUuid}`]()（更新）を実行する
      - 成功：APIレスポンスの `schemaUuid` と Canvas の Base64 画像データをコールバック関数 `onConfirm(schemaUuid, base64Image)` で親コンポーネント（REC001）に渡し画面を閉じる
      - 失敗：共通エラーダイアログを表示する。確定ボタンを再活性化する（isSubmitting を false に戻す）
  - [キャンセル]ボタン押下
    - 編集内容がある場合：キャンセル確認ダイアログを表示する（E003）
      - 「破棄」：変更を保存せずに画面を閉じる
      - 「キャンセル」：ダイアログを閉じて編集を継続する
    - 編集内容がない場合：そのまま画面を閉じる

- **前提条件（ロール・ステータス）**
  - ロール：　[医師]、[研修医]、[医療事務作業補助者（クラーク）]
  - ステータス：　診察記録画面が開かれていること

## AI実装制約

### 操作イベント定義

**8.1.1 操作イベント詳細定義（業務的）**

| イベントID | 操作種別 | 呼び出しAPI | 冪等性 | 監査ログ対象 | 備考 |
| --- | --- | --- | --- | --- | --- |
| EVT_INIT01 | 初期表示 | GET /bff/templates, GET /bff/favorites（並列）/ GET /bff/schemas（編集時のみ・直列） | 不要 | 非対象 | キャンバスを白背景で初期化し初期状態を履歴に保存。テンプレート一覧・お気に入り情報を並列取得。編集時はさらに既存シェーマを取得してキャンバスに描画 |
| EVT_CONFIRM | 確定 | POST/PUT /bff/schemas | 必須 | 対象 | Canvas画像をBase64エンコードして親に返す。REC001カーソル位置へ挿入。監査ログ記録 |
| EVT_CANCEL | キャンセル | なし | 不要 | 非対象 | 変更内容を破棄して画面を閉じる |
| EVT_FAVORITE_TOGGLE | 編集 | POST/DELETE /bff/favorites | 不要 | 非対象 | お気に入り状態をサーバーに保存（ユーザー単位管理） |

- イベントIDは監査ログおよびBFF連携で使用する
- 設計書に存在しないイベントは実装禁止
- EVT_CONFIRM は監査ログ対象のため、BFF経由でバックエンドに保存される

## 状態管理ルール（画面固有）
