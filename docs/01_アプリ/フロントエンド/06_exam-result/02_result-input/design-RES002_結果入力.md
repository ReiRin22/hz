## 3. 画面レイアウト

本機能は以下の画面・ダイアログで構成される。

- 検査科指示受け画面（遷移元）
- 検査結果入力画面（メイン）
- 検査結果修正理由ダイアログ
- 検査項目検索ダイアログ

> **設計メモ（議事録より）**
> - 項目追加は「案2」方式を採用：項目追加ボタン押下 → 検索画面展開・項目選択 → 元の「検査結果入力画面」に選択項目が追加された状態で直接入力
> - 検査結果画面での項目追加は代行入力扱いのため、指示受けで結果入力画面を押下した場合は代行入力確認画面への遷移要否を確認済み（カルテとの整合性を考慮し、代行入力側でオーダー修正を基本とする方針）
> - 一時保存機能は不要
> - 結果アップロード（外注/検査システム連携）は部門指示受け側で実施。期間指定機能を追加する方針

### エラーメッセージ一覧

| エラーメッセージID | メッセージ内容（日本語） | 備考・発生条件 |
|---|---|---|
| E001 | 数値で入力してください | 結果値に数値以外が入力された場合（フロントバリデーション） |
| E002 | 下限値は上限値以下で入力してください | 基準値の下限が上限を超える場合（フロントバリデーション） |
| E003 | 自動連携された結果項目が含まれているため削除できません | 自動連携行を削除しようとした場合（HTTP 400 / VALIDATION_DELETE） |
| E004 | 認証に失敗しました | 確定API実行時に認証エラー（HTTP 401 / UNAUTHORIZED） |
| E005 | 権限がありません | 確定API実行時に権限不足（HTTP 403 / FORBIDDEN） |
| E006 | データが存在しません | データ取得時にリソース不存在（HTTP 404 / NOT_FOUND） |
| E007 | 別ユーザーが編集しています | 編集ロック競合または期限切れ（HTTP 409 / CONFLICT） |
| E008 | 入力内容に不正な値が含まれています | 確定API実行時にリクエスト形式不正（HTTP 400 / VALIDATION_FORMAT） |

| E998 | システムエラーが発生しました | 検査項目一覧取得失敗（HTTP 502 / BAD_GATEWAY） |

## 5. 操作フロー／イベント仕様

### 検査結果入力画面

| No | 操作 | イベント内容 | 処理内容 |
|---|---|---|---|
| 1 | タブ操作（検査結果入力） | 表示内容切り替え | 結果入力（RES002）を表示する |
| 2 | タブ操作（検査結果参照） | 表示内容切り替え | 検査結果参照画面（REC008）が表示される |
| 3 | 項目追加ボタン押下 | 検査結果項目の追加 | PRI001代行入力確認ダイアログ読出しを実行する。成功時はダイアログを表示する。[はい]押下後（または医師・臨床検査技師ロールの場合）にGET /bff/test-itemsを実行し、成功時は検査項目検索ダイアログを表示する |
| 4 | 選択行削除ボタン押下 | 検査結果項目の削除 | チェック選択されている各行を確認し、自動連携された行が含まれる場合はエラーメッセージ（E003）を表示する。手動入力行のみの場合は該当行を削除する |
| 5 | 確定ボタン押下 | 検査結果確定 | フロントバリデーション（E001/E002）を実行する。初回登録時は確定APIを実行する。確定済み再登録時（reasonRequired=true）は修正理由ダイアログを表示後に確定APIを実行する。成功時は画面を閉じる |
| 6 | キャンセルボタン押下 | 取消処理 | 入力した内容を取り消して画面を閉じる |

## 6. 技術方針

| 項目 | 内容 |
|---|---|
| フレームワーク | Next.js (App Router) + React |
| 状態管理 | React useState / useReducer（画面スコープ） |
| BFF通信 | Server Action 経由（execution-bff） |
| 認証 | Bearer JWT（`Authorization` ヘッダ） |
| バリデーション | クライアントサイド（E001/E002）。E003（VALIDATION_DELETE）・E008（VALIDATION_FORMAT）はBFFが返すサーバーバリデーションエラーをフロントがダイアログ表示する |
| 排他制御 | BFFでロック取得（初期表示時）。ロック延長は操作状態検知トリガ |
