## 文書概要

- **目的**: 手動で検査結果を追加・入力できる機能
- **対象システム／サブシステム**: 【RES002】結果入力/【RES003】結果通知
- **対象範囲**
  - 本書は「【RES002】結果入力画面」の詳細設計を示す。
- **用語定義**

| 用語     | 説明                                         |
| -------- | -------------------------------------------- |
| 検査結果 | 本画面で入力・管理する患者に紐づく検査データ |
| 確定     | 入力内容を確定                              |
| 編集     | 入力中状態                                   |
| 修正     | 登録済みの検査結果を再登録する行為           |

<!-- ※ 共通用語は「システム共通用語集」を参照 -->

- **参照資料**

    ※ 本設計は上記機能設計書に基づき作成する。

- **UI制御**
  - 検査結果修正理由ダイアログ
    - 検査結果修正理由ダイアログ表示時、理由詳細テキストエリアは非表示
    - 理由「その他」選択時にテキストエリアを表示する
  - 表示モード制御
    - 結果入力タブ：編集モード(lockInfo.lockBy = 'SELF')
    - HTTPレスポンスが409の場合は参照モード
    - 基準値（ReferenceValueDisplay　!= NULL）, 前回値：参照のみ
    - 確定ボタン押下後

## 占有制御における操作状態の定義

※本仕様は本画面における占有制御の暫定定義である。
占有制御は横断機能であるため、将来的に共通設計書へ集約する想定とする。

本画面では、編集ロックの延長判定に使用するため、
ユーザーの操作状態を以下の通り定義する。

### 操作状態（操作あり）

以下のいずれかが検知された場合、「操作あり」と判定する。

- マウス操作（クリック、ダブルクリック）
- キーボード入力（keydown、input 等）
- フォーカス変更
- スクロール操作
- ボタン押下、選択変更などの明示的なUI操作
- API通信を伴う画面操作

※検知対象イベントの詳細および実装方式はフロント実装に委ねる。

### 無操作状態

以下の条件を満たす場合、「無操作状態」と判定する。

- 一定時間、操作状態が検知されない状態

※一定時間の閾値は排他制御仕様に従う。

### ロック延長トリガー

- 操作状態が検知された場合、ロック延長処理を実施する。
- 無操作状態が継続した場合、ロック延長処理は行わない。
- ロック有効期限を超過した場合は、占有制御仕様に従いロックを無効とする。
