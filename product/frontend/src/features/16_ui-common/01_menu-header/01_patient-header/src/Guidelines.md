# Harz医療システム開発ガイドライン

## 一般的な開発ルール

### コーディング規約
- TypeScriptを使用し、型安全性を重視する
- 関数型プログラミングのパラダイムを優先する
- カスタムフックを活用して再利用性を高める
- ファイルサイズを小さく保ち、単一責任の原則に従う
- 絶対配置は必要最小限に留め、FlexboxとGridを優先する

### ファイル構成
```
components/
├── layout/          # レイアウト・ナビゲーション関連
├── medical/         # 医療機能特化コンポーネント  
├── ui/              # 基本UIコンポーネント（shadcn/ui）
└── figma/           # Figma連携コンポーネント
```

### インポート規約
```typescript
// 1. React・外部ライブラリ
import { useState } from "react";
import { toast } from "sonner@2.0.3";

// 2. 内部コンポーネント（相対パス）
import { Button } from "../ui/button";

// 3. 型定義
import type { Patient, MedicalRecord } from "../../types";
```

## 医療システム特有のガイドライン

### デザインシステム
- **基本フォントサイズ**: 14px（医療現場での視認性を考慮）
- **カラーパレット**: 医療システム専用カラー変数を使用
- **レスポンシブ**: デスクトップ優先、タブレット対応
- **ダークモード**: 夜勤対応のため必須

### 医療用カラー規約
```css
/* プライマリ（診療記録・メイン機能） */
.medical-primary { background-color: var(--color-medical-primary); }

/* セカンダリ（オーダー・アクション機能） */  
.medical-secondary { background-color: var(--color-medical-secondary); }

/* 機能別カラー */
.medical-records { background-color: var(--color-medical-records); }
.medical-orders { background-color: var(--color-medical-orders); }
.medical-vitals { background-color: var(--color-medical-vitals); }
```

### UIコンポーネントルール
- **ボタン**: Primary（主要アクション）、Secondary（補助アクション）、Tertiary（最小アクション）
- **フォーム**: 医療用語のオートコンプリート機能を含める
- **モーダル**: 重要な医療情報は必ずモーダルで確認
- **テーブル**: ページネーション必須（大量データ対応）

### 医療データ取り扱いルール
- **患者情報**: 必ず暗号化して保存
- **医療記録**: 変更履歴を保持（監査対応）
- **セッション**: 15-30分で自動ログアウト
- **バックアップ**: リアルタイム自動保存

### アクセシビリティ
- **WCAG 2.1 AA準拠**: 医療従事者の多様性に配慮
- **キーボードナビゲーション**: マウス不使用でも操作可能
- **音声読み上げ**: スクリーンリーダー対応
- **コントラスト比**: 最低4.5:1以上

### パフォーマンス
- **初期読み込み**: 3秒以内
- **画面遷移**: 1秒以内
- **検索機能**: 500ms以内（インクリメンタルサーチ）
- **大量データ**: 仮想スクロール・ページネーション

## コンポーネント設計ルール

### 医療記録コンポーネント
```typescript
// SOAP形式を強制する構造
interface SOAPRecord {
  subjective: string;   // 主観的情報
  objective: string;    // 客観的情報  
  assessment: string;   // 評価・診断
  plan: string;         // 計画
}
```

### オーダーコンポーネント
- **15種類のオーダータイプ**: 型安全性を保つ
- **専用入力フィールド**: オーダー種別に応じた適切なフィールド
- **バリデーション**: 医療安全のための入力チェック

### 状態管理
- **患者データ**: usePatientDataフック
- **医療記録**: useRecordManagementフック  
- **オーダー**: useOrderManagementフック
- **UI状態**: 各コンポーネント内で局所的に管理

### エラーハンドリング
- **医療安全**: エラーは必ずユーザーに通知
- **データ整合性**: 保存前のバリデーション必須
- **ネットワークエラー**: 自動リトライ機能
- **ログ記録**: 全エラーを詳細ログに記録

## セキュリティガイドライン

### 認証・認可
- **多要素認証**: 推奨（医療従事者資格確認）
- **セッション管理**: JWT使用、適切な有効期限
- **権限管理**: ロールベースアクセス制御（RBAC）

### データ保護
- **暗号化**: AES-256で患者情報暗号化
- **通信**: HTTPS必須、TLS1.3推奨
- **ログ**: 個人情報を含まない形式で記録

### 監査対応
- **操作ログ**: 全ての医療記録操作を記録
- **変更履歴**: Who・When・What・Whyを記録
- **データ保持期間**: 法的要件に準拠

## テスト戦略

### 単体テスト
- **医療計算ロジック**: 100%カバレッジ必須
- **バリデーション**: 境界値テスト重要
- **カスタムフック**: 全パターンテスト

### 統合テスト  
- **医療ワークフロー**: 診療の流れ全体をテスト
- **データ整合性**: 患者情報の一貫性確認
- **エラーシナリオ**: 異常系の網羅的テスト

### E2Eテスト
- **診療シナリオ**: 実際の診療パターンを再現
- **パフォーマンス**: 大量データでの動作確認
- **ブラウザ互換性**: 医療現場で使用される環境

## デプロイ・運用

### 本番環境
- **ダウンタイム**: 計画停止は深夜帯のみ
- **バックアップ**: 1時間毎の自動バックアップ
- **監視**: 24/7監視、アラート設定
- **災害対策**: 地理的分散バックアップ

### 更新ポリシー
- **緊急時**: セキュリティパッチは即座適用
- **機能追加**: 段階的ロールアウト
- **データベース**: マイグレーション慎重実行
- **ユーザー教育**: 新機能は事前研修実施
